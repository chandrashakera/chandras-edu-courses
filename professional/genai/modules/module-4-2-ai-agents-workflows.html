AI Agents and Workflows

⏱ 12 min read 📝 Assignment inside

In Module 4.1 you learned how RAG gives an LLM access to your documents. This sub-module covers the next step: what happens when an LLM does not just answer a question but takes actions — searching the web, writing and running code, calling APIs, filling forms and working with other AI systems. That is what AI agents do.

Agentic AI is one of the fastest-moving areas of enterprise AI. Understanding it at a conceptual level is quickly becoming a basic expectation for anyone joining an IT organisation.

The scale of agentic AI adoption

Indian companies are moving from AI experiments to real use. In a November 2025 report by EY and CII, based on an EY survey of about 200 Indian enterprises:

  • 47% of organisations had multiple GenAI use cases live in production, while 23% were still at the pilot stage.
  • 24% of leaders said they were already deploying agentic AI.

What this means for you: AI that takes actions is no longer a research topic. You are likely to work on, test or supervise an agent-based workflow early in your career.

Chatbot vs AI agent — the critical difference

Most people's mental model of AI is a chatbot: you ask a question, it answers. AI agents are fundamentally different.

ChatbotAI agent
What it doesAnswers a questionWorks towards a goal
StepsOne reply per messagePlans and runs several steps on its own
ToolsUsually none, or only searchSearch, code, APIs, files, other systems
Changes things?No — it only produces textYes — it can send, update or create things
Main riskA wrong answerA wrong action, repeated across steps

The five core components of an AI agent

Most agent systems can be described with five building blocks. Here is what each means in practice:

  • Perception — how the agent takes in information: your instruction, files, web pages, tool results or system messages.
  • Reasoning — the LLM working out what the information means and what to do about it.
  • Memory — what the agent keeps track of: the steps already done in this task, and sometimes notes saved from earlier tasks.
  • Planning — breaking the goal into steps and deciding the next one, including changing the plan when something fails.
  • Tool use (action) — actually doing something: running a search, calling an API, executing code, reading or writing a file.

How the agent loop works — a complete example

Example — a service-desk agent: A user raises the ticket "VPN not connecting since morning."
  1. Plan: check whether others have the same issue, then check this user's account.
  2. Act: search today's tickets for "VPN". Observe: 40 similar tickets in the last hour.
  3. Plan again: this looks like a wider outage, not a single user's problem.
  4. Act: check the VPN service status page. Observe: the gateway is reporting errors.
  5. Check goal: the cause is found. The agent drafts a reply to the user and an alert to the network team.
  6. Human approval: the on-call engineer reviews the alert before it is sent, because it notifies many people.

Three real agent workflows — how they work in Indian IT

  • Ticket triage in managed services — the agent reads incoming tickets, classifies them, adds context from past tickets and runbooks, and routes them to the right team. Approval gate: closing a ticket or changing a production system.
  • Test-case generation in software delivery — the agent reads a user story, drafts test cases, runs them in a test environment and reports failures with logs. Approval gate: a tester reviews the test cases before they are added to the suite.
  • Invoice processing in finance operations — the agent reads invoices, extracts fields, matches them against purchase orders and flags mismatches. Approval gate: any payment and any invoice above a set amount.

Where AI agents are deployed in Indian IT in 2026

Agents are being used first where work is high-volume, rule-based and easy to check:

  • IT operations and service desks — triage, diagnosis and routine fixes.
  • Software engineering — code changes, testing and documentation, with developers reviewing every change.
  • Business process operations — finance, procurement and HR back-office tasks.
  • Customer service — answering and resolving common requests, with escalation to people for complex cases.

The EY–CII report found that companies were prioritising operations (63%) and customer service (54%) for their GenAI investments over the following 12 months — the same areas where agents fit most naturally.

The tools that power AI agents in 2026

Specific products change every few months, so learn the categories:

  • Models with tool use — LLMs from major providers can request a tool call (a search, a calculation, an API request) instead of only writing text. This "function calling" is the foundation of every agent.
  • Agent frameworks — open-source libraries that handle the loop, memory and multi-step planning so developers do not build them from scratch.
  • Connector standards — ways to plug agents into company systems safely. The Model Context Protocol (MCP), introduced by Anthropic as an open standard in November 2024, is one widely discussed example.
  • Enterprise agent platforms — cloud and IT-services platforms that add security, monitoring and approval workflows around agents.

Before an interview, check which of these the company uses — their website or job description usually names them.

What you need to know about agent risks

Agents inherit every LLM risk from Module 1.4 and add new ones. A hallucination in one step can feed into the next, so a small mistake can grow into a wrong action — an error cascade. Agents can also behave inconsistently on the same task, call the wrong tool, or take an action nobody intended. That is why responsible teams limit what agents can do on their own, log every step, and keep people in charge of decisions that matter.

How to work alongside AI agents — your role in an agentic workflow

Your role in an agentic workflow is not to do what the agent does — it is to:

  • Define the goal clearly — agents are only as good as the task definition they receive. Ambiguous goals produce unpredictable agent behaviour. This is prompt engineering applied to agent instructions.
  • Set the approval gates — decide which steps in the workflow require human review before the agent proceeds. Sending an email? Human review. Querying a database? Autonomous. Updating a production record? Human review.
  • Monitor and debug — agents fail silently in ways that are harder to catch than code errors. Reviewing agent logs, spotting unexpected tool calls, and identifying when the agent took a wrong turn are increasingly valued skills.
  • Validate outputs — the agent's final output is not automatically correct. Verify it against the original goal, and check that each step produced the intended result. This human-in-the-loop role is one companies increasingly need.

The three things to remember

  • AI agents act, chatbots answer — the defining difference is tool use and multi-step action. An agent can search, run code, call APIs and complete a multi-step task without human approval at every step. Understanding this distinction is a basic expectation in AI-related interviews.
  • The five components are your vocabulary — perception, reasoning, memory, planning and tool use. When you hear "agentic AI" in a meeting or interview, you can break any agent system into these five components and describe how each works.
  • Human-in-the-loop is the career opportunity — for high-stakes tasks, companies deploy supervised agents with human checkpoints, not fully autonomous ones. Professionals who can define goals, set approval gates, monitor workflows and validate outputs are the ones these systems need.

Your assignment

This assignment builds your ability to design and supervise an agent workflow. Each task should take 15–20 minutes.

  • Pick an agent workflow: choose one repetitive, multi-step task from your college, internship or target role — for example, compiling attendance shortages, triaging lab equipment complaints or checking expense claims. Write the goal in one clear sentence.
  • Break it into the five components: for your workflow, note what the agent perceives, what it must reason about, what it needs to remember, its plan of steps and the tools it would use.
  • Set the approval gates: list every step and mark each as "autonomous" or "human review", with a one-line reason.
