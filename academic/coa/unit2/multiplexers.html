Multiplexers

⏱ 16 min read 📝 Quiz inside 📖 Mano Ch. 4

This page closes out the Combinational Logic group with what might be the single most versatile building block covered in this unit: the multiplexer. Where a decoder routes one input to many outputs, a multiplexer does the reverse — it routes one of many inputs through to a single output, selected by a binary address. That simple idea turns out to be powerful enough to implement almost any Boolean function directly, without gates.

What a Multiplexer Does

A multiplexer (often shortened to MUX) is a combinational circuit that selects one of 2ⁿ input lines and routes it through to a single output line, based on the value of n select lines. Think of the select lines as an address: whatever binary value they hold picks out exactly which input gets connected to the output at that instant.

A 2-to-1 MUX has 1 select line (choosing between 2 inputs); a 4-to-1 MUX has 2 select lines (choosing among 4 inputs); in general, an n-select-line MUX handles 2ⁿ inputs.

4-to-1 Multiplexer

Fig 1: A 4-to-1 MUX — the 2-bit select address S₁S₀ (entering the top) picks which of I₀–I₃ reaches the output Y
S₁S₀Y
00I₀
01I₁
10I₂
11I₃

The Boolean expression for the output makes the "selecting" behavior explicit:

Y = S₁′S₀′I₀ + S₁′S₀I₁ + S₁S₀′I₂ + S₁S₀I₃

Only one of the four AND terms can be "enabled" (its select-line combination true) at any time — exactly the term matching the current select value — so Y always equals exactly one of the four data inputs, never a mixture.

Implementing Boolean Functions with a MUX

Here's the genuinely powerful idea on this page: compare the MUX output equation above to a canonical sum-of-minterms expression. They have the exact same shape — each term is a minterm of the select lines, multiplied by a data input. This means: if you tie each data input to a 0 or 1 matching a function's truth table, the MUX itself becomes a hardware implementation of that function — with the select lines acting as the function's input variables.

An n-variable Boolean function can be implemented directly with a 2ⁿ-to-1 MUX, no separate logic gates required at all, just by wiring each data input to the correct constant.

Worked Example — Implementing XOR

Implement F(A, B) = A ⊕ B using a 4-to-1 MUX, with A and B driving the select lines (S₁=A, S₀=B):

S₁=AS₀=BRequired FWire MUX input to...
000I₀ = 0
011I₁ = 1
101I₂ = 1
110I₃ = 0
Fig 2: Tying constants to the four data inputs, with A and B as the select lines, turns the MUX itself into an XOR circuit — no AND, OR, or XOR gates anywhere

Tie I₀ = 0, I₁ = 1, I₂ = 1, I₃ = 0 (constant logic levels — ground and supply voltage, in real hardware), and the MUX's built-in selection logic does the rest. Checking: at A=1, B=0 (select = 10), the MUX routes I₂ (=1) to the output — and indeed 1⊕0 = 1. ✓ No AND, OR, or XOR gates were used anywhere — the multiplexer's internal structure is the entire circuit.

🚀 Beyond the textbook: this same "route the right input using a select address" pattern is the conceptual seed of a CPU's data bus and register selection logic — deciding which register's value reaches the ALU on a given clock cycle is fundamentally a multiplexing problem, at a much larger scale than the 4-to-1 example here.

Demultiplexer — the Inverse Operation

A demultiplexer (DEMUX) does the opposite job: it takes a single data input D and routes it to one of 2ⁿ output lines, chosen by n select lines — all other outputs stay 0. Where a MUX answers "which of many inputs should I read right now?", a DEMUX answers "which of many destinations should this one value go to right now?"

A 1-to-4 DEMUX (2 select lines) routes D to exactly one of four outputs Y₀–Y₃:

Y₀ = S₁′S₀′D    Y₁ = S₁′S₀D    Y₂ = S₁S₀′D    Y₃ = S₁S₀D
Fig 3: A 1-to-4 DEMUX — the select address S₁S₀ picks which single output D is routed to; every other output stays 0

Compare this against the previous topic's decoder: a demultiplexer is a decoder, with the single data line D taking the place of the shared enable input. Any decoder with an enable pin can be used as a demultiplexer for free, and vice versa — they're the same circuit wearing two different names depending on how the extra input is used.

Common Pitfalls

  • The number of select lines determines the number of inputs a MUX can handle, not the other way around — n select lines always means exactly 2ⁿ data inputs, never more, never fewer.
  • When using a MUX to implement a function, the data inputs must be wired in the exact order the select-line truth table expects — swapping even one input's position produces a function that looks similar but is wrong on at least one row.
  • A MUX with unconnected (floating) data inputs is not a safe design — every data input needs a defined logic level (0, 1, or a real signal), even if that input is never expected to be selected in normal operation.

Applications

  • Data routing and bus systems: any time multiple signal sources need to share one destination (a shared bus, a single ALU input), a multiplexer is the standard way to pick which source is actually connected at a given moment.
  • Function implementation on programmable hardware: the "wire constants to a MUX's inputs" trick from this page is directly how look-up-table-based programmable logic (like the LUTs inside FPGAs) implements arbitrary Boolean functions in real chips.
  • Parallel-to-serial data conversion: cycling a MUX's select lines through all combinations while a fixed set of parallel bits sit on the data inputs produces those bits one at a time on the output — a direct hardware implementation of parallel-to-serial conversion.

This closes out the Combinational Logic group of Unit 2 — from the general analysis/design procedure through adders, multipliers, comparators, decoders, encoders, and multiplexers. Together, these are the standard components every larger digital system, including the CPU covered later in this course, is assembled from.
