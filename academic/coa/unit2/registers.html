Registers

⏱ 14 min read 📝 Quiz inside

A single flip-flop stores one bit. Wire several together, sharing one clock, and the result is a register — a small block of memory that can hold and move multi-bit data. Every register in a CPU, from the program counter to the general-purpose register file, is built from exactly this pattern.

In simple terms: a register is a row of flip-flops that store a binary word together, all updated by the same clock.

What a Register Is

An n-bit register is simply n D flip-flops, one per bit, all clocked together. Each flip-flop's D input is its own dedicated data line — unlike the shift register (next topic), where each stage's D comes from the previous stage's Q, here every bit is loaded independently and in parallel:

Four-bit register: four D flip-flops sharing Clock, with an active-low Clear. Adapted from M. Morris Mano and Michael D. Ciletti, Digital Design, Fig. 6.1.

On every active clock edge, the register captures whatever is on its data inputs and holds it until the next edge — a snapshot taken once per clock cycle. This is the exact circuit behind every register mentioned by name back in Unit 3's Register Transfer topics, just now shown down at the flip-flop level instead of as an abstract box.

Register with Parallel Load

A plain register like the one above captures new data on every clock edge — often not what's wanted, since a CPU frequently needs a register to hold its value across several cycles while other work happens. Adding a LOAD control line, through a 2-to-1 MUX in front of each flip-flop's D input, fixes that: the MUX picks between the flip-flop's own Q (feed it back to itself, i.e. hold) and the new external data (load):

One bit of a register with parallel load. LOAD=0 selects input 0 (Q fed back, hold); LOAD=1 selects input 1 (new data I, load). Every bit repeats this exact circuit.

Every bit of the register repeats the one-bit circuit above independently, all sharing the same LOAD line and the same clock — so the whole register either holds everything or loads everything together, never a mix of the two on a single clock edge.

Worked Example — Hold, Then Load, Then Hold

Suppose a 1-bit register like the one above currently holds Q=0, and I=1 is wired to its data input the entire time:

Clock 1: LOAD=0 → MUX selects Q(=0) → D=0 → Q stays 0   (hold)
Clock 2: LOAD=1 → MUX selects I(=1) → D=1 → Q becomes 1  (load)
Clock 3: LOAD=0 → MUX selects Q(=1) → D=1 → Q stays 1   (hold)

Even though I=1 is present on every single clock edge, the register only actually captures it on Clock 2, when LOAD=1 — that's the entire purpose of the load-control MUX: deciding, clock by clock, whether new data is allowed in at all.

🚀 Beyond the textbook: real register files (the small, fast bank of registers inside a CPU core) extend this same MUX-per-bit idea with an address decoder selecting which of many registers gets the LOAD pulse on a given cycle, and a second MUX layer selecting which register's Q drives the read-output bus — the same building blocks from this unit, just replicated and combined at a larger scale.

Common Pitfalls

  • Confusing a plain register with a shift register. A plain register's flip-flops are independent — each has its own dedicated data input. A shift register (next topic) deliberately chains them, each stage's D coming from the previous stage's Q.
  • Forgetting that LOAD must be stable and correct before the active clock edge, not after. Like any flip-flop input, LOAD is subject to the setup-time requirement from the previous topic — changing it right at (or after) the clock edge doesn't reliably control that edge's capture.
  • Assuming a register with LOAD=0 "does nothing." It isn't idle — the MUX is actively re-selecting and re-writing the flip-flop's own current value every single clock edge, which is what makes the hold behavior reliable rather than relying on the flip-flop simply "not being touched."

Applications

  • The program counter, instruction register, and general-purpose registers in a CPU datapath are all parallel-load registers essentially identical to that one-bit circuit, just wider (typically 32 or 64 bits) and often with additional control lines (e.g., a separate synchronous clear).
  • Pipeline stage registers in a pipelined CPU use LOAD (often called "enable" in that context) to implement pipeline stalls — holding a stage's value steady for an extra cycle while an earlier stage waits on a slow operation like a memory access.
  • Memory-mapped I/O status/control registers use exactly this parallel-load pattern, with LOAD driven by a decoded "write to this address" signal instead of a dedicated control bit.
