Analysis of Clocked Sequential Circuits

⏱ 16 min read 📝 Quiz inside 📖 Mano, Ch. 5

Just like combinational circuits (Unit 2's first topic group) had an analysis procedure for working backward from a diagram to a Boolean function, sequential circuits have their own analysis procedure — starting from a flip-flop circuit and working backward to a complete description of its behavior: equations, a state table, and a state diagram.

Next-State and Output Equations

Given a sequential circuit's gate-level diagram, the first step is always the same: write the Boolean expression feeding each flip-flop's input (this is the next-state equation for that flip-flop, since whatever value reaches, say, a D input is exactly what the flip-flop will hold after the next clock edge), and the Boolean expression for each external output (the output equation).

Worked Example — Circuit

A circuit has one D flip-flop (present state Q), one input X, and one output Y. An XOR gate combines X with the flip-flop's own output Q, and feeds the result into D. The output Y is simply Q itself:

Fig 1: D = X ⊕ Q, and the flip-flop's own Q feeds straight back as one of the XOR's inputs.
Next-state equation:  D = X ⊕ Q      (this is what Q becomes after the next clock edge)
Output equation:      Y = Q

Step 2 — State Table

A state table lists every combination of present state and input, alongside the resulting next state and output — reading it straight off the equations above:

Present State (Q)Input (X)Next State (D)Output (Y)
0000
0110
1011
1101

Reading a row: "if the circuit is currently in state Q=0 and X=1 arrives, the next state becomes 1 (and while still in state Q=0, the output Y was 0)." Notice the output here depends only on the present state, not on X — that specific pattern (output = f(state) only) is called a Moore machine, one of the two standard sequential-circuit models covered in more depth later in this course.

Step 3 — State Diagram

A state diagram is the same information as the state table, drawn as a graph: one circle per state, and a directed arrow for every present-state/input combination, pointing at the resulting next state and labeled with the input that causes it:

Fig 2: State diagram — X=0 keeps the circuit in its current state, X=1 always flips it. Each circle's output Y is shown attached to the state, since Y depends only on present state here.

Reading this diagram tells the same story as the equations, but visually: from state 0, an X=0 self-loop stays at 0; an X=1 arrow leaves for state 1. State 1 behaves the mirror image. This circuit is, in fact, exactly a T flip-flop in disguise — D=X⊕Q is precisely the T flip-flop's characteristic equation with T renamed to X, so "toggle when X=1, hold when X=0" is the whole story.

Common Pitfalls

  • Writing the next-state equation as if it depended only on the input. A next-state equation almost always depends on the present state too (Q appears on the right-hand side here) — that dependence is exactly what makes it a sequential, not combinational, circuit.
  • Confusing "next state" with "output." D (next state) and Y (output) can be, and often are, completely different expressions — in this example they happen to look related (Y=Q, D=X⊕Q) but that's a property of this specific circuit, not a general rule.
  • Missing a row in the state table. Every combination of present state and input must appear exactly once — for n flip-flops and m inputs, that's 2ⁿ⁺ᵐ rows, all of which need to be checked against the diagram before moving to the state diagram.

Applications

  • Reverse-engineering an unlabeled sequential circuit (a legacy design, an unfamiliar chip, a lab exercise) always starts with this exact analysis procedure — there's no other systematic way to recover what it does.
  • Verifying a synchronous design before fabrication often means analyzing the finished gate-level circuit back into a state table and checking it against the originally intended behavior — the same check-your-work idea from the combinational design procedure, applied one level up.
  • Every register and counter for the rest of this unit can be analyzed with exactly this procedure — write the next-state equation for each flip-flop, and the behavior falls out mechanically.
