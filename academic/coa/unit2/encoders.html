Encoders

⏱ 16 min read 📝 Quiz inside 📖 Mano Ch. 4

An encoder performs the inverse of the previous topic's decoder: it has 2ⁿ (or fewer) input lines, exactly one of which is active at a time, and produces the n-bit binary code corresponding to which input is active.

8-to-3 (Octal-to-Binary) Encoder

An octal-to-binary encoder (8 inputs D₀–D₇, one-hot; 3 outputs A₂A₁A₀) reads each output straight off which inputs include that bit position in their index:

A₀ = D₁ + D₃ + D₅ + D₇    (inputs whose index has bit 0 set)
A₁ = D₂ + D₃ + D₆ + D₇    (inputs whose index has bit 1 set)
A₂ = D₄ + D₅ + D₆ + D₇    (inputs whose index has bit 2 set)

Each output is simply an OR of the four input lines whose index has that bit position set — a plain encoder needs no AND gates or K-maps at all, just three 4-input OR gates. Here's the whole octal-to-binary encoder as a single block, every input and output drawn out individually:

Worked Example — Single Active Input

If input line D₅ is the one that's active (all others 0), the encoder outputs binary code 101 (5): checking against the equations above, A₂ = D₅ (among others) = 1, A₁ = D₆+D₃+D₂+D₇ = 0 (D₅ isn't in that list), A₀ = D₅ (among others) = 1. Result: A₂A₁A₀ = 101. ✓

The Priority Problem

A plain encoder has a real limitation baked into its design: it assumes exactly one input is active at any time. If two or more inputs happen to be active simultaneously, the OR-based logic above produces garbage — the outputs become the OR of multiple binary codes, which isn't a valid code for either active input.

Priority Encoder

A priority encoder solves this by resolving conflicts: if two or more inputs are active simultaneously, the encoder outputs the code corresponding to the highest-priority input — conventionally, the input with the highest index, ignoring lower-indexed ones even if they're also active.

D₃D₂D₁D₀A₁A₀V
0000XX0
0001001
001X011
01XX101
1XXX111

The X's are don't-cares (Unit 1 again) — once D₃ is known to be 1, D₂/D₁/D₀ genuinely don't matter for the output, since D₃ always wins regardless. V is a valid-output flag, 0 only when no input is active at all (needed because A₁=A₀=0 is otherwise ambiguous — does it mean "D₀ is active" or "nothing is active"?).

What's Inside — Gate-Level Equations

For a 4-input priority encoder, the standard gate-level equations (reading the "highest index wins" rule straight off the truth table above) are:

A₁ = D₃ + D₂
A₀ = D₃ + D₂′D₁
V  = D₃ + D₂ + D₁ + D₀

A₁ is simple — it's 1 whenever D₃ or D₂ is active, since those are the two highest-priority inputs. A₀ needs one extra step: D₁ only gets to set A₀ if D₂ is not active (D₂′) — otherwise D₂ would outrank it. Here's A₁ and A₀ built from actual gates:

Fig 1: A₁ = D₃+D₂ (top, one OR gate). A₀ = D₃+D₂′D₁ (bottom, a NOT gate and an AND gate feeding a final OR gate). V is a straightforward 4-input OR of D₃,D₂,D₁,D₀ and isn't drawn separately.

Worked Example — Two Inputs Active at Once

Suppose D₂ = 1 and D₁ = 1 simultaneously (D₃ = D₀ = 0). Since D₂ has higher priority than D₁, the encoder outputs the code for D₂: binary 10 (2) — completely ignoring that D₁ is also active. D₁'s activity is simply irrelevant to the output as long as any higher-priority input (D₂ or D₃) is active.

⚠️ It's easy to assume "priority" means the lowest index (D₀) wins, by analogy with array indexing or reading order. In the standard convention used here, it's the opposite — the highest-indexed active input wins. Always check which convention a specific chip or textbook is using before assuming.

Common Pitfalls

  • Building a plain encoder when multiple inputs can be active at once. A plain encoder's outputs are undefined (or wrong) if more than one input is active simultaneously — that's exactly the situation a priority encoder is designed to handle correctly.
  • Ignoring the valid-output flag V. Without V, a priority encoder's all-zero output is ambiguous between "input D₀ is active" and "no input is active at all" — V is what disambiguates the two.
  • "Priority" conventionally means the highest input index wins, not the lowest — verify this convention explicitly rather than assuming.

Applications

  • Keyboard encoders: when a key is pressed, a priority encoder converts "which key is physically active" into a compact binary scan code — and the priority mechanism resolves the case where a user's finger briefly grazes two keys at once.
  • Interrupt controllers in a CPU use priority encoders to decide which of several simultaneous interrupt requests gets serviced first — exactly the same priority-resolution logic as the keyboard example, applied to a different problem.
  • Analog-to-digital flash converters often use a priority-encoder stage internally to convert a thermometer-code comparator output into a compact binary result.
