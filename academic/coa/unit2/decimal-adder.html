Decimal (BCD) Adder

⏱ 19 min read 📝 Quiz inside

The previous page's binary adder reappears here almost unchanged. A BCD adder reuses it directly and just adds one correction step to keep the result a valid decimal digit. Recall from Unit 1: BCD represents each decimal digit (0–9) as a 4-bit pattern 0000–1001; the patterns 1010–1111 are invalid and never occur. An ordinary 4-bit binary adder works fine only when the result also lands in 0–9 — but 9+9=18 is 10010 in binary, which isn't valid BCD at all. The fix is a well-known correction rule.

In simple terms: add the two digits in binary; if the result is more than 9 (or a carry came out), add 6 to skip the six unused codes and pass a 1 to the next digit.

The Correction Rule

Feed both BCD digits (plus any carry-in from the previous decade) into an ordinary 4-bit binary adder, producing a raw binary sum Z (0–19) and a carry K. Laying out every possible sum from 0 to 19 shows exactly where the raw binary result stops matching valid BCD, and what adding 0110 does to fix it:

Up to 9, the raw binary sum and the correct BCD digit are identical column-for-column — no correction needed. From 10 onward (highlighted), the two diverge, and adding 0110 brings S back into range every time, with Output carry=1 carrying into the next decade exactly when it should. This is the rule in numbers:

  • If Z ≤ 9 and K = 0, the binary sum is already valid BCD — use it as-is.
  • If Z ≥ 10, or K = 1 (a carry occurred), the sum is invalid or represents 16–19 — add 0110 (6) to push it back into the correct BCD digit, and this correction step's own decade-carry becomes the carry into the next decade.

To detect "Z ≥ 10 or K = 1" directly from the sum's individual bits (call them Z₈Z₄Z₂Z₁, weights 8-4-2-1), we need one more small piece of logic. Z≥10 happens exactly for the patterns 1010–1111 — the same six BCD don't-cares from Unit 1. K-mapping those patterns gives the simple condition Z₈Z₄ + Z₈Z₂ (true when Z₈ is 1 and either Z₄ or Z₂ is also 1). Add in the adder's own carry, and the full correction condition is:

Output carry = K + Z₈Z₄ + Z₈Z₂     (Output carry = 1 means "add 6", and Output carry doubles as the carry into the next decade)

Here's the standard textbook layout for the correction logic: a single 3-input OR gate (fed directly by the carry K and both AND-gate outputs) produces the Output carry, which is wired straight into two of the second adder's inputs — no extra gating needed there.

Block diagram of a BCD adder. Adapted from M. Morris Mano and Michael D. Ciletti, Digital Design, Fig. 4.14.

The second adder adds 0110 (if Output carry=1) or 0000 (if Output carry=0) to Z. Since 0110 only has two 1-bits, no extra gate is needed to apply it — the Output carry wire itself is connected straight to the "4" and "2" bit positions, while the other two positions of the constant are simply tied low. The output S is guaranteed valid BCD, and the Output carry doubles as the carry into the next decade's adder.

Worked Example 1 — 8 + 7 in BCD (Z ≥ 10 case)

A = 1000 (8), B = 0111 (7), Cᵢₙ = 0
Binary adder:  1000 + 0111 = 1111  →  Z = 1111 (15), K = 0

Check: Z₈Z₄ = 1·1 = 1  →  Output carry = K + Z₈Z₄ + Z₈Z₂ = 0 + 1 + 1 = 1  (add 6)

Correction adder: 1111 + 0110 = 1 0101  →  S = 0101 (5), decade carry (Output carry) = 1

Result: "1" and "5" → 15 in BCD, correctly split across two decimal digit positions.  Check: 8+7=15 ✓

Worked Example 2 — 9 + 9 in BCD (K = 1 case)

This case is worth working through separately, because the adder's own carry-out K — not just a large Z — is what triggers the correction:

A = 1001 (9), B = 1001 (9), Cᵢₙ = 0
Binary adder:  1001 + 1001 = 1 0010  →  4-bit result Z = 0010 (2), K = 1 (overflowed the 4-bit adder)

Check: Z₈Z₄ = 0, Z₈Z₂ = 0, but K = 1  →  Output carry = K + Z₈Z₄ + Z₈Z₂ = 1 + 0 + 0 = 1  (add 6)

Correction adder: 0010 + 0110 = 1000  →  S = 1000 (8), decade carry (Output carry) = 1

Result: "1" and "8" → 18 in BCD.  Check: 9+9=18 ✓  Notice Z alone (0010=2) looked deceptively small — only checking K caught it.
🚀 Beyond the textbook: the two-adder-plus-correction design shown here is the classic textbook circuit, but it isn't the only way to build one — a single-adder design that pre-adds 0110 conditionally using extra gating logic is also common in real chips, trading a slightly more complex gate network for one fewer full 4-bit adder. Both designs implement the identical add-6 correction rule; they differ only in how many adder stages the correction is folded into.

Common Pitfalls

  • Forgetting the correction step entirely and just using the raw binary sum as BCD. A binary adder alone gives the arithmetically correct binary sum, but that's not automatically a valid BCD digit — 9+6=15 in binary is 1111, not the BCD digit sequence "1" "5".
  • Checking only Z≥10 and forgetting the adder's own carry K. As Worked Example 2 shows, a binary sum of 16–19 (9+9=18) already overflowed the 4-bit adder (K=1) even though the remaining 4 bits alone (Z=0010) look deceptively small — Output carry must account for both conditions.
  • Assuming the correction adder's own carry-out is the decade carry. It's Output carry — computed from the first adder's Z and K — that's wired forward to the next decade, not necessarily anything from the second adder.

Applications

  • Decimal-display calculators, POS terminals, and older financial hardware that compute directly in BCD (avoiding binary-to-decimal conversion errors) rely on exactly this add-6 correction circuit, cascaded one decade per digit.
  • Digital clocks and BCD counters (the Registers & Counters topic in this unit's Sequential Logic group) commonly use BCD arithmetic internally specifically because it maps directly onto seven-segment digit displays without any extra conversion logic.
  • Multi-digit decimal arithmetic chains several BCD adders together, one per digit, with each stage's Output carry feeding the next stage's Cᵢₙ — the same ripple-carry idea from the previous topic, just at the level of whole decimal digits instead of individual bits.
