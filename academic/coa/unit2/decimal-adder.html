Decimal (BCD) Adder

⏱ 16 min read 📝 Quiz inside 📖 Mano Ch. 4

The previous page's binary adder reappears here almost unchanged — a BCD adder reuses it directly, adding just one correction step to keep the result inside valid decimal-digit codes. Recall from Unit 1: BCD represents each decimal digit (0–9) as a 4-bit binary pattern 0000–1001; patterns 1010–1111 are invalid and never occur. Adding two BCD digits with an ordinary 4-bit binary adder works fine only if the result also lands in 0–9 — but 9+9=18 in binary is 10010, which isn't valid BCD at all. The fix is a well-known correction rule.

The Correction Rule

Feed both BCD digits (plus any carry-in from the previous decade) into an ordinary 4-bit binary adder, producing a raw binary sum K (0–19) and a carry C. Then:

  • If K ≤ 9 and C = 0, the binary sum is already valid BCD — use it as-is.
  • If K ≥ 10, or C = 1 (a carry occurred), the sum is invalid or represents 16–19 — add 0110 (6) to push it back into the correct BCD digit, and this correction step's own decade-carry becomes the carry into the next decade.

Detecting "K ≥ 10 or C = 1" from the binary sum's individual bits (call them K₃K₂K₁K₀, weights 8-4-2-1) needs one more small piece of logic. K≥10 happens for the patterns 1010–1111 — exactly the six BCD don't-cares from Unit 1 — which K-map down to the condition K₃K₂ + K₃K₁ (K₃ is 1 and either K₂ or K₁ is also 1). Combined with the adder's own carry:

Z = C + K₃K₂ + K₃K₁     (Z = 1 means "add 6", and Z doubles as the carry into the next decade)

Correction-Circuit Block Diagram

The second adder adds 0110 (if Z=1) or 0000 (if Z=0) to K — that constant is itself just gated by Z (four AND gates, one per bit of the constant 0110, all controlled by the same Z line — a small enough addition that it's usually left out of the block diagram). The output S is guaranteed valid BCD, and Z doubles as the carry into the next decade's adder.

Worked Example 1 — 8 + 7 in BCD (K ≥ 10 case)

A = 1000 (8), B = 0111 (7), Cᵢₙ = 0
Binary adder:  1000 + 0111 = 1111  →  K = 1111 (15), C = 0

Check: K₃K₂ = 1·1 = 1  →  Z = C + K₃K₂ + K₃K₁ = 0 + 1 + 1 = 1  (add 6)

Correction adder: 1111 + 0110 = 1 0101  →  S = 0101 (5), decade carry Z = 1

Result: "1" and "5" → 15 in BCD, correctly split across two decimal digit positions.  Check: 8+7=15 ✓

Worked Example 2 — 9 + 9 in BCD (C = 1 case)

This case is worth working through separately, because the adder's own carry-out C — not just a large K — is what triggers the correction:

A = 1001 (9), B = 1001 (9), Cᵢₙ = 0
Binary adder:  1001 + 1001 = 1 0010  →  4-bit result K = 0010 (2), C = 1 (overflowed the 4-bit adder)

Check: K₃K₂ = 0, K₃K₁ = 0, but C = 1  →  Z = C + K₃K₂ + K₃K₁ = 1 + 0 + 0 = 1  (add 6)

Correction adder: 0010 + 0110 = 1000  →  S = 1000 (8), decade carry Z = 1

Result: "1" and "8" → 18 in BCD.  Check: 9+9=18 ✓  Notice K alone (0010=2) looked deceptively small — only checking C caught it.
🚀 Beyond the textbook: the two-adder-plus-correction design shown here is the classic textbook circuit, but it isn't the only way to build one — a single-adder design that pre-adds 0110 conditionally using extra gating logic is also common in real chips, trading a slightly more complex gate network for one fewer full 4-bit adder. Both designs implement the identical add-6 correction rule; they differ only in how many adder stages the correction is folded into.

Common Pitfalls

  • Forgetting the correction step entirely and just using the raw binary sum as BCD. A binary adder alone gives the arithmetically correct binary sum, but that's not automatically a valid BCD digit — 9+6=15 in binary is 1111, not the BCD digit sequence "1" "5".
  • Checking only K≥10 and forgetting the adder's own carry C. As Worked Example 2 shows, a binary sum of 16–19 (9+9=18) already overflowed the 4-bit adder (C=1) even though the remaining 4 bits alone (K=0010) look deceptively small — Z must account for both conditions.
  • Assuming the correction adder's own carry-out is the decade carry. It's Z — computed from the first adder's K and C — that's wired forward to the next decade, not necessarily anything from the second adder.

Applications

  • Decimal-display calculators, POS terminals, and older financial hardware that compute directly in BCD (avoiding binary-to-decimal conversion errors) rely on exactly this add-6 correction circuit, cascaded one decade per digit.
  • Digital clocks and BCD counters (the Registers & Counters topic in this unit's Sequential Logic group) commonly use BCD arithmetic internally specifically because it maps directly onto seven-segment digit displays without any extra conversion logic.
  • Multi-digit decimal arithmetic chains several BCD adders together, one per digit, with each stage's Z output feeding the next stage's Cᵢₙ — the same ripple-carry idea from the previous topic, just at the level of whole decimal digits instead of individual bits.
