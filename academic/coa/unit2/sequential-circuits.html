Sequential Circuits

⏱ 12 min read 📝 Quiz inside 📖 Mano, Ch. 5

Everything built so far in this course — adders, decoders, multiplexers — is combinational: its output depends only on the present inputs, with no memory of anything that happened a moment ago. A CPU cannot be built from combinational logic alone. A program counter has to remember which instruction comes next; a register has to hold a value across many clock cycles. That memory is exactly what a sequential circuit adds.

Definition

A sequential circuit is a circuit whose output depends on both the present inputs and the circuit's current state — some stored information about what has happened before. That state comes from feeding part of the circuit's own output back into its input logic, through storage elements (latches or flip-flops, covered in the next two topics):

Next State = f(Inputs, Present State)

General Block Diagram

Every sequential circuit, no matter how complex, fits the same general shape: a combinational logic block computes both the outputs and the "next state" from the current inputs and the "present state"; a bank of memory elements stores that next state and feeds it back as the present state for the following clock cycle.

Fig 1: The general shape of every sequential circuit — outputs and the next state both come from the combinational block, and the present state loops back from memory to influence the next computation.

The "present state" feedback line is the entire difference from a purely combinational circuit — remove it, and the memory elements' output would no longer influence the combinational block, collapsing this diagram back into an ordinary combinational circuit with no memory.

The Latch — the Simplest Sequential Circuit

The smallest possible sequential circuit stores exactly one bit, using nothing more than ordinary gates wired with feedback — no separate "memory element" block needed, because the feedback loop itself is the memory. The next topic, Latches, builds exactly this circuit and shows precisely how a loop of ordinary NOR or NAND gates ends up remembering a bit.

Common Pitfalls

  • Assuming more gates automatically means "sequential." Gate count is irrelevant — the only thing that makes a circuit sequential is the presence of a feedback path from output back to input, storing state.
  • Forgetting that "state" is stored information, not a momentary signal value. A wire carrying a signal right now isn't state by itself — state is what persists and continues to influence behavior after the input that caused it is gone.
  • Confusing the "next state" and "present state" labels. "Present state" is what the memory elements currently hold (and feed back as an input to the combinational logic); "next state" is what the combinational logic computes and the memory elements will hold after the next clock edge.

Applications

  • Every register in a CPU — the program counter, instruction register, general-purpose registers — is a sequential circuit whose entire purpose is to hold state across clock cycles.
  • A CPU's control unit is itself one large sequential circuit: which micro-operation happens next depends on both the current instruction (input) and which step of executing it the control unit is currently on (state).
  • Every topic for the rest of this unit — latches, flip-flops, registers, counters — is a specific, increasingly elaborate instance of exactly the block diagram on this page.
