Other Counters

⏱ 16 min read 📝 Quiz inside 📖 Mano, Ch. 6

The last two topics covered the two main counter families in depth: ripple (asynchronous) and synchronous counters. This closing topic rounds out the picture with three variations built on those same ideas: a synchronous version of the mod-10 BCD counter, up/down counters that can reverse direction, and presettable counters that can be loaded with an arbitrary starting value.

Synchronous BCD Counter — Contrasted With the Ripple Version

The ripple-counter topic built a mod-10 counter by letting the count briefly reach the invalid state 1010 and using that moment to trigger an asynchronous clear. A synchronous BCD counter takes a cleaner approach: never let the invalid states be reached at all — instead, derive each flip-flop's input directly from the state table so the count goes 1001 → 0000 on its own, on the very next clock edge, with no illegal state ever appearing:

Design AspectRipple BCD (previous topic)Synchronous BCD (this topic)
How it resets at 10Briefly reaches 1010, NAND gate detects it, asynchronously clearsNever reaches 1010 — next-state logic sends 1001 straight to 0000
Clock wiringCascaded (each stage clocked by the previous stage's output)Common clock line to every stage
Design methodAdd one reset gate to an existing ripple counterFull 4-step synchronous design procedure
SpeedLimited by accumulated propagation delayLimited only by one flip-flop's delay

Using T flip-flops for state Q₃Q₂Q₁Q₀ (Q₃ = MSB) counting 0000 through 1001, applying the same state-table → excitation-table → K-map steps from the previous topic gives:

T₀ = 1                        (LSB toggles every clock, same as always)
T₁ = Q₀ · Q₃′                 (toggles when Q₀=1, except right after 1001)
T₂ = Q₁ · Q₀
T₃ = Q₂·Q₁·Q₀ + Q₃·Q₀         (the +Q₃Q₀ term is what forces 1001 → 0000)

The extra Q₃·Q₀ term in T₃ is the whole trick: at state 1001 (Q₃=1, Q₀=1), it fires and toggles the MSB back to 0 on the same edge that T₀ toggles the LSB back to 0 — landing exactly on 0000 with no detour through any invalid pattern.

Up/Down Counters

A counter that can run in either direction needs a way to pick, on each clock, whether the next-state logic should compute the "count up" pattern or the "count down" pattern. The standard technique is a 2:1 multiplexer per stage — the same MUX-based selection idea used for parallel load in a register — with a single control line (commonly called UP/DOWN or U/D̄) choosing which pattern feeds each flip-flop's input:

U/D̄ LineMUX SelectsCounter Behaves As
1 (UP)The "count up" next-state expressionOrdinary up-counter
0 (DOWN)The "count down" next-state expressionOrdinary down-counter, in reverse sequence

For a simple ripple-style up/down counter, no MUX is even needed — recall from the ripple-counters topic that choosing Q vs. Q′ to drive the next stage, combined with the trigger edge, already determines up or down. A synchronous up/down counter needs the MUX because its next-state logic is full combinational expressions, not just a choice of which wire to tap.

Presettable (Parallel-Load) Counters

A presettable counter can be forced to start counting from any value, not just 0000, by combining a synchronous counter with the parallel-load MUX structure from the Registers topic: on each clock, a LOAD control line picks whether each flip-flop's next input comes from the count logic or directly from an external data pin. This is exactly how ICs like the 74163 support both counting and being "jumped" to an arbitrary state — useful whenever a circuit needs to start counting from something other than zero, such as a countdown timer preset to a specific value.

PinFunction
CLKCommon clock, shared by all stages (synchronous)
CLRResets the count to 0000
LOADWhen active, next state = external data pins instead of count+1
D₃–D₀External data to load in when LOAD is active
ENABLEWhen inactive, the counter holds its current state (no counting)
Q₃–Q₀Current count value
RCORipple carry out — pulses when the counter reaches its terminal count, used to cascade multiple counter chips together

Common Pitfalls

  • Assuming a synchronous BCD counter needs a reset gate like the ripple version. It doesn't — the whole point of deriving T₃'s extra term (Q₃Q₀) from the state table is that the count never touches an invalid state to begin with.
  • Confusing LOAD with CLR. CLR always forces the count to 0000; LOAD forces it to whatever is on the external D₃–D₀ pins, which can be any value.
  • Forgetting that LOAD in a synchronous presettable counter only takes effect on a clock edge. Unlike an asynchronous clear, the loaded value doesn't appear until the next clock pulse — it isn't instantaneous.

Applications

  • Countdown timers use presettable counters loaded with the starting time value, then counted down to zero.
  • Frequency synthesizers and programmable clock dividers use presettable up/down counters to generate a configurable division ratio.
  • Cascading counter chips (e.g., chaining multiple 74163s for a wider count range) relies on each chip's RCO output enabling the next chip's ENABLE input.
