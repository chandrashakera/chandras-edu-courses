Magnitude Comparator

⏱ 16 min read 📝 Quiz inside

A magnitude comparator takes two binary numbers and reports which is larger — three mutually-exclusive outputs: A>B, A=B, and A<B, exactly one of which is 1 for any given pair of inputs. It's a question that comes up constantly in real hardware, from sorting circuits to CPU branch conditions.

In simple terms: compare from the most significant bit down — the first bit position where the numbers differ decides which is larger.

1-Bit Comparator

ABA>BA=BA<B
00010
01001
10100
11010

All three read off directly, no K-map needed:

(A>B) = A B′
(A<B) = A′ B
(A=B) = A′B′ + AB   = (A ⊕ B)′        (the XNOR of A and B)

Cascading to n Bits

For multi-bit numbers, comparison has to start at the most significant bit — if the MSBs already differ, nothing about the remaining lower-order bits can change the outcome, no matter what they are. Only when a pair of bits is equal does the comparison need to continue down to the next bit.

For a 2-bit comparison of A=A₁A₀ against B=B₁B₀, using xᵢ = (Aᵢ = Bᵢ) as a per-bit equality signal:

(A>B) = A₁B₁′  +  x₁·A₀B₀′
(A<B) = A₁′B₁  +  x₁·A₀′B₀
(A=B) = x₁ · x₀

Read the first line as: "A>B if bit 1 alone already decides it (A₁B₁′), or bit 1 is tied (x₁) and bit 0 decides it (A₀B₀′)." This pattern extends directly to any width: each stage only gets to contribute its own >/< decision if every more-significant bit compared equal so far.

In hardware, that's exactly two 1-bit comparator stages cascaded, bit 1 (the higher-order bit) first:

Two-bit comparison as two cascaded 1-bit stages, most significant bit first.

CMP₁ compares A₁ against B₁ and outputs its own (GT,EQ,LT) — that's exactly the x₁ signal (EQ) plus the >/< decision, feeding into CMP₀. CMP₀ then applies the rule from the formula above: if CMP₁ already decided (not EQ), pass that decision straight through as the final answer; only if CMP₁ says EQ does CMP₀'s own comparison of A₀ vs B₀ get to decide. This is precisely what "x₁ gates whether bit 0's comparison counts" means in circuit form.

In hardware, this is built as a chain of 1-bit comparator stages, most-significant bit first, each stage passing a running (GT, EQ, LT) cascade signal — the decision so far — to the next; here's the same idea extended to 4 bits:

Four-bit comparison as a chain of 1-bit stages, each passing GT, EQ, LT to the next.

Each cascade line actually carries the full running (GT, EQ, LT) decision from every bit compared so far, not just a single "still tied" flag — a single tied bit alone couldn't tell a later stage which way an earlier bit decided. The cascade entering CMP₃ is fixed at (0,1,0) — "equal so far," vacuously true, since there's no higher-order stage yet. Every stage then applies the same rule: if the incoming cascade already says GT or LT, pass it straight through unchanged, since a higher-order bit has already settled the outcome and no lower bit can overrule it; only if the incoming cascade still says EQ does the stage's own bit comparison get to update the result. Only the final stage's (A>B, A=B, A<B) outputs are the actual overall result — every earlier stage's outputs are consumed internally by the next stage, not used directly.

The textbook builds the same 4-bit comparator directly from gates. Each xi = AiBi + Ai′Bi′ (an XNOR) is 1 when bit i of A and B are equal. Then (A = B) = x3x2x1x0, (A > B) = A3B3′ + x3A2B2′ + x3x2A1B1′ + x3x2x1A0B0′, and (A < B) is the same with A and B swapped in each term.

Four-bit magnitude comparator. Adapted from M. Morris Mano and Michael D. Ciletti, Digital Design, Fig. 4.17.

Worked Example — Comparing Two 4-Bit Numbers

A = 1011 (11),  B = 1010 (10)

Bit 3: A₃=1, B₃=1  → equal, cascade "still equal" to bit 2
Bit 2: A₂=0, B₂=0  → equal, cascade "still equal" to bit 1
Bit 1: A₁=1, B₁=1  → equal, cascade "still equal" to bit 0
Bit 0: A₀=1, B₀=0  → A₀>B₀, and every higher bit was tied

Result: A > B  (11 > 10) ✓ — decided entirely by the last (least significant) bit,
because every bit above it happened to match.

Common Pitfalls

  • Comparing from the least significant bit instead of the most significant. Magnitude comparison is fundamentally MSB-first — a difference in a low-order bit means nothing if a higher-order bit already differs.
  • Forgetting that only one of A>B, A=B, A<B can be 1 at a time. If a design ever produces two of these simultaneously, that's a bug — the three outputs are mutually exclusive by construction.
  • Treating an intermediate stage's output as the final answer. In the cascaded circuit, only the last stage's outputs are meaningful externally; every earlier stage's result is just an internal signal feeding the next comparison.

Applications

  • The 74LS85 is a classic off-the-shelf 4-bit magnitude comparator IC, built exactly as cascaded stages with dedicated cascading inputs — chaining several together compares numbers of any width.
  • CPU branch and comparison instructions (e.g., "jump if greater than") rely on magnitude comparator logic inside the ALU, often sharing circuitry with the subtractor from an earlier topic (A−B's sign bit alone can answer A<B for signed numbers).
  • Priority and arbitration logic — deciding which of several requesting devices gets access to a shared bus — frequently uses magnitude comparators to rank competing values or priority levels.
