Decoders

⏱ 17 min read 📝 Quiz inside 📖 Mano Ch. 4

A decoder is a combinational circuit that converts binary information from n input lines into a maximum of 2ⁿ unique output lines — with, at most, one output line active for each valid input combination. It's a workhorse of real digital systems, from memory addressing to instruction decoding in the CPU you'll study later in this course.

2-to-4 Decoder

A₁A₀D₀D₁D₂D₃
001000
010100
100010
110001

Each output is simply a minterm of the inputs: D₀ = A₁′A₀′, D₁ = A₁′A₀, D₂ = A₁A₀′, D₃ = A₁A₀. This is worth recognizing directly: a decoder is literally a physical implementation of the minterm-generation step from the K-map topic in Unit 1 — each decoder output IS one minterm, realized in hardware.

Enable Input

Most real decoder chips add an enable input E: every output gate gets a third input tied to E, so all outputs stay 0 whenever E=0, regardless of the address inputs. This is what makes decoders useful as chip-select logic — only the addressed chip's enable line goes active. Here's the whole 2-to-4 decoder as a single block, with E as a third input pin:

Worked Example — 3-to-8 Decoder

A 3-to-8 decoder takes 3 input lines (A₂ A₁ A₀) and activates exactly one of 8 output lines (D₀–D₇), matching the input's binary value.

Fig 1: A 3-to-8 decoder selects exactly one of eight outputs — here, input 101 (5) activates only D₅

Input A₂A₁A₀ = 101 (decimal 5) activates only D₅ — every other output stays at 0. This "exactly one active line" property is precisely why decoders are the standard building block for memory address selection: each memory chip or memory bank gets wired to one decoder output, guaranteeing only one is ever selected at a time.

Implementing Any Boolean Function

Since every decoder output already is one minterm, implementing any Boolean function of n variables is just: feed the n variables into an n-to-2ⁿ decoder, then OR together whichever decoder outputs correspond to the function's minterms. This is the canonical-SOP idea from Unit 1, built directly in hardware with zero simplification needed.

Small example: F(A,B) = Σm(1,2) on a 2-to-4 decoder — checking against the truth table above, D₁=A′B=m₁ and D₂=AB′=m₂, so F = D₁ + D₂: a single 2-input OR gate feeding off two of the decoder's outputs, no separate AND-gate array needed at all, since the decoder already built every minterm.

Worked Example — F(A,B,C) = Σm(1,3,5,6) on a 3-to-8 Decoder

The same idea scales directly to a larger decoder — the exact function used as a running example across several Unit 1 pages, implemented with a 3-to-8 decoder: connect decoder outputs D₁, D₃, D₅, and D₆ to an OR gate:

F = D₁ + D₃ + D₅ + D₆

A single gate can only cleanly draw two inputs at a time, so here the OR is built as three ordinary 2-input OR gates — Boolean-wise this is identical, since D₁+D₃+D₅+D₆ = (D₁+D₃) + (D₅+D₆):

Fig 2: D₁, D₃, D₅, D₆ each feed a 2-input OR gate; the two partial results are OR-ed again to make F. D₀, D₂, D₄, D₇ are unused.

No K-map simplification needed at all — the decoder-plus-OR-gate approach trades gate-minimization effort for a completely mechanical implementation process, at the cost of needing a full decoder (which internally uses more gates than a minimized custom circuit would).

Common Pitfalls

  • A decoder's outputs are mutually exclusive by design — at most one output is active for any valid input combination; if a decoder circuit shows two outputs active simultaneously, there's a wiring or logic error.
  • Forgetting the enable input disables ALL outputs, not just one. E=0 forces every decoder output to 0 simultaneously — it doesn't select a "default" output, it silences the whole decoder.
  • Assuming the decoder-plus-OR technique needs any AND gates or K-map work. It deliberately needs neither — every minterm already exists at a decoder output; the only job left is OR-ing the right ones together.

Applications

  • Memory address decoding: the address bus feeds a decoder, and each decoder output selects exactly one memory chip or memory bank — this is the single most common real-world use of decoders in computer organization.
  • Seven-segment display drivers are specialized decoders (BCD-to-seven-segment) that turn a 4-bit digit code into the right combination of active segments.
  • Instruction opcode decoding inside a CPU's control unit (a later unit in this course) uses decoder logic to turn a compact opcode field into one active control signal per instruction type.
