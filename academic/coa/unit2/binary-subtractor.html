Binary Subtractor

⏱ 20 min read 📝 Quiz inside

The previous page built an adder from the ground up. This page does the same for subtraction — starting with a single-bit half subtractor, then the full subtractor that can be chained, and finally a trick that lets one circuit do both addition and subtraction, reusing almost all of the same hardware.

In simple terms: subtraction is addition in disguise — invert B and add 1 — so one adder with an XOR on each B input can do both.

Half Subtractor

A half subtractor takes two single bits — a minuend A and a subtrahend B — and computes A − B, producing a difference bit D and a borrow bit Bₒᵤₜ (a borrow of 1 means "this position couldn't subtract on its own, so it had to borrow from the next position").

ABD (Difference)Bₒᵤₜ (Borrow)
0000
0111
1010
1100

D = A ⊕ B    Bₒᵤₜ = A′B

D is exactly XOR, same as a half adder's sum. Bₒᵤₜ is 1 only when A=0 and B=1 — the only row where a borrow is actually needed:

Half subtractor — one XOR gate makes the difference, one NOT + AND gate makes the borrow.

Like the half adder, a half subtractor has no way to accept a borrow-in from a previous, less significant position — so it only works for the very lowest bit of a multi-bit subtraction.

Full Subtractor

A full subtractor computes A − B for one bit position, given a borrow-in Bᵢₙ from the previous, less significant position. It produces a difference bit D and a borrow-out Bₒᵤₜ (a borrow-out of 1 means "this position couldn't subtract on its own, so it had to borrow from the next position").

D = A ⊕ B ⊕ Bᵢₙ    Bₒᵤₜ = A′B + A′Bᵢₙ + BBᵢₙ

Notice that D is exactly the same equation as the full adder's sum from the previous page (S = A ⊕ B ⊕ Cᵢₙ) — XOR just outputs 1 when an odd number of its inputs are 1, whether you call those inputs "carry" or "borrow." The borrow equation is also similar to the adder's carry equation, just with A inverted.

Just like the full adder, the easiest way to build a full subtractor is to reuse two half subtractors plus one OR gate:

A full subtractor built from two half subtractors and one OR gate — HS₁ computes A−B, HS₂ then subtracts Bᵢₙ from that result.

HS₁ computes A − B, giving a partial difference D₁ and a borrow B₁. HS₂ then subtracts Bᵢₙ from D₁, giving the final difference D and a second borrow B₂. B₁ and B₂ can never both be 1 at the same time, so — exactly like the full adder's two carries — simply OR-ing them together gives the correct Bₒᵤₜ.

Combined Adder–Subtractor

Building a whole separate subtractor circuit is wasteful. Unit 1 already showed that 2's complement turns subtraction into addition:

A − B = A + B′ + 1

where B′ means every bit of B inverted. That same trick lets one adder circuit handle both addition and subtraction, controlled by a single line M (mode: 0 = add, 1 = subtract). The idea: put one XOR gate in front of every bit of B, and feed that same M line into the first stage's carry-in too:

  • M = 0: each XOR gate passes its B bit through unchanged (B ⊕ 0 = B), and the first stage's carry-in is 0. The circuit computes A + B — ordinary addition.
  • M = 1: each XOR gate inverts its B bit (B ⊕ 1 = B′), and the first stage's carry-in is 1. The circuit computes A + B′ + 1, which is exactly A − B.

Here's the XOR gate that sits in front of one bit of B, labeled generically as bit i:

One XOR gate per bit of B — the same M line that flips this gate also becomes the first stage's carry-in.

Put one of these XOR gates in front of every B input of the 4-bit ripple carry adder from the previous page, and the full circuit looks like this — same four full adders, with one XOR gate added in front of each B input:

For signed numbers, V detects overflow: it is 1 when the carry into the sign position (C₃) differs from the carry out of it (C₄). The final carry C matters only for unsigned numbers.

Common Pitfalls

  • Confusing "carry" with "borrow." The combined adder-subtractor never computes a separate borrow signal — subtraction is handled entirely as addition of a complemented number, using ordinary carries.
  • Forgetting that M must feed both the XOR gates and the first stage's carry-in. Wiring M to only the XOR gates (forgetting the carry-in) computes A + B′ instead of A + B′ + 1, which is off by exactly one from the correct subtraction result.
  • Treating the discarded final carry-out as an error during subtraction. When A ≥ B, a final carry-out of 1 is normal and expected — it should be dropped, not treated as overflow.

Applications

  • Every ALU (Arithmetic Logic Unit) in every processor contains an adder-subtractor essentially identical to the one built here, usually with a faster carry mechanism (carry-lookahead) replacing the simple ripple chain for speed.
  • Any datapath needing both addition and subtraction — not just CPUs, but DSP chips, calculators, and embedded controllers — prefers the combined adder-subtractor over two separate circuits, since it costs only one XOR gate per bit more than a plain adder.
  • Program counters and address generation inside a CPU use small dedicated adders (often just "+4" or "+1" incrementers) built from the same full-adder block used here.
