Latches & Flip-Flops

⏱ 22 min read 📝 Quiz inside 📖 Mano, Ch. 6

Every combinational circuit built so far in this course has no memory — its output depends only on its present inputs. A CPU, by contrast, is defined by state: registers, program counters, and flags that persist from one clock cycle to the next. That memory is built from the smallest possible unit — a single stored bit — using a latch or flip-flop as the basic building block.

The SR Latch

Cross-coupling two NOR gates — each gate's output feeding back as one of the other gate's inputs — produces a circuit with two stable states, which is exactly what's needed to remember one bit:

Top gate: Q = NOR(R, Q′). Bottom gate: Q′ = NOR(S, Q).

S=R=1 forces both Q and Q′ to 0, breaking the Q=Q̄′ relationship the latch depends on — this combination must always be avoided.

The Gated D Latch

Driving S=D and R=D′ (D inverted) makes S and R always complements of each other, eliminating the forbidden state by construction. Adding an Enable (EN) input — via two AND gates gating D and D′ before they reach the SR core — adds control over exactly when the latch updates:

While EN=1, Q follows D continuously ("transparent"); when EN drops to 0, Q freezes at whatever D was last — this level-sensitive behavior is the key thing an edge-triggered flip-flop adds on top of.

Latch vs. Flip-Flop

A latch is level-sensitive — transparent for as long as its enable is high. A flip-flop is edge-triggered: it samples its inputs and updates only at the instant the clock transitions, then ignores its inputs for the rest of the cycle. That's exactly what makes multi-stage synchronous circuits — registers, counters, an entire CPU datapath — behave predictably: every stage changes at the same defined instant instead of drifting based on how long a signal happens to stay high.

The Race-Around Problem & Master-Slave JK

A level-triggered JK latch has a flaw: with J=K=1 ("toggle"), if the clock pulse stays high longer than one gate delay, the output toggles repeatedly during a single pulse — unpredictable. The fix is two latches — master and slave — driven by opposite clock phases, so they're never transparent at the same time:

While CLK=1, the master absorbs J,K but the slave (inverted clock) is latched, isolating Q. While CLK=0, the master locks and the slave copies through. Q only ever changes on the falling edge, by which point the master can no longer be affected by its own output — no race.

The X (don't-care) entries in JK and T are exactly what a later K-map minimization step (used heavily when designing counters and control units) gets to exploit — this is the direct link between a flip-flop's excitation table and simplified next-state logic.

Common Pitfalls

  • Driving a plain SR latch with S=R=1. This actively breaks the Q=Q̄′ relationship, not just "an invalid input" — the resulting state when both return to 0 is a race, not a defined value.
  • Confusing a JK latch with a JK flip-flop. The race-around condition is a level-triggered latch problem; a properly built edge-triggered (or master-slave) JK flip-flop does not race-around.
  • Reading the excitation table backwards. The characteristic equation answers "given the inputs, what's the next state?" The excitation table answers the reverse — "given the desired transition, what inputs are needed?" — which is the direction needed for register and counter design.

Applications

  • Every register in a CPU — the program counter, instruction register, general-purpose registers — is built from a bank of D flip-flops, one per bit.
  • Address latches in bus-multiplexed systems (e.g., classic microprocessors that multiplex address and data on the same pins) use exactly the transparent/latched behavior of a gated D latch to hold the address stable.
  • The next topic, Registers & Counters, builds directly on the flip-flop as its basic storage element — every register and counter in a CPU's datapath is a bank of flip-flops plus a little control logic.
