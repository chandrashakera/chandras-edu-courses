Design Procedure

⏱ 18 min read 📝 Quiz inside 📖 Mano Ch. 4

Design runs the opposite direction from analysis: starting from a word-description of what's needed, and ending with a working, minimized logic diagram. Every remaining building block in this unit — adders, comparators, decoders, encoders, multiplexers — was itself originally derived using exactly this procedure, starting from a truth table that defines the desired behavior.

The Procedure

  1. Specification. State the problem precisely. Determine the required number of inputs and outputs, and assign a letter symbol to each.
  2. Truth table. Derive the truth table that defines the exact required relationship between every input combination and its corresponding output(s).
  3. Simplify. Obtain the simplified Boolean function for each output, as a function of the input variables — using K-maps (Unit 1) or algebraic manipulation.
  4. Draw and verify. Draw the logic diagram from the simplified expressions, and check it against the original specification — ideally by re-deriving the truth table from the diagram and confirming it matches step 2.
Fig 1: The four-step design procedure, applied to every combinational circuit in this unit

Worked Example 1 — Full Design Cycle

Specification: design a circuit with two inputs A, B that outputs 1 whenever exactly one of the two inputs is 1 (deliberately the same function analyzed on the previous page, so the two directions of the process can be compared directly).

Step 1 — Specification: two inputs (A, B), one output (F). F = 1 when exactly one input is 1.

Step 2 — Truth table:

ABF
000
011
101
110

Step 3 — Simplify: reading the 1-rows directly gives the canonical sum: F = A′B + AB′. With only two variables and two minterms that aren't adjacent on a K-map (no simplification possible — they sit diagonally opposite), this is already the minimal SOP form.

Step 4 — Draw and verify: two NOT gates, two 2-input AND gates, one 2-input OR gate — exactly the circuit analyzed on the previous page. Re-deriving its truth table (already done there) confirms it matches step 2 exactly. Design cycle complete.

🚀 Beyond the textbook: in practice, this exact two-input "differs" function is common enough that it has its own dedicated gate symbol — XOR — rather than being redrawn from AND/OR/NOT every time. Real digital design flows almost never build XOR this way; they simply use an XOR gate directly. This example is valuable specifically because it demonstrates the design procedure end-to-end on a function simple enough to fully verify by hand.

Worked Example 2 — 3-Input Majority Function

Specification: design a circuit with three inputs A, B, C and one output F, where F = 1 whenever a majority (2 or more) of the inputs are 1.

Step 2 — Truth table → minterms: F is 1 for input combinations with two or three 1s: m3 (011), m5 (101), m6 (110), m7 (111). So F(A,B,C) = Σm(3,5,6,7).

Step 3 — Simplify with a K-map:

A\BC00011110
0 0m0 0m1 1m3 0m2
1 0m4 1m5 1m7 1m6
Pair {m6,m7} → AB Pair {m5,m7} → AC Pair {m3,m7} → BC

Three valid pairs exist, and each one shares cell m7 with the other two — a normal and expected overlap (recall from Unit 1: a group only needs to cover a 1, nothing forbids the same 1 from being covered more than once):

Pair {m6, m7} (A=1, B=1, C varies): term = AB
Pair {m5, m7} (A=1, C=1, B varies): term = AC
Pair {m3, m7} (B=1, C=1, A varies): term = BC

F = AB + AC + BC

Step 4 — Draw and verify: the minimal circuit needs 3 two-input AND gates (one per product term) feeding a 3-input OR gate — or equivalently, two cascaded 2-input OR gates. Either is a direct, mechanical translation of the SOP expression above: five gates total, and no further simplification is possible since every group is already a maximal pair.

Common Pitfalls

  • Skipping the re-derivation in step 4 — a common shortcut that hides algebra mistakes. A slip in Boolean simplification can produce a circuit that looks correct on paper but doesn't actually implement the specification.
  • Forgetting that a K-map group can overlap another group. As the majority-function example shows, using the same 1-cell in multiple groups is completely normal and often unavoidable for functions like this one.
  • Jumping straight to a circuit from the truth table, skipping minimization. An unminimized SOP (one AND gate per row that's a 1) always works, but a K-map-minimized version is smaller, cheaper, and usually faster — minimization is a required step, not an optional polish.

Applications

  • Every circuit on the remaining pages of this unit — adders, comparators, decoders, encoders, multiplexers — is a direct product of this exact four-step design procedure, just with more inputs, more outputs, and more involved simplification.
  • Majority-vote circuits specifically are used in triple-modular-redundancy (TMR) fault-tolerant systems — three identical subsystems compute the same result, and a majority circuit like the one designed above picks the answer that at least two of them agree on.
  • Hardware description languages (Verilog, VHDL) let engineers skip drawing the gate-level diagram by hand, but the underlying logic — specification → truth table → simplified equations → circuit — is exactly what the compiler/synthesis tool does automatically underneath.
