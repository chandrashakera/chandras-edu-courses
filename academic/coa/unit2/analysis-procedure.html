Analysis Procedure

⏱ 10 min read 📝 Quiz inside

Analysis means starting with a circuit diagram and figuring out what it does — finding the Boolean expression (and optionally a truth table) for its output. You'll use this whenever someone hands you a circuit you didn't design yourself.

In simple terms: analysis goes from circuit to function: name every gate output, write its expression, then substitute until only the inputs remain.

The Procedure

  1. Label every gate output with a variable name, working from the inputs toward the final output.
  2. Write the Boolean expression for each labeled signal.
  3. Substitute until the final output is written purely in terms of the original inputs.
  4. Tabulate — build the truth table by evaluating the final expression for all 2ⁿ input combinations, if you need one.
🚀 The most common mistake is skipping step 1 — trying to write the final expression straight from the diagram without naming the in-between signals. Labeling first is slower, but far less error-prone.

Worked Example 1 — A 2-Input Circuit

A circuit has two inputs, A and B:

Circuit for Worked Example 1: F = A′B + AB′.

F = A′B + AB′

Checking all four input combinations:

ABA′BAB′F = A′B + AB′
00000
01101
10011
11000

F is 1 exactly when A and B differ. That's the XOR function — built here from AND, OR, and NOT gates instead of a single XOR gate.

Worked Example 2 — A 3-Input Circuit

A second circuit has three inputs, A, B, C, and one output F:

Circuit for Worked Example 2: F = AB + C.

Step 1 — label the AND gate's output: w1 = AB
Step 2 — the OR gate combines w1 and C directly: F = w1 + C
Step 3 — substitute: F = AB + C

F = AB + C. So F is 1 whenever C is 1 (no matter what A and B are), or whenever both A and B are 1. Labeling w1 first made this much easier than trying to read the whole expression off the diagram at once.

Common Pitfalls

  • Skipping the labeling step. Writing the final expression straight from a multi-gate diagram, without naming the in-between signals, is where mistakes creep in.
  • Leaving truth table rows blank. Every input combination needs a defined output, unless it's explicitly marked as a don't-care.
  • Two different-looking circuits can compute the same function. If their truth tables match, they're equivalent — even with different gates or wiring.

Applications

  • Understanding an unfamiliar circuit — from a datasheet, an old design, or a lab exercise — always starts with this procedure.
  • Verifying a circuit works correctly before using it also relies on this same process: label, write equations, substitute.
