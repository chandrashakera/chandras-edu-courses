Analysis Procedure

⏱ 15 min read 📝 Quiz inside 📖 Mano Ch. 4

Analysis starts with a logic diagram already drawn, and works backward to a mathematical description — a set of Boolean expressions, and optionally a truth table — of what the circuit actually computes. It's the skill you reach for whenever you're handed an unfamiliar circuit (a datasheet, a legacy design, a lab exercise) and need to figure out what it does before you can use, verify, or modify it.

The Procedure

  1. Label every gate output with an intermediate variable name, working from the inputs toward the final outputs — not just the final output(s).
  2. Write the Boolean expression for each labeled signal, building up from the inputs through each layer of gates.
  3. Substitute through until each final output is expressed purely in terms of the original input variables.
  4. Tabulate — build the truth table by evaluating the final expressions for all 2ⁿ input combinations, if a table is what's needed.
🚀 The single most common mistake at this stage is skipping step 1 — trying to read a multi-gate circuit's final expression directly off the diagram, without naming intermediate signals. Label first, substitute second; it's mechanical and far less error-prone.

Worked Example 1 — A 2-Input Circuit

Take a circuit with two inputs A, B, one NOT gate on A feeding an AND gate (giving A′B), one NOT gate on B feeding a second AND gate (giving AB′), and a final OR gate combining those two AND outputs.

F = A′B + AB′

Evaluating this at all four input combinations:

ABA′BAB′F = A′B + AB′
00000
01101
10011
11000

This is worth recognizing immediately: F is 1 exactly when A and B differ — this circuit is an XOR gate, built entirely from AND, OR, and NOT. Spotting patterns like this (a multi-gate circuit turning out to be a familiar single function) is a routine, valuable part of analysis.

Worked Example 2 — A 3-Input Circuit

Analyze a second circuit, with three inputs A, B, C and one output F: an AND gate combines A and B, and its output feeds an OR gate together with C directly.

Step 1 — label the AND gate's output:  w1 = AB
Step 2 — the OR gate combines w1 and C directly:  F = w1 + C
Step 3 — substitute:                              F = AB + C

Evaluating F = AB + C for all 8 input combinations gives the full truth table — F is 1 whenever C is 1 (regardless of A, B), or whenever both A and B are 1. Notice how much simpler this is with intermediate labeling: nobody needs to mentally track "what does this OR gate see" while also parsing what feeds the AND gate — w1 already carries that information forward.

Common Pitfalls

  • Skipping the "label every wire" step. Trying to write the final output's expression directly from a multi-gate diagram, without naming intermediate signals, is exactly where transcription errors creep in.
  • A truth table isn't complete until every input combination is assigned an output — leaving rows unspecified makes the circuit's behavior ambiguous for those inputs, unless they're explicitly marked as don't-cares.
  • Identical truth tables always mean functionally equivalent circuits — even if the gate count, gate types, or internal wiring are completely different. Don't assume two different-looking diagrams must compute different functions.

Applications

  • Reverse-engineering an unlabeled schematic — from a datasheet, a legacy design, or a lab exercise — always starts with the analysis procedure; there's no other systematic way to recover what a circuit does.
  • Circuit verification and debugging in real hardware design relies on this exact procedure — given an unfamiliar circuit, analysis is how you determine what it actually does before trusting it.
  • Hardware description languages (Verilog, VHDL) let engineers skip drawing the gate-level diagram by hand, but the underlying logic — labeled signals → equations → substitution — is exactly what a synthesis or simulation tool does automatically underneath.
