Code Converters

⏱ 20 min read 📌 Supplementary — beyond the syllabus
In simple terms: a code converter is just a combinational circuit whose inputs are one code and whose outputs are another — write the truth table, simplify each output with a K-map, then draw the gates.

A code converter translates the same information from one binary code to another — for example, BCD from a calculator keypad into Excess-3 for an older arithmetic unit, or binary from a counter into Gray code for a rotary encoder. Each design follows the combinational design procedure: truth table → K-map per output → gate equations.

1. BCD to Excess-3

Excess-3 = BCD + 3. Inputs ABCD (BCD 0–9); outputs wxyz. Inputs 1010–1111 never occur, so they are don’t-cares (X).

Result

z = D′
y = CD + C′D′            = (C ⊕ D)′
x = B′C + B′D + BC′D′    = B′(C + D) + B(C + D)′  = B ⊕ (C + D)
w = A + BC + BD          = A + B(C + D)

The factored forms share the term C + D between x and w, so the whole converter needs one OR gate for C + D, one XOR, one XNOR, one AND, one OR and one inverter.

Check: input 0111 (7) → w = 0 + 1·1 = 1, x = 1 ⊕ 1 = 0, y = (1 ⊕ 1)′ = 1, z = 0 → 1010 = 10 = 7 + 3 ✓

2. Binary to Gray Code

In Gray code, consecutive values differ in exactly one bit. Each Gray bit is the XOR of the binary bit and the next higher binary bit.

Equations

G₃ = B₃
G₂ = B₃ ⊕ B₂
G₁ = B₂ ⊕ B₁
G₀ = B₁ ⊕ B₀          → three XOR gates
Example: 1011 → G₃ = 1, G₂ = 1⊕0 = 1, G₁ = 0⊕1 = 1, G₀ = 1⊕1 = 0 → 1110

The K-map of each Gray output is a checkerboard pattern across two columns or rows, which is why it reduces to a single XOR rather than an SOP.

3. Gray Code to Binary

Going back, each binary bit is the XOR of the Gray bit and the binary bit just found above it — so the outputs are computed from the top down.

B₃ = G₃
B₂ = B₃ ⊕ G₂ = G₃ ⊕ G₂
B₁ = B₂ ⊕ G₁ = G₃ ⊕ G₂ ⊕ G₁
B₀ = B₁ ⊕ G₀ = G₃ ⊕ G₂ ⊕ G₁ ⊕ G₀
Example: 1101 → B₃ = 1, B₂ = 1⊕1 = 0, B₁ = 0⊕0 = 0, B₀ = 0⊕1 = 1 → 1001 ✓ (1001 → Gray 1101)
Binary → Gray uses only the input bits (parallel XORs); Gray → binary chains through the outputs, so its delay grows with the number of bits.

Practice Problems

  1. Convert binary 0110 1101 to Gray code.
    Show answer

    0101 1011.

  2. Convert Gray code 1011 to binary.
    Show answer

    1101.

  3. Design an Excess-3 to BCD converter (inputs wxyz, outputs ABCD; Excess-3 codes 0000, 0001, 0010, 1101, 1110, 1111 are don't-cares).
    Show answer

    A = wx + wyz; B = x′y′ + x′z′ + xyz; C = y ⊕ z; D = z′.

  4. Why is the BCD to Excess-3 converter simpler than a 4-bit adder adding 0011?
    Show answer

    The six unused BCD inputs are don't-cares, so K-maps give larger groups; an adder must work for all 16 inputs.

Common Pitfalls

  • Forgetting the don't-cares — inputs 1010–1111 never appear in BCD; leaving them as 0 gives much larger circuits.
  • Writing outputs in the wrong bit order — w is the MSB of Excess-3 and A the MSB of BCD; keep the same order in the table and the K-maps.
  • Gray → binary with Gray bits only in parallel — B₁ = G₂ ⊕ G₁ is wrong; it must include G₃ (B₁ = G₃ ⊕ G₂ ⊕ G₁).
  • Starting the Gray conversion from the LSB — the MSB is copied unchanged; the XORs work downward from it.
