Registers & Counters

⏱ 26 min read 📝 Quiz inside 📖 Mano, Ch. 6

A single flip-flop stores one bit. Wire several together with shared control, and two distinct families of building block emerge: registers, which hold and move multi-bit data, and counters, registers whose "next value" is wired to automatically follow a fixed sequence. Both are everywhere in a CPU — the register file, the program counter, and the instruction pipeline's staging registers all reduce to variations on what's built here.

Shift Registers

A shift register is a cascade of flip-flops sharing one clock, where each stage's D input is simply the previous stage's Q — every clock pulse, every stored bit moves one position down the chain:

SISOSerial-In / Serial-Out1 bit/clock1 bit/clockTime delay, buffering
SIPOSerial-In / Parallel-Out1 bit/clockAll bits at onceSerial-to-parallel (UART receive)

SIPO simply taps every stage's Q as its own output pin instead of using only the last one; PISO adds a way to force each stage directly to an external bit before shifting begins — both are the same core chain above, with extra access points.

Ring & Johnson Counters

Feed the last stage's output straight back into the first stage's input, with no external data, and the register becomes a self-contained counter — a ring counter: N states for N flip-flops, with a single 1 circulating (pre-loaded to e.g. 1000 → 0100 → 0010 → 0001 → 1000…). Feed back the inverted last output instead, and it becomes a Johnson (twisted-ring) counter: 2N states, self-starting from all-0 (0000 → 1000 → 1100 → 1110 → 1111 → 0111 → 0011 → 0001 → 0000…), since the inversion means the count is never actually "stuck."

Asynchronous (Ripple) Counters

Cascade T flip-flops (each permanently wired T=1, so it toggles every clock) so that only the first receives the external clock — every later stage is clocked by the output of the stage before it:

FF0 toggles every clock; FF1 only when Q₀ falls; FF2 only when Q₁ falls — each stage runs at half the frequency of the one before it, which is binary counting. Because each stage's toggle physically waits for the previous stage's output, the count "ripples" through — the accumulated delay is the ripple counter's main weakness, and exactly what a synchronous counter is built to avoid.

Synchronous Counters

Every flip-flop shares one common clock — all stages update simultaneously, eliminating ripple delay, at the cost of needing combinational logic to compute each stage's inputs. The design procedure: state table → excitation table (previous topic) → K-map minimization → circuit. Worked for a 3-bit JK up-counter (state AnBnCn, A=MSB), the minimized equations come out to:

JC = 1,   KC = 1    (LSB toggles every clock)
JB = C,   KB = C    (B toggles when C is 1)
JA = BC,  KA = BC   (A toggles when B and C are both 1)

Every clock triangle taps the same shared line — the single structural difference from the ripple counter's staggered chain above. FF(C) always toggles; FF(B)'s J and K both come from C; FF(A)'s J and K both come from a single AND gate combining B and C.

Common Pitfalls

  • Assuming a ripple counter's bits all change at the same instant. They don't — each stage waits for the previous one, so the count briefly passes through invalid-looking intermediate states during a transition.
  • Powering up a ring counter and expecting it to count. Without pre-loading exactly one stage to 1, it can sit stuck at all-0 forever.
  • Wiring a synchronous counter's clock through even slightly different paths per stage. The entire point is one shared clock net — reintroducing per-stage clock skew undoes the benefit over a ripple counter.

Applications

  • Shift registers are the core of UART serial communication (PISO on transmit, SIPO on receive) and of simple hardware sequencers.
  • Synchronous counters (the 74163/74169 family and their equivalents) are the standard choice for a CPU's program counter and pipeline stage counters, precisely because they avoid ripple delay at higher clock rates.
  • The general 4-step synchronous design procedure used here — state table, excitation table, K-map, circuit — extends directly to any finite state machine, which is exactly how a CPU's control unit gets designed.
