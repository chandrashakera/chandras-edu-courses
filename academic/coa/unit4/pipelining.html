Pipelining

⏱ 25 min read 📌 Supplementary — beyond the syllabus
In simple terms: pipelining is an assembly line inside the processor. A task is split into steps, each step has its own hardware, and while one task is in step 3 the next is in step 2 and the one after in step 1 — so a new result comes out every clock.

Parallel Processing and the Pipeline Idea

Parallel processing makes a computer do several things at once. Pipelining is one form of it: a process is divided into k sub-operations (segments), each executed by its own circuit, and the segments run at the same time on different data. Each segment is a combinational circuit followed by a register that holds its result for the next segment; one common clock moves every result one segment forward.

A k-segment pipeline: each segment Si is followed by a register Ri, all clocked together.

Textbook illustration: computing Ai × Bi + Ci for i = 1 … 7 in three segments — segment 1 loads Ai and Bi, segment 2 multiplies and loads Ci, segment 3 adds. Once the pipeline is full, one result leaves every clock.

The Space-Time Diagram

Space-time diagram: four segments, six tasks, nine clock cycles. Adapted from M. Morris Mano, Computer System Architecture, Fig. 9-4.

The first task needs k clocks to pass through all segments; after that one task finishes every clock. So n tasks take k + n − 1 clock cycles.

Speedup, Efficiency and Throughput

With clock period tp and a non-pipelined unit that takes tn per task:

Pipelined time      = (k + n − 1) · tp
Non-pipelined time  = n · tn
Speedup  S = n·tn / ((k + n − 1)·tp)
If tn = k·tp and n is very large:  S → k   (the maximum speedup equals the number of segments)
Efficiency  = S / k            Throughput = n / ((k + n − 1)·tp)   tasks per unit time

In practice the maximum is never reached: segments take different times, the clock must suit the slowest one, and registers add delay.

Instruction Pipeline

An instruction cycle can be pipelined too. A four-segment example:

SegmentAction
FIFetch the instruction
DADecode it and calculate the effective address
FOFetch the operand
EXExecute

Ideally a new instruction starts every clock. Three kinds of hazard spoil this:

HazardCauseRemedies
Resource (structural)Two segments need the same hardware at once (e.g. one memory for instruction fetch and operand fetch)Separate instruction and data memories (or caches)
DataAn instruction needs a result the previous one hasn’t produced yetHardware interlock (stall), operand forwarding (bypass the result directly to the next instruction), delayed load (compiler reorders or inserts no-ops)
Branch (control)A branch changes the PC, so the instructions already fetched are wrongPrefetch the branch target, branch target buffer, loop buffer, branch prediction, delayed branch (compiler fills the slot after the branch with a useful instruction)

Example — a data hazard:

ADD R1, R2, R3     ; R1 ← R2 + R3
SUB R4, R1, R5     ; needs the new R1

Without forwarding, SUB must wait until ADD writes R1 — the pipeline stalls; with forwarding, ADD’s result goes straight from the execute stage to SUB’s input.

Solved Problems

Problem 1 — Speedup of a four-segment pipeline

k = 4 segments, tp = 20 ns, n = 100 tasks, non-pipelined tn = k·tp = 80 ns
Pipelined:      (k + n − 1)·tp = (4 + 100 − 1) × 20 = 2,060 ns
Non-pipelined:  n·tn = 100 × 80 = 8,000 ns
Speedup S = 8,000 / 2,060 = 3.88      (close to the maximum, k = 4)
Efficiency = 3.88 / 4 = 0.97          Throughput = 100 / 2,060 ns ≈ 48.5 million tasks/s

Problem 2 — Unequal stages and latch delay

Stage delays 60, 50, 70, 80 ns; register (latch) delay 10 ns; 1,000 instructions
Clock period = slowest stage + latch = 80 + 10 = 90 ns
Pipelined:      (4 + 1000 − 1) × 90 = 90,270 ns
Non-pipelined:  1000 × (60 + 50 + 70 + 80) = 260,000 ns
Speedup = 260,000 / 90,270 ≈ 2.88     (well below 4, because of the slow stage and the latch)

Problem 3 — Branch penalty

CPI = clock cycles per instruction.

Ideal CPI = 1; 20 % of instructions are branches; each costs 3 stall cycles
Effective CPI = 1 + 0.2 × 3 = 1.6     → the pipeline delivers 1/1.6 = 62.5 % of its ideal rate

Problem 4 — Cycles for n tasks

A 4-segment pipeline needs 4 + 6 − 1 = 9 cycles for 6 tasks (space-time diagram above), against 4 × 6 = 24 without pipelining.

Practice Problems

  1. A 5-segment pipeline has a 10 ns clock. How long do 50 tasks take, and what is the speedup over a non-pipelined unit taking 50 ns per task?
    Show answer

    (5 + 50 − 1) × 10 = 540 ns; 2,500 / 540 ≈ 4.63.

  2. What is the maximum speedup of a 6-segment pipeline?
    Show answer

    6 (as n → ∞, with tn = k·tp).

  3. Stage delays 40, 30, 50 ns, latch 5 ns. What is the clock period?
    Show answer

    55 ns.

  4. 30 % branches, 2-cycle penalty each: effective CPI?
    Show answer

    1 + 0.3 × 2 = 1.6.

Common Pitfalls

  • Using k × n for pipelined time. The pipelined time is (k + n − 1) clocks; k × n is the non-pipelined count.
  • Clocking at the average stage delay. The clock must suit the slowest stage plus the register delay.
  • Expecting speedup = k for a few tasks. k is the limit only for very many tasks; for small n the fill time dominates.

Applications

  • Every modern processor pipelines instruction execution (typically 5 to 20 stages).
  • Floating-point units, graphics processors and DSPs pipeline arithmetic.
  • The compiler’s job of reordering instructions (delayed load, delayed branch) exists because of pipeline hazards.
