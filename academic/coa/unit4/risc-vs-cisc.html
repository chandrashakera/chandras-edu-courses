RISC vs CISC Architecture

⏱ 35 min read 📌 Supplementary — beyond the syllabus

Every processor makes one basic design choice: give programmers many powerful instructions, or give them a small set of simple instructions that run very fast. The first approach is called CISC (complex instruction set computer), the second RISC (reduced instruction set computer). This page compares the two, explains the overlapped register windows used in RISC designs, and works through the exam-style problems: instruction counts and memory references, CPU time, average CPI, register-file size and fixed-length instruction formats.

In simple terms

A CISC instruction can do a lot in one step — for example, read two numbers from memory, add them and write the result back. A RISC instruction does one small thing, works only on registers, and finishes in about one clock cycle. RISC needs more instructions for the same job, but each one is simple enough to decode quickly, run on hardwired control and overlap in a pipeline.

Why CISC Came First

When memory was small and expensive, a program that used fewer instructions saved memory. Designers also wanted machine instructions to look like high-level language statements, so the instruction set kept growing. Microprogrammed control made this affordable: a new complex instruction only needed a new routine in control memory, not new hardware. The result was large instruction sets with many addressing modes.

Studies of compiled programs later showed that most of the execution time was spent on a small number of simple instructions — loads, stores, adds, compares and branches. The rarely used complex instructions still cost decoding hardware and control-memory space, and slowed down the common case. RISC designs keep the frequent operations and make them fast.

Characteristics

CISC

  • A large number of instructions, some of them for special tasks that programs rarely use.
  • Many addressing modes.
  • Variable-length instruction formats.
  • Instructions that operate directly on operands in memory.
  • Usually a microprogrammed control unit.

RISC

  • Relatively few instructions and few addressing modes.
  • Memory is accessed only by load and store instructions; all other operations use CPU registers.
  • A fixed-length instruction format that is easy to decode.
  • Single-cycle execution for most instructions.
  • Hardwired rather than microprogrammed control.
  • A large number of registers (often organised as overlapped register windows), an efficient instruction pipeline, and a compiler that does more of the work.

Link to performance: CPU time = IC × CPI × T (instruction count × cycles per instruction × clock period). CISC lowers IC; RISC lowers CPI and usually allows a shorter T. Which one wins depends on the product of all three, as Problems 2 and 3 show.

Overlapped Register Windows

Procedure calls and returns are frequent in compiled programs, and each one normally saves registers to memory and passes parameters through memory. RISC I and its successors avoid most of this traffic with a large register file divided into overlapping windows. Only one window is active at a time. Each window has four parts:

  • Global registers (G): shared by all procedures.
  • High overlapping registers (C): parameters received from the calling procedure.
  • Local registers (L): used only by the active procedure.
  • Low overlapping registers (C): parameters passed to the next procedure called.

The low registers of the caller are the same physical registers as the high registers of the procedure it calls, so parameters pass without any data movement. A call moves the window pointer down one window; a return moves it back.

Window size (registers one procedure sees)
      = L + 2C + G

    Register file size (W windows)
      = (L + C) × W + G

Note: the textbook's RISC I example uses G = 10, L = 10, C = 6 and W = 8: a window of 32 registers and a file of 138. The first RISC I chip fabricated in 1981 actually carried 78 registers; the 138-register file was built in its successor, RISC II.

Solved Problems

Problem 1: The same statement on a CISC and a RISC machine

Compute X = (A + B) − C, where A, B, C and X are 32-bit words in memory.

CISC machine: memory-to-memory three-address instructions; each instruction is a 1-byte opcode plus a 2-byte address per memory operand. RISC machine: every instruction is 32 bits (4 bytes); only LOAD and STORE access memory. Find the number of instructions, the code size, the data memory references and the total memory traffic (instruction bytes + data bytes) for each.

CISC                    bytes  data refs
    ADD  T, A, B            7      3 (2 reads, 1 write)
    SUB  X, T, C            7      3
    Total: 2 instructions   14     6

    RISC                    bytes  data refs
    LOAD  R1, A             4      1
    LOAD  R2, B             4      1
    LOAD  R3, C             4      1
    ADD   R1, R1, R2        4      0
    SUB   R1, R1, R3        4      0
    STORE X, R1             4      1
    Total: 6 instructions   24     4

    Memory traffic (data word = 4 bytes)
    CISC: 14 + 6 × 4 = 38 bytes
    RISC: 24 + 4 × 4 = 40 bytes

Answer: CISC uses 2 instructions, 14 bytes of code and 6 data references; RISC uses 6 instructions, 24 bytes and 4 data references. CISC has smaller code, but it writes the temporary T to memory and reads it back; RISC keeps the intermediate result in R1. Total traffic is almost the same (38 vs 40 bytes) — the RISC advantage comes from simple, one-cycle instructions, not from fewer bytes.

Problem 2: CPU time, MIPS and break-even CPI

A program compiles to 50 million instructions on a CISC processor with an average CPI of 4.0 and a 2 GHz clock. On a RISC processor it compiles to 80 million instructions with an average CPI of 1.25 and a 2.5 GHz clock. (a) Find the CPU time on each and the speedup. (b) Find the MIPS rating of each. (c) What average CPI on the RISC processor would make the two equally fast?

(a) CPU time = IC × CPI / f
    CISC: 50×10⁶ × 4.0  / (2×10⁹)   = 0.100 s
    RISC: 80×10⁶ × 1.25 / (2.5×10⁹) = 0.040 s
    Speedup = 0.100 / 0.040 = 2.5

    (b) MIPS = f / (CPI × 10⁶)
    CISC: 2000 / 4.0  =  500 MIPS
    RISC: 2500 / 1.25 = 2000 MIPS   (ratio 4)

    (c) 80×10⁶ × CPI / (2.5×10⁹) = 0.100
        CPI = 0.100 × 2.5×10⁹ / 80×10⁶ = 3.125

Answer: (a) 0.100 s and 0.040 s; RISC is 2.5 times faster. (b) 500 and 2000 MIPS. The MIPS ratio (4) overstates the real speedup (2.5) because the two processors execute different instructions — compare CPU time, not MIPS. (c) Above an average CPI of 3.125 the RISC processor would lose its advantage, despite the faster clock.

Problem 3: Average CPI from an instruction mix

A RISC processor runs a program with this mix: ALU 50 % (CPI 1), load 20 % (CPI 2), store 10 % (CPI 1), branch 20 % (CPI 2). A CISC processor with the same clock needs only 60 % as many instructions for the program, with an average CPI of 3. (a) Find the average CPI of the RISC processor. (b) Which processor is faster, and by how much? (c) What CISC CPI would give equal performance?

(a) CPI(RISC) = 0.5×1 + 0.2×2 + 0.1×1 + 0.2×2
                 = 0.5 + 0.4 + 0.1 + 0.4 = 1.4

    (b) Same clock → compare IC × CPI
        RISC: IC × 1.4       = 1.4 IC
        CISC: 0.6 IC × 3     = 1.8 IC
        RISC faster by 1.8 / 1.4 = 1.29

    (c) 0.6 × CPI(CISC) = 1.4
        CPI(CISC) = 1.4 / 0.6 = 2.33

Answer: (a) 1.4. (b) The RISC processor is about 1.29 times faster. (c) A CISC CPI of about 2.33 would make them equal. The CISC processor's 40 % saving in instruction count does not make up for its higher CPI.

Problem 4: Register windows

A RISC processor has 8 global registers, 8 local registers per window, 8 overlapping registers between adjacent windows, and 6 windows. Registers in each window are numbered R0–R7 global, R8–R15 low, R16–R23 local, R24–R31 high. (a) Find the window size and the total register file. (b) When procedure P calls procedure Q, where does P put two parameters, and where does Q find them? (c) How many registers does P save to memory for this call?

(a) Window size = L + 2C + G
                   = 8 + 2×8 + 8 = 32
        File size   = (L + C) × W + G
                   = (8 + 8) × 6 + 8 = 104

        Check: a window of 32 registers needs
        5-bit register fields (2⁵ = 32).

    (b) P writes the parameters into its low
        registers, e.g. R8 and R9.
        The call moves the window; the same
        physical registers are now Q's high
        registers R24 and R25.

    (c) None — the overlap passes the parameters
        and Q has its own local registers.

Answer: (a) 32 registers per window and 104 in the file. (b) P's R8–R9 become Q's R24–R25. (c) No registers are saved. Memory is needed only when calls nest deeper than the windows available: the oldest window is then saved to memory and restored on return.

Problem 5: A fixed-length RISC instruction format

A RISC processor has 32-bit instructions, 64 registers and a 7-bit opcode. (a) In the three-register format (opcode, Rd, Rs1, Rs2), how many bits are left unused? How many opcodes are possible? (b) In the register-immediate format (opcode, Rd, Rs1, immediate), how many bits does the immediate get, and what is its range as a 2's complement number? (c) A branch uses opcode + displacement only. What displacement range is possible?

Register field = log₂ 64 = 6 bits

    (a) 7 + 6 + 6 + 6 = 25 bits used
        Unused = 32 − 25 = 7 bits
        Opcodes = 2⁷ = 128

    (b) Immediate = 32 − 7 − 6 − 6 = 13 bits
        Range = −2¹² … 2¹² − 1 = −4096 … +4095

    (c) Displacement = 32 − 7 = 25 bits
        Range = −2²⁴ … 2²⁴ − 1
              = −16 777 216 … +16 777 215

Answer: (a) 7 unused bits, 128 opcodes. (b) 13 bits, −4096 to +4095. (c) −16 777 216 to +16 777 215 (in the machine's addressing unit). Because every field sits at the same bit position in every instruction, the control unit can read the register numbers while it is still decoding the opcode — one reason RISC instructions decode in a single short step.

Practice Problems

Q1. For the machines of Problem 1, write X = A + B + C on each and find the instructions, code bytes and data references.

Show answer

CISC: ADD T, A, B; ADD X, T, C → 2 instructions, 14 bytes, 6 data references. RISC: LOAD R1, A; LOAD R2, B; LOAD R3, C; ADD R1, R1, R2; ADD R1, R1, R3; STORE X, R1 → 6 instructions, 24 bytes, 4 data references.

Q2. A CISC processor runs a program in 30 million instructions at CPI 3.5 and 3 GHz. A RISC processor at 3 GHz needs 1.5 times as many instructions at CPI 1.2. Find both CPU times and the speedup.

Show answer

CISC: 30×106 × 3.5 / 3×109 = 35 ms. RISC: 45×106 × 1.2 / 3×109 = 18 ms. Speedup = 35 / 18 ≈ 1.94.

Q3. A register file has 12 global registers, 12 local registers per window, 8 overlapping registers and 10 windows. Find the window size and the file size.

Show answer

Window = 12 + 2×8 + 12 = 40. File = (12 + 8) × 10 + 12 = 212.

Q4. A 32-bit RISC instruction has a 6-bit opcode and addresses 32 registers. How many bits remain for the immediate in the opcode, Rd, Rs1, immediate format, and what is its unsigned range?

Show answer

Register fields are 5 bits: 32 − 6 − 5 − 5 = 16 bits; unsigned range 0 to 65 535.

RISC and CISC Today

The line between the two is less sharp than in the 1980s. Intel x86 is a CISC instruction set, but since the P6 family Intel processors have split each x86 instruction into simple internal micro-operations and executed those on a pipelined, out-of-order core — a RISC-style engine behind a CISC decoder. ARM processors, used in most phones, and RISC-V, an open-standard instruction set maintained by RISC-V International, follow the RISC load/store approach. The exam answer stays the same: compare the instruction sets as defined, using the characteristics above.

Common Pitfalls

  • Saying RISC programs need fewer instructions. RISC needs more instructions; it wins on CPI and clock rate.
  • Comparing MIPS across RISC and CISC. The instructions do different amounts of work; compare CPU time.
  • Calling every RISC instruction single-cycle. Most are; loads, branches and multiplies can take longer, which is why the average CPI is above 1.
  • Mixing up the register-window formulas. Window size is L + 2C + G; the file size is (L + C) × W + G — the overlap is counted once per window, the globals once in total.
  • Linking RISC with microprogrammed control. RISC control is usually hardwired; microprogramming is typical of CISC.
  • Assuming RISC has no addressing modes. It has few, not none — register, immediate and displacement (and PC-relative for branches).
