General Register Organization

⏱ 18 min read 📝 Quiz inside

Processors need fast temporary storage for intermediate results — partial products during multiplication, pointer values during address computation, return addresses during subroutine calls. Using main memory for all of these is expensive: a memory access is the slowest operation a CPU performs. The solution is a small register file inside the CPU, connected through a shared bus and a single arithmetic logic unit. The resulting structure — a general register organisation — is the internal datapath most modern CPUs are built around.

In simple terms: pick two registers (SELA, SELB), pick an operation (OPR), pick where the answer goes (SELD). Those four choices, 14 bits in total, make one control word.

The Bus-Organised Register File

Mano's example uses seven registers, R1 through R7, plus an external input path. Every register output goes to two multiplexers. The single ALU output goes back to the inputs of all seven registers and to the external output; a 3×8 decoder decides which one register actually loads it. Sharing one ALU this way needs far less wiring than connecting every register to every other.

Register set with common ALU (block diagram and 14-bit control word). Adapted from M. Morris Mano, Computer System Architecture, Fig. 8-2.

MUX A (SELA) selects a source register for bus A. MUX B (SELB) selects a source register for bus B. Both drive the ALU, which performs the operation selected by OPR. The ALU result is placed on the output bus, which reaches all registers. The 3×8 decoder, driven by SELD, activates the load input of exactly one destination register, so only that register takes the result at the clock edge. When SELA or SELB = 000, the external Input is placed on that bus. When SELD = 000, the result is available on the external output only — no register is written.

The 14-Bit Control Word and ALU Operations

The four selector fields form a 14-bit control word: SELA (3 bits) + SELB (3 bits) + SELD (3 bits) + OPR (5 bits). The register encoding is simple: binary code 000 selects external Input (for SELA/SELB) or no destination (for SELD); codes 001–111 select R1–R7. There are eleven named ALU operations, including ADD (00010), SUB (00101), AND (01000), OR (01010), XOR (01100), COMA (01110), SHRA (10000), and SHLA (11000).

To execute R1 ← R2 + R3: set SELA = 010 (R2 on bus A), SELB = 011 (R3 on bus B), OPR = 00010 (ADD), SELD = 001 (result into R1). The 14-bit control word is 010 011 001 00010. On the clock edge the ALU result is loaded into R1.

Common Pitfalls

  • Confusing SELD with SELB. SELB selects a source register to read; SELD selects the destination register to write. Same 3-bit encoding, opposite purpose.
  • Three bits encoding seven registers. Code 000 is reserved, leaving only codes 001–111 for registers. A CPU with eight general-purpose registers needs a different convention or an extra bit.
  • OPR ignoring bus B. For single-operand operations (TSFA, INCA, COMA, shifts), the ALU uses only bus A. SELB must still hold a valid code — the MUX always drives bus B — but the OPR circuitry disregards it.
  • Read-before-write on the same register. If SELA = SELD = 001, the operation reads R1 at the start of the clock cycle and writes the result at the clock edge. This is correct: R1 ← R1 + R2 behaves as expected.
