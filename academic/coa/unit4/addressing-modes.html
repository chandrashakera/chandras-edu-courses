Addressing Modes

⏱ 18 min read 📝 Quiz inside

The addressing mode of an instruction specifies the rule for interpreting or modifying the address field before the operand is referenced. Modes serve two purposes: to give programmers flexibility (pointers, loop counters, array indexing, program relocation) and to reduce the number of bits needed in the address field. The effective address is the final memory address computed according to the given mode. This topic covers the addressing modes from implied to base register, and the table below works out the effective address for nine of them.

In simple terms: an addressing mode is the rule the CPU uses to find the data. The operand may be inside the instruction, in a register, in memory, or at an address the CPU must first calculate.

Instruction Format with Mode Field

Some computers encode the mode in a distinct binary field alongside the opcode and address. Others fold both opcode and mode into a single code. In either case, three phases govern every instruction: fetch, decode, execute. During decode the control unit reads the mode field to determine how to locate the operand.

Adapted from M. Morris Mano, Computer System Architecture, Fig. 8-6

Two modes need no address field at all — implied and immediate. The remaining seven all use the address field, but interpret it differently.

The Addressing Modes

1. Implied mode. The operand is specified implicitly in the instruction definition — no address field needed. All accumulator-referenced instructions are implied-mode (the operand location AC is implied). Zero-address stack instructions are also implied-mode — operands are implied to be on top of the stack.

2. Immediate mode. The operand field of the instruction contains the actual operand, not its address. No memory access is needed. Useful for loading a constant into a register. The effective address is the address of the instruction's second word (201 in the numerical example below).

3. Register mode. The address field specifies a processor register that contains the operand. No memory access is required. A k-bit field selects one of 2k registers. There is no memory effective address.

4. Register indirect mode. The address field specifies a register whose contents give the memory address of the operand. The instruction uses fewer bits than a direct address field would require. The programmer must load the desired address into the register beforehand.

5. Autoincrement or autodecrement mode. Like register indirect, but the register is automatically incremented after (autoincrement) or decremented before (autodecrement) the operand is accessed. Autoincrement is useful for stepping forward through a data table; autodecrement for stepping backward or implementing a stack.

6. Direct address mode. The address field of the instruction directly gives the effective address. The operand is fetched from that memory location in one access. In branch instructions the address field is the branch target.

7. Indirect address mode. The address field points to a memory word that contains the effective address. The control unit makes two memory accesses beyond the instruction fetch: first to read the effective address, then to read the operand.

8. Relative address mode. The effective address is the sum of the address field (a signed displacement) and the program counter, which has already been incremented past the instruction. Relative addressing produces position-independent code and needs fewer address bits because the displacement is small.

9. Indexed addressing mode. The effective address is the sum of the address field and the content of an index register (XR). The address field holds the base (beginning) of a data array; XR holds the element offset. The index register can be incremented to access successive array elements.

Base register addressing mode is computed the same way as indexed, but the register is called a base register and is used for program relocation rather than array indexing. The textbook text explains it, but it is not a separate row in the table below.

Numerical Example

Common Pitfalls

  • Relative mode PC value. By the time EA is computed, PC has already been incremented. In the example PC = 202 (not 200 or 201) is added to the address part.
  • Indirect vs register indirect. Indirect mode reads the EA from a memory location (two extra accesses). Register indirect reads it from a register (one extra access, no register indirect address in memory).
  • Autoincrement vs autodecrement order. Autoincrement increments after the access; autodecrement decrements before.
  • Nine modes in the table. The table lists exactly nine rows. Base register mode is explained in the textbook text but is not a separate row in the table above — it is computed identically to indexed mode but used differently (relocation rather than array indexing).
