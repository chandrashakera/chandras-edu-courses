Control Memory

⏱ 16 min read 📝 Quiz inside

Every machine instruction a computer executes triggers an ordered sequence of register transfers and ALU operations. Generating these control signals by logic gates alone — the hardwired approach — produces fast but inflexible hardware. Microprogrammed control offers a systematic alternative: all control signals are stored as binary patterns in a dedicated memory called the control memory, and the control unit reads them out one word at a time, exactly as a processor reads instructions from main memory.

In simple terms: a microprogrammed control unit is a tiny computer inside the CPU. Its program (the microprogram) lives in a ROM called control memory. Each word it reads out (a microinstruction) switches on the control signals for one clock cycle.

The Control Memory and the Microinstruction

Every word stored in control memory is called a microinstruction. A microinstruction specifies one or more microoperations — register transfers, ALU selections, memory-access signals — that are to be active during a single clock cycle. A contiguous sequence of microinstructions that implements one machine-language instruction is called a microprogram.

Because a microprogram never changes once the hardware is manufactured, the control memory can be a read-only memory (ROM). ROM is a combinational circuit: present an address at its inputs and the stored word appears immediately at the output, with no clock edge needed to trigger the read. Some advanced designs use writable control memory (RAM), enabling dynamic microprogramming — a new microprogram can be loaded from disk at boot time, allowing one processor to emulate another.

Hardware Organisation

The microprogrammed control unit has four components working together.

Microprogrammed control organization. Adapted from M. Morris Mano, Computer System Architecture, Fig. 7-1.

The CAR holds the address of the current microinstruction. The sequencer computes the next address. The ROM outputs the microinstruction at the CAR address. The CDR (pipeline register) holds the fetched microinstruction while the next address is being computed; Mano's Chapter 7 example omits the CDR and uses a single-phase clock, reading the control word directly from ROM output.

The Microinstruction Format

In Mano's example computer, the control memory is 128 × 20: 128 microinstructions, each 20 bits wide, divided into six fields:

Microinstruction code format (20 bits). Adapted from M. Morris Mano, Computer System Architecture, Fig. 7-6.

The nine bits F1–F2–F3 select up to three simultaneous microoperations (code 000 = no operation in that field). The AD field is seven bits wide because 2⁷ = 128 matches the control memory size. CD selects which status bit to test; BR specifies the type of address transition.

Common Pitfalls

  • Confusing control memory with main memory. They are physically separate. Main memory holds user programs; control memory holds the microprogram that interprets those programs.
  • Assuming the CDR is always present. The organisation figure above shows the CDR as a pipeline register; Mano's worked example leaves it out and reads the control word straight from the ROM. Draw it only when the question asks for the general organisation or a pipelined design.
  • Conflicting microoperations. Two fields may specify operations on the same register simultaneously, producing an undefined result. Always check for conflicts when writing microcode.
  • AD field width. Seven bits address 128 locations exactly. If the control memory size changes, the AD field width changes with it.
