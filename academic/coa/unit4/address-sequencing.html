Address Sequencing

⏱ 20 min read 📝 Quiz inside

A microprogram stored in control memory is not executed strictly from beginning to end. Each machine instruction maps to its own microprogram routine, those routines share a common fetch sequence, and conditional branches may take different paths depending on status bits. The hardware that computes which address to load into the CAR for the next clock cycle is the microprogram sequencer. Understanding its four capabilities is the central task of this topic.

In simple terms: after each microinstruction the CAR must get a new address. It can step to the next one, jump to the AD address, jump to the start of the routine for the current machine instruction (mapping), or jump into and back from a subroutine.

Four Required Capabilities

Mano identifies four operations the sequencer must support:

  1. Increment the CAR — execute the next microinstruction in sequence.
  2. Unconditional or conditional branch — jump to the address in the AD field, always or only when a tested status bit has a specific value.
  3. Map the machine-instruction opcode to a control memory address — at the start of each execute phase, jump to the routine for the current machine instruction.
  4. Subroutine call and return — jump to a shared microprogram subroutine and return to the calling address afterwards.

The Sequencer Block

Selection of address for control memory. Adapted from M. Morris Mano, Computer System Architecture, Fig. 7-2.

The multiplexers choose the next address from four sources: the incrementer (CAR + 1), the branch address from the AD field, the mapping logic, and the SBR. The incrementer adds one to the CAR value; its output also feeds the SBR during a subroutine call. The subroutine register (SBR) saves the return address. The branch logic tests the status bit selected by CD and drives the MUX select lines. The mapping logic converts the machine-instruction opcode into a control memory starting address.

The CD and BR Fields

BRSymbolFunction
00JMPCAR ← AD if condition = 1; CAR ← CAR + 1 if condition = 0
01CALLCAR ← AD and SBR ← CAR + 1 if condition = 1; CAR ← CAR + 1 if condition = 0
10RETCAR ← SBR (return from subroutine)
11MAPCAR(2–5) ← DR(11–14), CAR(0, 1, 6) ← 0

Adapted from M. Morris Mano, Computer System Architecture, Table 7-1

CD selects the condition: 00 = U (always 1), 01 = I (DR(15), indirect bit), 10 = S (AC(15), sign), 11 = Z (AC = 0). With CD = 00, JMP and CALL always take the branch. The mapping logic is implemented with a PLD or a small ROM that transforms opcode bits into a control memory address. Nested subroutine calls require a hardware stack in the SBR, since one register can only save one return address.

Worked Examples

Example 1 — Mapping an opcode to its routine address

Mapping rule: 0 xxxx 00  (a 0, the 4-bit opcode, then 00) → each routine gets 4 microinstructions
ADD      opcode 0000 → 0 0000 00 = 0
BRANCH   opcode 0001 → 0 0001 00 = 4
STORE    opcode 0010 → 0 0010 00 = 8
EXCHANGE opcode 0011 → 0 0011 00 = 12

Example 2 — Width of the address field

A control memory of 2k words needs k address bits: 128 words → 7 bits; 512 words → 9 bits.

Example 3 — Subroutine call and return

CAR = 45 holds "CALL 80":  SBR ← CAR + 1 = 46,  CAR ← 80
Subroutine runs at 80, 81, … 85;  85 holds "RET":  CAR ← SBR = 46
Execution resumes at 46 — the microinstruction after the call.

Common Pitfalls

  • Forgetting the mapping step. The correct sequence is fetch → map → execute. The sequencer cannot jump from the fetch routine to the correct execute routine without the mapping hardware.
  • Confusing BR and CD. BR selects what kind of address transition to make; CD selects which status bit to test. Both fields act together for conditional branching.
  • SBR depth. One SBR register supports only one level of subroutine nesting. A subroutine that calls another subroutine overwrites the first return address.
  • Mapping input. Mapping logic reads opcode bits from the instruction register, not from the AD field of the current microinstruction.
