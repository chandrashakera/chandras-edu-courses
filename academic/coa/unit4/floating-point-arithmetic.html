Floating-Point Arithmetic Operations

⏱ 18 min read 📝 Quiz inside

Floating-point numbers appear in programs wherever a real declaration is used instead of an integer declaration. Any processor that supports a high-level language must be able to perform floating-point arithmetic either in hardware or through software subroutines. This topic develops the hardware algorithms for all four floating-point operations.

In simple terms: a floating-point number is a mantissa times a power of 2. To add, first make the exponents equal by shifting a mantissa; to multiply, add the exponents and multiply the mantissas; to divide, subtract the exponents and divide the mantissas — then normalise.

Floating-Point Representation — Basics

A floating-point number in a register consists of two parts: a mantissa m and an exponent e, representing the value m × re where r is the radix. The radix and the position of the radix point are implied, not stored. This topic assumes binary (r = 2) with the mantissa stored as a fraction.

A floating-point number is normalised when the most significant digit of the mantissa is nonzero. Normalisation maximises the number of significant digits in the mantissa. Zero cannot be normalised; it is represented with all 0s in both mantissa and exponent fields.

Biased Exponent

The exponent can be stored in one of four ways: signed-magnitude, signed-2's complement, signed-1's complement, or biased. The biased representation is the most common. A positive bias value is added to every exponent before it is stored, so that all stored exponents are non-negative. For example, with a bias of 50 and an exponent range of −50 to +49, the stored values are 0 to 99 — all positive, requiring no sign bit.

Advantage of biased exponents: all stored exponents are positive, so a magnitude comparator (no sign logic needed) can compare their relative size. This simplifies the mantissa alignment hardware.

Register Configuration

The figure below shows the three registers used for floating-point operations. Each register is divided into a mantissa part (uppercase letter: B, A, Q) and an exponent part (corresponding lowercase letter: b, a, q). The sign bit of the mantissa is separate (Bₛ, Aₛ, Qₛ).

Register configuration for floating-point arithmetic operations. Adapted from M. Morris Mano, Computer System Architecture, Fig. 10-14.

  • BR (Bₛ, B, b): holds one operand — its sign, mantissa, and biased exponent.
  • AC (Aₛ, A₁, A, a): the accumulator. A₁ is the MSB of the mantissa and is checked during normalisation — it must be 1 for the number to be normalised.
  • QR (Qₛ, Q, q): used as the multiplier/quotient register during multiplication and division.
  • A parallel adder handles mantissa arithmetic (same circuit as fixed-point); a separate parallel adder and comparator handles exponent operations.

Addition and Subtraction

Floating-point addition and subtraction proceed in four phases.

Phase 1 — Check for zeros

If BR = 0 the result is already in AC (no operation). If AC = 0 then AC ← BR (load the other operand). For subtraction when AC = 0, the sign of AC is complemented. If neither is zero, proceed to alignment.

Phase 2 — Align mantissas

The exponents a and b are compared. The mantissa with the smaller exponent is shifted right and its exponent incremented, one bit at a time, until both exponents are equal. Shifting right rather than left preserves the most significant digits — left shifts would lose precision.

Phase 3 — Add or subtract mantissas

Once aligned, the mantissa arithmetic follows the signed-magnitude algorithm from the Addition and Subtraction topic. The signs Aₛ and Bₛ together with the operation (add/sub) determine whether the magnitudes are added or subtracted. If an overflow carry E = 1 occurs during addition, the sum is shifted right and the exponent incremented.

Phase 4 — Normalise the result

After subtraction the result may have leading zeros (underflow). The mantissa is shifted left and the exponent decremented until A₁ = 1. If the mantissa is all zeros, AC is cleared to represent zero. An overflow carry from addition (E = 1) is handled by shifting right once and incrementing the exponent.

Addition and subtraction of floating-point numbers (four phases). Adapted from M. Morris Mano, Computer System Architecture, Fig. 10-15.

Multiplication

Floating-point multiplication does not require mantissa alignment. The algorithm has four steps:

  1. Check for zeros. If either operand is zero, set AC ← 0 and stop.
  2. Add exponents. a ← q (copy QR exponent), then a ← a + b. Since both exponents are biased, their sum has double the bias. Subtract the bias: a ← a − bias.
  3. Multiply mantissas. The mantissa multiplication follows the same shift-and-add algorithm as in the Multiplication Algorithms topic. The double-precision product is in AQ; only the single-precision part in AC is kept.
  4. Normalise. Check A₁. If A₁ = 0 (underflow — at most one leading zero is possible since both inputs were normalised), shift AQ left and decrement the exponent once. If A₁ = 1, the product is already normalised.

Multiplication of floating-point numbers. Adapted from M. Morris Mano, Computer System Architecture, Fig. 10-16.

Why subtract the bias in multiply? Adding two biased exponents a + b yields (truea + bias) + (trueb + bias) = truea + trueb + 2×bias. Subtracting one bias gives the correctly biased product exponent: truea + trueb + bias.

Division

Floating-point division requires that the mantissas be divided and the exponents subtracted. The algorithm has five steps:

  1. Check for zeros. If BR = 0 — divide by zero: terminate with an error. If AC = 0 — result is zero: set QR ← 0 and stop.
  2. Initialise. Qₛ ← Aₛ ⊕ Bₛ (sign of quotient), Q ← 0, SC ← n − 1.
  3. Align dividend. EA ← A + B̄ + 1 (trial subtraction). If E = 1 (A ≥ B), shift A right and increment a so that A < B — this is called dividend alignment and prevents mantissa divide overflow. If E = 0 (A < B), restore A by adding B.
  4. Subtract exponents. a ← a + b̄ + 1 (subtract biased exponents). Add the bias back and transfer to q.
  5. Divide mantissas. The mantissa division follows the algorithm in the Division Algorithms topic. Since dividend alignment guarantees A < B, the result is already normalised — no normalisation step is needed after division.

Division of floating-point numbers. Adapted from M. Morris Mano, Computer System Architecture, Fig. 10-17.

Dividend alignment: by ensuring A < B before dividing, the mantissa quotient is guaranteed to be a fraction less than 1, which is already in normalised form. Division is the only FP operation that does not require a separate normalisation step.

Comparison of All Four Operations

DivideSubtract exponents; add biasDivideNo — dividend alignment guarantees normalised result

Summary

  • A floating-point number = mantissa × 2exponent; mantissa is a fraction; exponent is biased (all stored values positive).
  • Normalised: A₁ = 1 (MSB of mantissa nonzero). Zero is all-zeros in both fields.
  • Add/Sub: 4 phases — zero check → align (shift smaller mantissa right) → add/sub mantissas → normalise.
  • Multiply: zero check → add exponents (subtract bias once) → multiply mantissas → at most one normalisation shift.
  • Divide: zero check → init → dividend alignment (ensure A < B) → subtract exponents (add bias) → divide mantissas; result already normalised.
  • All four operations share the same registers (BR, AC, QR) and the same mantissa adder as fixed-point arithmetic.
