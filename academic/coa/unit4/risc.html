RISC

⏱ 15 min read 📝 Quiz inside 📌 Supplementary (beyond syllabus)

As digital hardware became cheaper in the 1970s, instruction sets grew in size and complexity. Computers accumulated hundreds of instructions — complex operations intended to bridge the gap between high-level languages and machine code. By the early 1980s researchers noticed that compilers rarely used most of these complex instructions and that the hardware to decode and execute them slowed down the entire machine. The response was the Reduced Instruction Set Computer (RISC) philosophy: fewer, simpler instructions that execute faster within the CPU itself.

In simple terms: a RISC CPU uses a small set of simple, fixed-length instructions that finish in one clock cycle, keeps data in many registers, and touches memory only with load and store.

CISC Characteristics

A complex instruction set computer (CISC) is designed around the goal of providing one machine instruction for each high-level language statement. The major characteristics of CISC architecture are:

  1. A large number of instructions — typically from 100 to 250
  2. Some instructions that perform specialised tasks and are used infrequently
  3. A large variety of addressing modes — typically from 5 to 20 different modes
  4. Variable-length instruction formats
  5. Instructions that can manipulate operands directly in memory

RISC Characteristics

RISC architecture reduces execution time by simplifying the instruction set so that each instruction executes in a single clock cycle. The 7 major characteristics of a RISC processor are:

  1. Relatively few instructions
  2. Relatively few addressing modes
  3. Memory access limited to load and store instructions only
  4. All operations done within the registers of the CPU
  5. Fixed-length, easily decoded instruction format
  6. Single-cycle instruction execution
  7. Hardwired rather than microprogrammed control

Because only load and store instructions access memory, all arithmetic and logic operations work on register operands. This simplifies the control unit, allows fixed-length instructions to be decoded in a single cycle, and makes hardwired control practical. Single-cycle execution is achieved by overlapping the fetch, decode, and execute phases of successive instructions — a technique called pipelining.

Overlapped Register Windows

RISC processors typically include a large number of registers to reduce memory accesses. One important feature is the use of overlapped register windows to accelerate procedure call and return. The concept is illustrated in the figure below.

Overlapped register windows. Adapted from M. Morris Mano, Computer System Architecture, Fig. 8-9.

In the figure above the system has a total of 74 registers. Registers R0 through R9 are 10 global registers available to all procedures. The remaining 64 registers are divided into 4 windows for procedures A, B, C, and D. Each window consists of 10 local registers and two sets of 6 registers that overlap with the adjacent windows. Using the formula: window size = L + 2C + G = 10 + 12 + 10 = 32 registers visible to each active procedure; register file = (L + C) × W + G = (10 + 6) × 4 + 10 = 74 total registers.

The overlap is the key mechanism: the high registers of the calling procedure are the same physical registers as the low registers of the called procedure. Parameters are automatically available to the called procedure without copying — the same bits are simply visible under different register names in the two windows.

Berkeley RISC I — Instruction Set and Formats

Berkeley RISC I, developed at the University of California, Berkeley, was one of the first projects demonstrating the RISC approach. It is a 32-bit integrated circuit CPU with a 32-bit fixed-length instruction format, a total of 31 instructions grouped in three categories, and 3 addressing modes: register, register-immediate, and PC-relative.

The figure below shows the three instruction formats. The opcode field is 8 bits wide: 7 bits specify the operation and the 8th bit controls whether the status register is updated after an ALU operation.

Bit 13 chooses the second source: 0 means S2 is a 5-bit register number (bits 12–5 unused), 1 means S2 is a 13-bit signed constant. In the PC-relative format the COND field takes the place of Rd and selects one of 16 branch conditions, and Y is a 19-bit relative address used by the jump and call instructions.

Berkeley RISC I instruction formats. Adapted from M. Morris Mano, Computer System Architecture, Fig. 8-10.

Berkeley RISC I has 31 instructions in three categories: data manipulation (arithmetic, logic, shift), data transfer (load, store, PSW transfer), and program control (jump, call, return, interrupt). Every instruction uses three operands; the second source S2 can be either a register or a 13-bit signed immediate, selected by bit 13.

Common Pitfalls

  • Confusing RISC and CISC instruction counts. RISC has fewer instructions (Berkeley RISC I has 31); a typical CISC has 100–250. Fewer instructions does not mean less capability — compilers generate sequences of simple instructions to achieve the same effect as one complex one, usually faster.
  • Misunderstanding overlapped windows. The overlap registers are not copies — they are the same physical registers visible under different names in adjacent windows. No data movement occurs during a procedure call; the caller simply stores parameters in its high-overlap registers, which automatically appear as the low-overlap registers of the callee.
  • Assuming RISC means no memory access. RISC restricts memory access to load and store instructions only; all other operations use register operands. This is different from having no memory access at all.

Key Points

  • CISC has 5 major characteristics including large instruction counts (100–250), many addressing modes, variable-length formats, and memory operands.
  • RISC has 7 major characteristics: few instructions, few addressing modes, memory access only via load/store, register-only operations, fixed-length format, single-cycle execution, and hardwired control.
  • The overlapped register windows use a 74-register file with 10 global registers (R0–R9) and 4 windows of 32 registers each. Adjacent windows share 6 overlap registers that pass parameters without copying.
  • Berkeley RISC I has 31 instructions, a 32-bit fixed-length format, and 3 addressing modes: register, register-immediate, and PC-relative.
  • The opcode field is 8 bits: 7 bits for the operation, 1 bit to control status register update. Bit 13 selects between a 5-bit register address and a 13-bit signed immediate for the second source operand.
