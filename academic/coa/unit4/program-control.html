Program Control

⏱ 16 min read 📝 Quiz inside 📖 Mano, §8-7

Reference: M. Morris Mano, Computer System Architecture, §8-7

Under normal sequential execution the program counter is incremented after every fetch so that instructions execute one after another in memory order. Program control instructions break this sequence by loading a new value into the program counter, causing the CPU to branch to a different part of the program. Section 8-7 covers the instructions that alter program flow — branches, calls, returns, and interrupts — and the status bits that make conditional branching possible.

Program Control Instructions

Table 8-10 lists 7 typical program control instructions. Branch and jump instructions are used interchangeably in many architectures, though some use them to distinguish different addressing modes. The compare and test instructions do not change program flow directly; they update status bits, which a subsequent conditional branch then tests.

Table 8-10 — Typical program control instructions (Mano §8-7)
NameMnemonicAction
BranchBRPC ← branch address (conditional or unconditional)
JumpJMPUnconditional transfer to specified address
SkipSKPIncrement PC by 1 extra if condition is met (skip next instruction)
CallCALLSave return address; transfer to subroutine
ReturnRETRestore return address into PC; resume caller
Compare (by subtraction)CMPSet status bits from A − B; result discarded
Test (by ANDing)TSTSet status bits from A AND B; result discarded

Status Bit Conditions

A status register supplements the ALU by storing condition codes from the most recent operation. Figure 8-8 shows the block diagram of an 8-bit ALU with a 4-bit status register. The four status bits are named C, S, Z, and V, set or cleared by ALU operations as follows:

Figure 8-8 — Status register bits (Mano §8-7)

The four status bits are set or cleared after each ALU operation:

  • C (carry): set to 1 if the end carry C₈ is 1 after an addition; cleared to 0 otherwise.
  • S (sign): set to 1 if the highest-order bit F₇ of the result is 1 (indicating a negative value in 2's complement); cleared otherwise.
  • Z (zero): set to 1 if all bits of the ALU output are 0; cleared if any bit is 1.
  • V (overflow): set to 1 if the exclusive-OR of the last two carries (C₇ and C₈) equals 1, indicating 2's complement overflow; cleared otherwise.

For an 8-bit ALU, overflow (V = 1) means the result is greater than +127 or less than −128. The XOR of C₇ and C₈ detects this because overflow occurs exactly when the carry into the sign bit differs from the carry out of it.

Note that BE and BNE appear in both the unsigned and signed groups because the test for equality (Z = 1) is the same regardless of whether the operands are treated as signed or unsigned. The terms higher and lower apply to unsigned comparison; greater than and less than apply to signed comparison, where the V and S bits must both be considered.

Subroutine Call and Return

A subroutine is a self-contained sequence of instructions that can be called from multiple points in a program. When a CALL instruction executes, the CPU must save the return address (the address of the next instruction after CALL) so the subroutine knows where to return. The most efficient mechanism uses a memory stack, implemented with the following RTL:

CALL subroutine:
SP ← SP − 1           Decrement stack pointer
M[SP] ← PC           Push return address onto stack
PC ← effective address   Transfer control to subroutine
Return from subroutine (RET):
PC ← M[SP]           Pop return address into PC
SP ← SP + 1           Increment stack pointer

Using a stack for return addresses means that nested and recursive subroutine calls are handled automatically — each call pushes a new return address, and each return pops the most recent one, always returning to the correct caller.

Program Interrupt

Program interrupt transfers control from a running program to a service routine in response to an event that occurs asynchronously or as an error condition. Section 8-7 identifies three major types of interrupt:

  • External interrupts — initiated by signals from input/output devices, timing circuits, or power-failure detectors outside the CPU. These are asynchronous with respect to the currently executing program.
  • Internal interrupts — also called traps, triggered by illegal or erroneous instruction execution: register overflow, division by zero, invalid operation code, stack overflow, or protection violation. They are synchronous — the same instruction always causes the same trap.
  • Software interrupts — initiated by executing a special instruction (a supervisor call). The program deliberately invokes an interrupt, typically to switch from user mode to supervisor mode in order to request an operating-system service.

The interrupt mechanism is similar to a subroutine call: the CPU pushes the program counter and the program status word (PSW) onto the stack, then loads the branch address of the service routine into the PC. When the service routine finishes, a return from interrupt instruction pops the PSW and PC, restoring the CPU state exactly as it was when the interrupt occurred.

Common Pitfalls

  • Confusing signed and unsigned branch conditions. After CMP A, B, the instruction BHI tests whether A is unsigned higher than B; BGT tests whether A is signed greater than B. The two give different results for the same bit patterns when the values are negative.
  • Forgetting that compare and test discard the result. CMP sets status bits from A − B but does not store the difference; TST sets them from A AND B but discards the AND. The original operands are preserved.
  • Overflow vs carry. C flags a carry out of the most significant bit (relevant for unsigned arithmetic); V flags a sign-bit change caused by overflow (relevant for signed 2's complement arithmetic). They are independent.

Key Points

  • Table 8-10 lists 7 program control instructions. Branch, jump, skip, call, return, compare, and test.
  • The status register holds 4 bits — C, S, Z, V — derived from C₈, F₇, the zero-check circuit, and XOR(C₇, C₈) respectively.
  • Table 8-11 groups conditional branch instructions into 3 groups: flag-based, unsigned compare, and signed compare conditions.
  • Subroutine CALL stores the return address on the stack and transfers to the subroutine; RET pops it back into PC.
  • The 3 interrupt types are external (asynchronous hardware events), internal (traps from erroneous instructions), and software (deliberate supervisor calls).
