CPU Performance: CPI, MIPS and Amdahl's Law — Solved Problems

⏱ 30 min read 📌 Supplementary — beyond the syllabus

How do you say one processor is "faster" than another? Clock speed alone does not answer it, and neither does the MIPS figure on a datasheet. This page builds the one equation that does — CPU time = Instruction count × CPI × Clock cycle time — and then uses Amdahl's law to show how much an improvement to one part of a system can really help. Nine solved problems cover the question types seen in university exams, followed by practice problems with answers.

In simple terms: A program's running time depends on three things: how many instructions it executes, how many clock cycles each instruction takes on average (CPI), and how long one clock cycle is. Improve any one and the program runs faster — unless the change makes another one worse. Amdahl's law adds a reality check: speeding up one part only helps in proportion to how much of the time that part was taking.

Notation bridge: question papers also write Amdahl's law as Speedup = 1 / [(1 − Fractionenhanced) + Fractionenhanced / Speedupenhanced], or with p and s in place of Fe and Se. It is the same equation. Here f always means clock rate, so the fraction is written Fe.

The Three Factors at a Glance

FactorMainly decided byExample of a change
Instruction count (IC)Algorithm, compiler, instruction setA better compiler removes redundant loads
CPIProcessor organisation, memory system, instruction mixA larger cache cuts the cycles spent waiting on loads
Clock cycle time (T)Circuit technology, pipeline depthA faster process raises the clock rate

No single factor is a fair measure of speed on its own. Only the product IC × CPI × T gives the time the user actually waits.

Solved Problems — CPU Time, CPI and MIPS

Problem 1: CPU time and MIPS from IC, CPI and clock rate

A program executes 2 × 106 instructions on a 500 MHz processor with an average CPI of 2.5. Find the CPU time and the MIPS rating.

Clock cycle time  T = 1 / (500 × 10⁶) = 2 ns

    CPU time = IC × CPI × T
             = 2 × 10⁶ × 2.5 × 2 ns
             = 10 × 10⁶ ns
             = 10 ms

    MIPS = f / (CPI × 10⁶) = (500 × 10⁶) / (2.5 × 10⁶) = 200

    Check: IC / (time × 10⁶) = 2 × 10⁶ / (0.01 × 10⁶) = 200  ✓

Answer: CPU time = 10 ms; MIPS = 200.

Problem 2: Average CPI from an instruction mix

A 900 MHz processor runs a program of 109 instructions with this mix:

ClassFraction of instructionsCPI
ALU50 %1
Load/Store30 %3
Branch20 %2

Find the average CPI, the MIPS rating and the CPU time.

Average CPI = Σ (Fᵢ × CPIᵢ)
                = 0.5 × 1 + 0.3 × 3 + 0.2 × 2
                = 0.5 + 0.9 + 0.4
                = 1.8

    MIPS = (900 × 10⁶) / (1.8 × 10⁶) = 500

    CPU time = (IC × CPI) / f
             = (10⁹ × 1.8) / (900 × 10⁶)
             = 2 s

Answer: CPI = 1.8; MIPS = 500; CPU time = 2 s.

Note the cycle shares: load/store instructions are 30 % of the instructions but use 0.9 of the 1.8 cycles per instruction — 50 % of the time. Problem 6 uses this.

Problem 3: Higher clock rate, higher CPI — which design is faster?

Design A runs at 2 GHz with CPI 1.6. Design B raises the clock to 2.5 GHz, but its deeper pipeline raises the CPI to 2.1. Both run the same program (same IC). Which is faster, and by how much? What CPI would B need just to match A?

IC is the same, so compare time per instruction = CPI / f

    A: 1.6 / (2 × 10⁹)   = 0.80 ns
    B: 2.1 / (2.5 × 10⁹) = 0.84 ns

    Time_B / Time_A = 0.84 / 0.80 = 1.05

    Break-even CPI for B:
    CPI_B / 2.5 GHz = 0.80 ns  →  CPI_B = 0.80 × 2.5 = 2.0

Answer: Design A is 1.05 times faster despite the lower clock rate. B needs CPI below 2.0 to beat A.

Problem 4: Why MIPS can mislead

A 2 GHz processor has three instruction classes with CPI 1 (class A), 2 (class B) and 4 (class C). Two compilers produce code for the same program with these instruction counts (in billions):

CompilerClass AClass BClass C
X421
Y811

Which code has the higher MIPS rating? Which runs faster?

Compiler X
      Cycles = (4×1 + 2×2 + 1×4) × 10⁹ = 12 × 10⁹
      Time   = 12 × 10⁹ / 2 × 10⁹       = 6 s
      IC     = 7 × 10⁹
      MIPS   = 7 × 10⁹ / (6 × 10⁶)      ≈ 1166.7
      CPI    = 12 / 7                   ≈ 1.71

    Compiler Y
      Cycles = (8×1 + 1×2 + 1×4) × 10⁹ = 14 × 10⁹
      Time   = 14 × 10⁹ / 2 × 10⁹       = 7 s
      IC     = 10 × 10⁹
      MIPS   = 10 × 10⁹ / (7 × 10⁶)     ≈ 1428.6
      CPI    = 14 / 10                  = 1.4

Answer: Y has the higher MIPS rating (≈ 1428.6 vs ≈ 1166.7), but X finishes first (6 s vs 7 s). Y executes many more simple instructions, which inflates MIPS without doing the work sooner. Compare machines or compilers by execution time, not MIPS.

Solved Problems — Amdahl's Law

Problem 5: Basic speedup and its upper limit

Floating-point operations take 40 % of a program's execution time. A new FP unit makes them 8 times faster. Find the overall speedup and the best speedup possible from improving FP alone.

Fₑ = 0.4,  Sₑ = 8

    S = 1 / [(1 − 0.4) + 0.4 / 8]
      = 1 / [0.6 + 0.05]
      = 1 / 0.65
      ≈ 1.54

    Upper limit (Sₑ → ∞):
    S_max = 1 / (1 − 0.4) = 1 / 0.6 ≈ 1.67

Answer: Overall speedup ≈ 1.54; even an infinitely fast FP unit cannot exceed ≈ 1.67, because 60 % of the time is untouched.

Problem 6: Amdahl's law needs the fraction of time, not of instructions

For the processor in Problem 2, a better cache reduces the load/store CPI from 3 to 2. Find the speedup (a) from the new CPI and (b) using Amdahl's law.

(a) New CPI = 0.5×1 + 0.3×2 + 0.2×2 = 0.5 + 0.6 + 0.4 = 1.5
        IC and f unchanged, so
        S = CPI_old / CPI_new = 1.8 / 1.5 = 1.2

    (b) Fraction of TIME in load/store (from Problem 2):
        Fₑ = 0.9 / 1.8 = 0.5
        Sₑ = 3 / 2 = 1.5
        S  = 1 / [(1 − 0.5) + 0.5 / 1.5]
           = 1 / [0.5 + 0.3333]
           = 1 / 0.8333
           = 1.2  ✓

    Wrong way: using the instruction fraction 0.3 as Fₑ
        1 / [0.7 + 0.3 / 1.5] = 1 / 0.9 ≈ 1.11  ✗

Answer: S = 1.2 both ways. Fe must be the fraction of execution time (cycles), which here is 0.5, not the 30 % instruction share.

Problem 7: How much must one part improve? (and when it is impossible)

A program runs in 80 s, of which 60 s is spent on multiply operations. By what factor must multiplication be sped up to make the whole program (a) 3 times faster, (b) 4 times faster?

Time_new = 20 s (rest, unchanged) + 60 / k s

    (a) Target = 80 / 3 ≈ 26.67 s
        20 + 60 / k = 26.67
        60 / k = 6.67   →   k = 9

    (b) Target = 80 / 4 = 20 s
        20 + 60 / k = 20
        60 / k = 0     →   no finite k works

Answer: (a) Multiplication must become 9 times faster. (b) Impossible — the 20 s of non-multiply work alone already equals the target. In Amdahl's terms, Fe = 60/80 = 0.75, so Smax = 1 / 0.25 = 4, and that limit is reached only as k → ∞.

Problem 8: Choosing between two enhancements

Enhancement P makes floating-point work (30 % of execution time) 3 times faster. Enhancement Q makes memory accesses (50 % of execution time) 1.5 times faster. The two parts do not overlap. Which single enhancement gives more speedup? What if both are applied?

P: S = 1 / [0.7 + 0.3 / 3]   = 1 / 0.80   = 1.25
    Q: S = 1 / [0.5 + 0.5 / 1.5] = 1 / 0.8333 = 1.20

    Both (unenhanced part = 1 − 0.3 − 0.5 = 0.2):
    S = 1 / [0.2 + 0.3 / 3 + 0.5 / 1.5]
      = 1 / [0.2 + 0.1 + 0.3333]
      = 1 / 0.6333
      ≈ 1.58

Answer: P is better alone (1.25 vs 1.20). Together they give ≈ 1.58. Note that 1.25 × 1.20 = 1.5 is not the combined answer — speedups do not multiply when both are measured against the same original time.

Problem 9: Amdahl's law for multiprocessors

90 % of a program's execution time can be split evenly across processors; the rest is serial. Find (a) the speedup on 10 processors, (b) the limit as processors increase, (c) the number of processors needed for a speedup of 8.

Fₑ = 0.9,  Sₑ = n (number of processors)

    (a) n = 10:
        S = 1 / [0.1 + 0.9 / 10] = 1 / 0.19 ≈ 5.26

    (b) n → ∞:
        S_max = 1 / 0.1 = 10

    (c) 1 / [0.1 + 0.9 / n] = 8
        0.1 + 0.9 / n = 0.125
        0.9 / n = 0.025   →   n = 36

Answer: (a) ≈ 5.26 on 10 processors; (b) never above 10; (c) 36 processors. Going from 10 to 36 processors (3.6 times the hardware) raises the speedup only from 5.26 to 8.

Practice Problems

Q1. A 1.2 GHz processor runs a program of 3 × 109 instructions in 4 s. Find the average CPI and the MIPS rating.

Show answer

Cycles = 4 × 1.2 × 109 = 4.8 × 109; CPI = 4.8 / 3 = 1.6. MIPS = 3 × 109 / (4 × 106) = 750.

Q2. A 2 GHz processor executes ALU instructions 40 % (CPI 1), loads 25 % (CPI 4), stores 15 % (CPI 3) and branches 20 % (CPI 2). Find the average CPI and the MIPS rating.

Show answer

CPI = 0.4 + 1.0 + 0.45 + 0.4 = 2.25. MIPS = 2000 / 2.25 ≈ 888.9.

Q3. 25 % of a program's execution time cannot be parallelised. Find the maximum possible speedup and the speedup on 6 processors.

Show answer

Smax = 1 / 0.25 = 4. On 6 processors: 1 / (0.25 + 0.75 / 6) = 1 / 0.375 ≈ 2.67.

Q4. An enhancement runs 10 times faster than the original mode. What fraction of the original execution time must use it to give an overall speedup of 2.5?

Show answer

1 / [(1 − Fe) + Fe / 10] = 2.5 → 1 − 0.9 Fe = 0.4 → Fe = 2/3 ≈ 0.667 (66.7 % of the time).

Q5. Machine A runs at 3 GHz with CPI 2.4. Machine B runs at 2 GHz. For the same program and instruction count, what CPI must B have to match A?

Show answer

Time per instruction on A = 2.4 / 3 GHz = 0.8 ns. B: CPI / 2 GHz = 0.8 ns → CPI = 1.6.

Common Pitfalls

  • Judging speed by clock rate alone. A higher clock with a higher CPI can be slower (Problem 3).
  • Judging speed by MIPS. MIPS ignores how much work each instruction does; compare execution time instead (Problem 4).
  • Using the instruction fraction as Fe. Amdahl's law needs the fraction of execution time (Problem 6).
  • Multiplying separate speedups. For enhancements to different parts of the same program, add the enhanced and unenhanced time terms in one Amdahl expression (Problem 8).
  • Unit slips. 1 GHz ↔ 1 ns, 500 MHz ↔ 2 ns; MIPS divides by 106, not 109.
  • Counting lines of code as IC. IC is the number of instructions executed; a loop body counts once per iteration.
