Priority Interrupt

⏱ 18 min read 📝 Quiz inside

When a computer has several I/O devices, any of them can raise an interrupt at any time — including simultaneously. The system must decide which device to service first. Section 11-5 develops the hardware and software mechanisms for priority interrupt systems.

The Priority Problem

A priority interrupt system assigns each device a priority level. When two or more devices interrupt at the same time, the highest-priority device is serviced first. High-speed devices such as magnetic disks are given high priority (a missed disk transfer can cause data loss); slow devices such as keyboards receive low priority.

Two approaches exist: establishing priority by software polling or by hardware.

Software Polling

In software polling, all devices share a single interrupt line. When an interrupt occurs, the CPU branches to a common service routine that tests each device's status flag in sequence — highest priority first. The first device found with its flag set receives service.

Priority is determined entirely by the order in which the software tests devices. This is simple and flexible (priority can be changed in software) but slow when there are many devices, since every device must be tested before the correct one is found.

Hardware Priority — Daisy-Chain Method

The daisy-chain method connects all devices in a serial chain. Each device has a Priority In (PI) and a Priority Out (PO) signal.

  • The CPU sends an interrupt acknowledge (INTACK) signal that enters Device 1 at its PI input.
  • If Device 1 has no pending interrupt, it passes INTACK through to Device 2 via its PO → Device 2's PI.
  • The first device in the chain that does have a pending interrupt intercepts INTACK: it sets PO = 0 (blocking further propagation) and places its vector address (VAD) on the data bus.
  • The CPU reads VAD and jumps to that device's service routine.

Priority is determined by physical position: the device closest to the CPU (first in the chain) has the highest priority.

Each device stage contains an RF (request flip-flop) set by the interrupt request from the device. The internal logic for one daisy-chain stage (Fig 11-13) is:

  • PI = 0: PO = 0 and VAD is disabled regardless of RF. INTACK is blocked.
  • PI = 1, RF = 0: PO = 1 (pass INTACK on). Device has no pending request.
  • PI = 1, RF = 1: PO = 0 (block INTACK) and VAD is enabled onto the bus. This device services the interrupt.
PI/PO truth (one stage):
PI=0, RF=any → PO=0, VAD disabled
PI=1, RF=0   → PO=1, VAD disabled (pass through)
PI=1, RF=1   → PO=0, VAD enabled (intercept)

Hardware Priority — Parallel Method (Fig 11-14)

For faster priority resolution, each device has a separate wire to a central priority interrupt controller. Figure 11-14 shows the hardware for four devices (disk, printer, reader, keyboard — priority 0 to 3).

Fig 11-14 — Priority interrupt hardware (interrupt register, mask register, priority encoder).
Adapted from M. Morris Mano, Computer System Architecture, Fig. 11-14

The key components:

  • Interrupt register — one bit per device, set by the device's interrupt request signal and cleared by program instruction.
  • Mask register — one bit per device, set/cleared by program. Each interrupt bit is ANDed with its mask bit; masked (0) devices are ignored by the encoder.
  • Priority encoder — receives the four AND outputs (I₀–I₃) and produces a 2-bit vector address (VAD) for the highest-priority active device. I₀ (disk) has highest priority.
  • IST (interrupt status flip-flop) — set when any unmasked interrupt is active; generates the interrupt signal to the CPU (combined with IEN).
  • IEN (interrupt enable flip-flop) — global enable; IST AND IEN = interrupt to CPU. Programs set/clear IEN to globally enable or disable all interrupts.
  • INTACK — from the CPU; enables the VAD bus buffers so the winning device's address appears on the data bus.

Summary

  • A priority interrupt system services the highest-priority device first when multiple devices interrupt simultaneously.
  • Software polling: test devices in priority order in a common ISR — flexible but slow.
  • Daisy-chain: INTACK propagates through devices; the first requesting device intercepts it and places its VAD on the bus. Priority = position in chain.
  • Parallel (Fig 11-14): interrupt register + mask register + priority encoder; IST AND IEN drives the CPU interrupt line; INTACK enables the VAD of the winning device.
  • The mask register lets software selectively enable/disable individual interrupt sources without changing hardware.
