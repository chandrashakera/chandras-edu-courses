Memory Hierarchy

⏱ 15 min read 📝 Quiz inside

No single memory technology simultaneously provides unlimited capacity, zero access time, and zero cost. Instead, computer systems use a memory hierarchy — several levels of storage, each faster and more expensive than the one below it — to achieve a good balance of all three.

In simple terms: fast memory is expensive and small; cheap memory is slow and large. Computers combine several kinds — registers, cache, main memory, disk, tape — and keep the data needed right now in the fastest levels.

The Hierarchy

The figure below shows how these levels are connected. From bottom (slowest, cheapest, largest) to top (fastest, costliest, smallest):

  • Magnetic tape — removable, sequential access, very large capacity, very slow. Used for archival and backup.
  • Magnetic disk — random access (relative to tape), large capacity, slower than main memory. Primary auxiliary storage.
  • Main memory (RAM/ROM) — directly accessible by the CPU, medium capacity, access time ~100–700 ns.
  • Cache memory — very small, very fast (~10–100 ns), holds the currently active segments of programs and data.
  • CPU registers — the fastest storage; a handful of words inside the processor itself; access in one clock cycle.

The Cost-Capacity-Speed Trade-off

The fundamental reason the hierarchy exists is economics: as storage speed increases, the cost per bit rises and the practical capacity falls. The goal of the hierarchy is to give the CPU the impression of fast, large, cheap memory by keeping the most-used data in the fast levels and the rest in slower levels.

Access time ratios: Cache is approximately 7× faster than main memory (100 ns vs 700 ns). Auxiliary memory (disk) is approximately 1000× slower than main memory. Block sizes differ too: auxiliary memory block = 256–2048 words; cache block = 1–16 words.

Cache Memory

Cache sits between the CPU and main memory to compensate for the speed gap. The CPU accesses cache first. If the data is there (cache hit) it is obtained quickly. If not (cache miss) the data is fetched from main memory — often bringing a whole block into cache at once, exploiting the principle of locality of reference: programs tend to reuse recently accessed memory locations.

The cache holds those segments of programs currently executing and data currently in use. The Cache Memory topic covers cache mapping techniques in detail.

Auxiliary Memory and the I/O Processor

The CPU cannot access auxiliary memory directly. Transfer between auxiliary memory (disk, tape) and main memory is managed by the I/O processor (IOP) using DMA. When the CPU needs data not in main memory, it instructs the IOP to bring it in and then continues with another task (multiprogramming). When the transfer is done, the IOP interrupts the CPU.

Multiprogramming

Multiprogramming means keeping several independent programs at different levels of the hierarchy simultaneously — one executing in the CPU using cache, others waiting in main memory, yet others resident in auxiliary memory. The memory management system (software + hardware) supervises the movement of programs between levels. This keeps the CPU, the IOP, and the I/O devices all busy, maximising throughput.

Summary

  • Memory hierarchy: CPU registers → cache → main memory → auxiliary memory (disk → tape). Speed ↑, cost/bit ↑, capacity ↓ going up.
  • Goal: high apparent speed + large capacity + low average cost.
  • Cache access ≈ 7× faster than main memory; auxiliary ≈ 1000× slower than main memory.
  • Cache exploits locality of reference; block size 1–16 words.
  • Auxiliary ↔ main memory transfers via IOP (DMA); enables multiprogramming.
