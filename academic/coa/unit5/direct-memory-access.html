Direct Memory Access

⏱ 15 min read 📝 Quiz inside

When a high-speed device such as a magnetic disk needs to transfer a large block of data to memory, even interrupt-driven I/O is too slow — one interrupt per byte is too much overhead. Direct Memory Access (DMA) solves this by letting a dedicated controller manage the entire block transfer, bypassing the CPU for the data path.

In simple terms: instead of the CPU carrying every byte between a fast device and memory, a DMA controller borrows the memory bus and moves the data itself. The CPU only sets it up at the start and gets one interrupt at the end.

The DMA Idea

In programmed and interrupt-driven I/O, every data word flows through the CPU: the CPU reads the interface register and writes to memory (or vice versa). For high-speed devices this creates a bottleneck. DMA removes the CPU from the data path entirely:

  • The DMA controller takes temporary ownership of the memory bus.
  • Data flows directly between the I/O device and main memory.
  • The CPU is interrupted only once — when the entire block is done.

DMA Controller

The figure below shows the block diagram of a DMA controller. It sits between the memory bus and the I/O bus and contains three key registers.

Block diagram of DMA controller. Adapted from M. Morris Mano, Computer System Architecture, Fig. 11-18.

  • Address Register (AR) — holds the starting memory address for the transfer. Incremented by 1 after each word is transferred.
  • Word Count Register (WC) — holds the number of words to transfer. Decremented by 1 after each word. When WC reaches zero, the transfer is complete and the controller interrupts the CPU.
  • Control/Status Register — receives the transfer direction (read/write), the start command from the CPU, and records status (done, error) for the CPU to inspect after the interrupt.

The controller is selected by the CPU through the DMA select (DS) and register select (RS) inputs, like any interface, and talks to the I/O device through two lines: DMA request (device is ready) and DMA acknowledge (controller is transferring).

The CPU initialises all three registers, issues a start command, and then returns to its own program. The DMA controller takes over from there.

Bus Request and Bus Grant — BR / BG

The DMA controller and CPU share the memory bus. Two control lines coordinate access:

  • Bus Request (BR) — asserted by the DMA controller when it needs the memory bus for a transfer.
  • Bus Grant (BG) — asserted by the CPU in response, signalling that the bus is free. The CPU finishes its current bus cycle before granting.

When BG is active, the CPU places its address bus, data bus and read/write lines in the high-impedance state, so the DMA controller can drive them.

CPU bus signals for DMA transfer. Adapted from M. Morris Mano, Computer System Architecture, Fig. 11-17.

Once BG is received, the DMA controller takes ownership, performs the transfer, and then releases the bus. The CPU detects the release and resumes normal bus operations.

Cycle Stealing

DMA can transfer data in two ways. In burst transfer, the controller keeps the bus for a whole block of words in one continuous burst — fast, used for fast devices such as disks. In cycle stealing, it takes the bus for one word at a time and gives it back between words.

The most common DMA method is cycle stealing: the DMA controller steals one memory bus cycle at a time from the CPU, transferring exactly one word per stolen cycle.

DMA cycle stealing — one bus cycle is stolen per word transferred

The sequence for each stolen cycle:

  1. DMA controller asserts BR.
  2. CPU finishes its current bus cycle and asserts BG.
  3. DMA controller transfers one word (memory address from AR, data from/to device).
  4. DMA controller increments AR, decrements WC, releases the bus.
  5. CPU resumes. If WC ≠ 0, repeat from step 1 after the next device-ready signal.
Effect on the CPU: the CPU is slowed slightly — it is held off the bus for one cycle per stolen transfer — but it continues executing instructions between steals. This is far more efficient than interrupt-driven I/O for large blocks.

DMA Transfer Sequence — Summary

DMA transfer in a computer system. Adapted from M. Morris Mano, Computer System Architecture, Fig. 11-19.

  1. Initialise: CPU writes starting address into AR, word count into WC, and direction into the control register. Issues the start command.
  2. CPU continues with its own program.
  3. DMA transfers — one stolen cycle per word: BR → BG → transfer → increment AR → decrement WC → release bus.
  4. Completion: WC = 0 → DMA controller asserts interrupt. CPU checks status register and handles any errors.

Summary

  • DMA removes the CPU from the data path for block transfers between high-speed devices and memory.
  • Three DMA registers: AR (address, incremented each word), WC (count, decremented each word), Control/Status.
  • BR/BG handshake: DMA requests bus (BR), CPU grants (BG), DMA transfers one word, releases bus — repeated per word (cycle stealing).
  • CPU is interrupted once on completion (WC = 0), not once per byte.
