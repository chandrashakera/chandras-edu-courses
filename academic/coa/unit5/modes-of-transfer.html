Modes of Transfer

⏱ 15 min read 📝 Quiz inside

Once an interface is in place, the CPU must decide how to coordinate data movement between the interface register and main memory. This topic describes three fundamentally different strategies, each with a different trade-off between simplicity and CPU efficiency.

In simple terms: there are three ways to move I/O data — the CPU keeps checking (programmed I/O), the device taps the CPU on the shoulder when ready (interrupt), or a DMA controller moves whole blocks while the CPU does other work.

The three modes of I/O data transfer — overview

Mode 1 — Programmed I/O (Polling)

In programmed I/O the CPU is entirely responsible for detecting when data is ready and performing the transfer. The interface sets a flag bit (F) in its status register whenever a new data byte is available. The CPU runs a polling loop:

  1. Read the status register.
  2. Check the flag bit — if F = 0, go back to step 1 (busy-wait).
  3. When F = 1: read the data register; store the byte in memory; clear the flag.

The efficiency problem: if a device transfers one byte every 10,000 µs and a poll takes 1 µs, the CPU checks the flag 10,000 times per byte — wasting 9,999 cycles doing nothing useful. Programmed I/O is practical only for very fast devices or dedicated embedded systems that have nothing else to do.

Mode 2 — Interrupt-Driven I/O

To free the CPU from polling, the interface is given permission to interrupt the CPU when it has data ready.

  • The CPU enables the device and continues executing its main program.
  • When data is ready, the interface asserts the interrupt line (INT).
  • At the end of the current instruction, the CPU saves its program counter onto the stack and branches to an interrupt service routine (ISR).
  • The ISR reads the data register, stores the byte in memory, and clears the flag. The CPU then restores its state and resumes the main program.

Two approaches to finding the correct ISR exist. In a non-vectored interrupt the CPU always branches to a fixed address and must then poll devices to find which one interrupted. In a vectored interrupt the interrupting device itself places a vector (the address of its own ISR, or a pointer to it) on the data bus during the interrupt acknowledge cycle — no polling needed.

Mode 3 — Direct Memory Access (DMA)

For high-speed devices (magnetic disk, network) that transfer large blocks of data, even interrupt-driven I/O is too slow — one interrupt per byte is too much overhead. DMA solves this by delegating the entire block transfer to a dedicated DMA controller:

  1. The CPU programmes the DMA controller with the starting memory address, the byte count, and the direction (read/write).
  2. The CPU releases the bus to the DMA controller and continues executing (if it has access to a cache or separate bus) or halts bus access temporarily.
  3. The DMA controller transfers the entire block, incrementing the address and decrementing the count for each byte.
  4. When the count reaches zero, the DMA controller interrupts the CPU to signal completion.

Summary

  • Programmed I/O: CPU polls the flag bit; simple but wastes CPU cycles in a busy-wait loop.
  • Interrupt-driven I/O: device interrupts when ready; CPU runs other tasks between transfers; service routine handles each byte. Vectored interrupt lets the device supply its own ISR address.
  • DMA: DMA controller transfers entire block without per-byte CPU involvement; one interrupt at completion; essential for disk and network I/O.
