Cache Memory

⏱ 22 min read 📝 Quiz inside

Cache memory is a small, fast memory placed between the CPU and main memory to reduce the average memory access time. Its effectiveness rests on a fundamental property of programs: locality of reference.

In simple terms: a cache keeps copies of recently used words in a small, fast memory next to the CPU. Because programs reuse the same instructions and data again and again, most requests are found in the cache.

Locality of Reference

Analysis of typical programs shows that memory accesses over any short interval are confined to a small, localised region. This happens because:

  • Instruction loops — the same set of instructions is fetched repeatedly.
  • Subroutine calls — a subroutine's instructions are localised at one address range.
  • Array and table accesses — data is accessed in contiguous or nearby locations.

Because the active region fits in a small cache, the CPU finds most requested words already in cache — a hit. When the word is absent — a miss — it is fetched from main memory and a block of adjacent words is loaded into cache to exploit future locality.

Hit Ratio and Average Access Time

Cache performance is measured by the hit ratio h = hits / (hits + misses). The average memory access time is:

Tavg = h · Tc + (1 − h) · (Tc + Tm)

where Tc is the cache access time and Tm the main memory access time; on a miss the cache is checked first, so a miss costs Tc + Tm. With Tc = 100 ns, Tm = 1000 ns and h = 0.9: Tavg = 0.9 × 100 + 0.1 × 1100 = 200 ns — five times faster than main memory alone (1000 ns). Hit ratios of 0.9 and higher are common.

The Three Mapping Methods

The central problem of cache design is the mapping — how to determine where a given main memory block is stored in cache, and where to look for it on a CPU access. Three methods are used (example: 32K×12 main memory, 512×12 cache, 15-bit CPU address).

1. Associative Mapping

The associative cache stores both the full 15-bit main memory address and the 12-bit data word together. A lookup presents the CPU address to the associative memory, which searches all cache entries simultaneously. If a match is found (hit), the data is returned.

Associative mapping cache (all numbers in octal). Adapted from M. Morris Mano, Computer System Architecture, Fig. 12-11.

  • Advantage: any main memory block can go to any cache location — no conflict misses.
  • Disadvantage: the associative search hardware is expensive; suitable only for small caches.

2. Direct Mapping

The 15-bit address is split into a tag field (6 bits) and an index field (9 bits). The index directly selects one of 512 cache lines. The tag stored in that line is compared with the tag of the CPU address to confirm a hit.

Direct mapping cache organization. Adapted from M. Morris Mano, Computer System Architecture, Fig. 12-13.

  • Advantage: fast — no searching, only a single tag comparison.
  • Disadvantage: conflict misses — two addresses with the same index but different tags cannot coexist in cache and repeatedly evict each other.

With a block size of 8 words, the 9-bit index is split into a 6-bit block field and a 3-bit word field. An entire block of 8 words is transferred on a miss.

3. Set-Associative Mapping

A compromise: the cache is organised into sets of k locations. The index selects a set; within the set, all k tag–data pairs are searched associatively. In the book's two-way example the 9-bit index still selects one of 512 sets, and each set holds two tag–data pairs, so a cache word is 2 × (6 + 12) = 36 bits: a 512 × 36 cache that holds 1024 words of main memory.

Two-way set-associative mapping cache. Adapted from M. Morris Mano, Computer System Architecture, Fig. 12-15.

  • Advantage: k words with the same index can coexist — reduces conflict misses significantly.
  • Disadvantage: slightly more complex than direct mapping; cost between direct and fully associative.

Replacement Algorithms

When a miss occurs and the target cache line or set is full, an existing block must be evicted. Three common algorithms:

  • Random replacement — choose any block at random. Simple hardware; acceptable performance.
  • FIFO (first-in, first-out) — evict the block that has been in the set the longest. Implemented with a few extra bits per line.
  • LRU (least recently used) — evict the block that was accessed least recently. Best hit ratio in practice; requires tracking usage order per set.

Writing into Cache — Write Policies

When the CPU writes a word, there are two strategies:

  • Write-through — write to both cache and main memory simultaneously on every write. Main memory is always up to date — DMA devices always get current data. More bus traffic.
  • Write-back (copy-back) — write only to cache. The block is marked with a dirty bit. Main memory is updated only when the block is evicted. Fewer bus writes but main memory can be stale.

Cache Initialization

Each cache word has a valid bit (initially 0). On power-up, all valid bits are cleared, so every first access is a miss and forces a block load from main memory. Once a block is loaded, its valid bit is set to 1. This ensures the cache never accidentally supplies data from a previous power-on session.

Summary

  • Locality of reference makes cache effective: programs reuse a small memory region repeatedly.
  • Hit ratio h = hits/(hits+misses); Tavg = h·Tc + (1−h)(Tc + Tm).
  • Associative mapping: full address stored; any block → any line; fastest lookup, most expensive.
  • Direct mapping: index selects line; one tag comparison; fastest but conflict misses.
  • Set-associative (k-way): index selects set; associative search within k entries; compromise.
  • Replacement: random, FIFO, or LRU (best hit ratio).
  • Write-through: always consistent with main memory. Write-back: fewer writes, dirty bit needed.
  • Valid bit: cleared on power-up; set when a block is loaded.
