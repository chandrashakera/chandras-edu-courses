Number Conversions — Solved Problems

⏱ 20 min read 📌 Supplementary — beyond the syllabus
In simple terms: to change bases, go through decimal (divide for the integer part, multiply for the fraction) — or, between binary, base 4, octal and hex, just regroup the bits.

These problems use the methods from Data Types and Number Systems and Complements. Each answer ends with a check.

1. Base Conversions

Problem 1 — (258.75)₁₀ to Binary, Octal and Hexadecimal

Integer 258:  258 → 129 r0 → 64 r1 → 32 r0 → 16 r0 → 8 r0 → 4 r0 → 2 r0 → 1 r0 → 0 r1
              read upward: 100000010
Fraction .75: .75×2 = 1.5 → 1;  .5×2 = 1.0 → 1   → .11
(258.75)₁₀ = (100000010.11)₂
Octal (3-bit groups from the point):  100 000 010 . 110  → (402.6)₈
Hex   (4-bit groups from the point):  0001 0000 0010 . 1100 → (102.C)₁₆
Check: 256 + 2 + 0.5 + 0.25 = 258.75 ✓

Problem 2 — (9BCD)₁₆ to Octal (via Binary)

9 B C D → 1001 1011 1100 1101
Regroup in 3s from the right: 001 001 101 111 001 101 → 1 1 5 7 1 5
(9BCD)₁₆ = (115715)₈        Check: both equal (39885)₁₀ ✓

Problem 3 — (7654)₈ to Decimal and Hexadecimal

Decimal: 7×512 + 6×64 + 5×8 + 4 = 3584 + 384 + 40 + 4 = (4012)₁₀
Hex: 111 110 101 100 → 1111 1010 1100 → (FAC)₁₆
Check: 15×256 + 10×16 + 12 = 4012 ✓

Problem 4 — (343)₅ to Base 6 (Base r → Base s Through Decimal)

(343)₅ = 3×25 + 4×5 + 3 = (98)₁₀
98 ÷ 6 = 16 r 2;  16 ÷ 6 = 2 r 4;  2 ÷ 6 = 0 r 2   → read upward: 242
(343)₅ = (242)₆            Check: 2×36 + 4×6 + 2 = 98 ✓

Problem 5 — (11001101.0101)₂ to Base 4, Octal and Hexadecimal

Base 4 (2-bit groups):  11 00 11 01 . 01 01         → (3031.11)₄
Octal  (3-bit groups):  011 001 101 . 010 100       → (315.24)₈
Hex    (4-bit groups):  1100 1101 . 0101            → (CD.5)₁₆
All equal (205.3125)₁₀ ✓   Pad with 0s on the outside: left of the integer part, right of the fraction.

Problem 6 — (3A.C)₁₆ to Decimal

3×16 + 10×1 + 12×(1/16) = 48 + 10 + 0.75 = (58.75)₁₀

Problem 7 — (0.1)₁₀ to Binary (a Fraction that Never Ends)

0.1→0.2 (0)  0.2→0.4 (0)  0.4→0.8 (0)  0.8→1.6 (1)  0.6→1.2 (1)
0.2→0.4 (0)  0.4→0.8 (0)  0.8→1.6 (1)  0.6→1.2 (1)  …  the pattern 0011 repeats
(0.1)₁₀ = (0.000110011…)₂  — stop at the required number of bits, e.g. 10 bits: 0.0001100110
This is why 0.1 cannot be stored exactly in binary floating point.

3. Subtraction with Complements

Problem 10 — 8456 − 3272 and 3272 − 8456 (10’s Complement, 4 Digits)

8456 − 3272:  8456 + 6728 (10's comp of 3272) = 1 5184
              end carry → discard → answer +5184
3272 − 8456:  3272 + 1544 (10's comp of 8456) =   4816
              no end carry → negative: −(10's comp of 4816) = −5184

Problem 11 — X − Y and Y − X with X = 1101010, Y = 0110111 (2’s Complement)

X − Y:  1101010 + 1001001 = 1 0110011  → discard carry → +0110011 (= 51)
Y − X:  0110111 + 0010110 =   1001101  → no carry → −(2's comp) = −0110011 (= −51)
Check: 106 − 55 = 51 ✓

Problem 12 — the Same X − Y and Y − X with 1’s Complement

X − Y:  1101010 + 1001000 = 1 0110010  → end-around carry: 0110010 + 1 = +0110011
Y − X:  0110111 + 0010101 =   1001100  → no carry → −(1's comp) = −0110011

Common Pitfalls

  • Reading remainders the wrong way — integer digits read bottom-up; fraction digits read top-down.
  • Grouping from the wrong end — group outward from the binary point, padding with 0s on the outside.
  • Keeping the end carry in r's-complement subtraction — discard it; in (r−1)'s complement add it back (end-around carry).
  • Missing overflow — a wrong-sign result from two same-sign operands is overflow, not a valid answer.
