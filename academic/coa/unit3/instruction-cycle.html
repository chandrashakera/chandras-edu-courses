Instruction Cycle

⏱ 20 min read 📝 Quiz inside 📖 Mano, Ch. 5

Every register, instruction, and timing signal from this unit exists to run one repeating loop: fetch an instruction, decode it, and execute it — then do it again for the next one. This topic is where all of it finally runs together.

Fetch and Decode — T0, T1, T2

These three timing states are identical for every instruction, no matter what it turns out to be:

T0:  AR ← PC
T1:  IR ← M[AR],  PC ← PC + 1
T2:  D0,…,D7 ← Decode IR(14-12),  AR ← IR(11-0),  I ← IR(15)

T0 points AR at the next instruction. T1 reads it into IR and immediately advances PC — so PC is already pointing past the current instruction before execution even begins. T2 does three things at once: the opcode decoder (Timing and Control) produces D0-D7, the low 12 bits are copied into AR as a tentative address, and I captures the indirect-addressing bit.

The Full Cycle

The single decision point standing in for two real ones: among memory-reference opcodes, I selects direct execution versus one extra state (T3: AR ← M[AR]) to resolve an indirect address first; among opcode-111 instructions, I selects the register-reference decoder versus the I/O decoder (both covered in Computer Instructions). Either way, the cycle always ends the same way — SC ← 0 — and control loops straight back to T0.

Common Pitfalls

  • Thinking PC advances during execute. PC is incremented once, during fetch (T1) — by the time execution starts, PC already points at the next instruction, which is exactly what makes BUN/BSA "jumps" meaningful (they overwrite that already-advanced value).
  • Treating "decode" as a separate hardware step from timing. Decode isn't a different mechanism — it's just T2 driving the same D0-D7 opcode decoder from Timing and Control at a specific timing state.
  • Assuming indirect addressing adds many extra cycles. It costs exactly one extra state (AR ← M[AR]) before execution proceeds — a single indirection level, not a loop.

Applications

  • Fetch-decode-execute is the von Neumann cycle — every general-purpose CPU built since, no matter how deep its pipeline, is still running this same three-phase loop underneath.
  • Real CPUs overlap these phases across instructions (pipelining) instead of running them strictly one after another — fetching instruction N+1 while instruction N is still executing. This flowchart is the sequential baseline that pipelining optimizes.
