Arithmetic Micro-operations

⏱ 18 min read 📝 Quiz inside

A micro-operation is the smallest unit of work a CPU performs in one clock cycle on data held in registers — one register transfer, possibly combined with a simple operation along the way. Arithmetic micro-operations are the first of three families this unit covers (logic and shift are next); together, all three are exactly what an ALU is built from.

In simple terms: one parallel adder does all the arithmetic micro-operations — add, subtract, increment, decrement — by changing what is fed into its second input and its carry.

The Basic Arithmetic Micro-operations

OperationRTL Statement
AdditionR3 ← R1 + R2
SubtractionR3 ← R1 − R2  (implemented as R3 ← R1 + R2′ + 1)
IncrementR1 ← R1 + 1
DecrementR1 ← R1 − 1

Subtraction is written as addition of the 2's complement — R2′ (bitwise complement) plus a carry-in of 1 — because that's exactly what turns a plain binary adder into a subtractor with almost no extra hardware, as Unit 2's Binary Adder & Subtractor topic derived in full.

One Circuit, Four Operations

All four operations above run on a single n-bit adder-subtractor: a chain of full adders (Unit 2) with a mode control M that XORs into the B input and feeds the first carry-in:

n-bit adder-subtractor: mode input M selects addition (M=0) or subtraction (M=1) via XOR gates and carry-in. Adapted from M. Morris Mano, Computer System Architecture, Fig. 4-7.

M=0: S = A + B (add). M=1: S = A + B′ + 1 (subtract).

Increment and decrement reuse the very same idea at smaller scale — increment is just an add where one operand is hardwired to all-0 with a carry-in forced to 1 (equivalent to a chain of half-adders fed a constant 1), rather than needing a second full n-bit operand register at all.

4-bit binary incrementer. Adapted from M. Morris Mano, Computer System Architecture, Fig. 4-8.

Arithmetic Circuit

All the arithmetic micro-operations can be produced by one circuit: a parallel adder whose Y inputs come from 4 × 1 multiplexers. The select inputs S1S0 choose B, B̅, all 0s or all 1s for Y, and the input carry Cin adds 0 or 1, giving D = A + Y + Cin.

4-bit arithmetic circuit. Adapted from M. Morris Mano, Computer System Architecture, Fig. 4-9.

010B̅D = A + B̅Subtract with borrow

Overflow Detection

When adding two signed numbers, the result can land outside the representable range even though the addition circuit itself "succeeds" — that's overflow. The detection rule needs no extra logic beyond what the adder already computes: compare the carry into the sign bit against the carry out of the sign bit.

V = Cn ⊕ Cn−1

where Cn is the final carry-out and Cn−1 is the carry into the most significant (sign) bit position. If the two disagree, the sign bit was corrupted by a carry it shouldn't have absorbed — overflow.

Example (4-bit signed, range -8 to +7): 0101 (+5) + 0100 (+4) ------ 1001 ← result reads as -7 in 2's complement, but 5+4=9 is not representable C₄ (carry out of bit 3) = 0 C₃ (carry into bit 3) = 1 V = C₄ ⊕ C₃ = 0 ⊕ 1 = 1 → overflow correctly flagged

Common Pitfalls

  • Confusing overflow with an ordinary carry-out. Carry-out (Cn) matters for unsigned arithmetic; overflow (V) matters for signed arithmetic — they're different flags answering different questions, and a given addition can set one without the other.
  • Forgetting decrement needs its own carry chain, not just "increment with M flipped." R1−1 = R1 + (all-1s), which needs a carry-in of 0 through an adder whose B input is the current register value complemented appropriately — it's a related but distinct configuration from the increment case.
  • Assuming subtraction needs a genuinely separate circuit from addition. As covered in Unit 2, the entire point of 2's complement is that R1−R2 = R1+R2′+1 — one adder, one XOR layer, one control bit M, covers both operations.

Applications

  • Every ALU add/sub instruction in a real instruction set architecture routes through exactly this one adder-subtractor circuit, selected by a single mode bit derived from the opcode.
  • The Program Counter is incremented by exactly this increment micro-operation on every instruction fetch (PC ← PC + 1), almost always via the simpler half-adder-chain implementation rather than a full adder.
  • Overflow detection feeds directly into a CPU's status/flags register, which conditional branch instructions (later units) read to implement signed comparisons correctly.
