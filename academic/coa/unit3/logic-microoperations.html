Logic Micro-operations

⏱ 16 min read 📝 Quiz inside 📖 Mano, Ch. 4

Where an arithmetic micro-operation treats a register as one big number (with carries rippling between bit positions), a logic micro-operation treats it as a plain array of independent bits — each bit position is computed with no interaction with its neighbors at all. That independence is exactly what makes logic micro-operations useful for something arithmetic can't do cleanly: manipulating individual bits of a register on purpose.

The Four Basic Logic Micro-operations

OperationRTL StatementPer-bit rule
ANDA ← A ∧ B1 only where both bits are 1
ORA ← A ∨ B1 where either bit is 1
XORA ← A ⊕ B1 where the bits differ
ComplementA ← A′every bit flipped

Selective Bit Manipulation with a Mask

Treat a second register B as a mask — a 1 in some bit position of B marks "touch this bit of A," a 0 means "leave it alone." Which logic operation you pick determines what happens to the marked bits:

NameRTLEffect on marked bits (where B=1)
Selective-setA ← A ∨ BForced to 1
Selective-complementA ← A ⊕ BFlipped
Selective-clearA ← A ∧ B′Forced to 0
Mask (AND)A ← A ∧ BKept as-is; unmarked bits (B=0) are forced to 0 instead

Worked example — A = 1010 1100, B = 0000 1111 used as the mask:

b7b6b5b4b3b2b1b0
A10101100
B (mask)00001111
Selective-set (A∨B)10101111
Sel.-complement (A⊕B)10100011
Selective-clear (A∧B′)10100000
Mask (A∧B)00001100

Only the four bits marked by B=1 (positions b3–b0, highlighted) are ever affected by selective-set/complement/clear — the unmarked bits (b7–b4) pass straight through unchanged in all three. Mask is the odd one out: it keeps A's marked bits but actively zeroes the unmarked ones, rather than leaving them alone.

Insert — Mask, Then Set

Combine two logic micro-operations to overwrite just one field of a register with a new value — first clear the target field to 0 (AND with a mask that's 0 exactly there), then OR in the new field value (which is 0 everywhere outside the field, so it can't disturb anything else):

A ← A ∧ 1111 0000   (clear the low nibble)
A ← A ∨ 0000 1010   (insert new value 1010 into it)

A Free Clear-to-Zero

XOR-ing any register with itself always produces all zeros, regardless of its content — A ← A ⊕ A is a clear operation that needs no separate constant-0 source wired in.

Common Pitfalls

  • Mixing up AND-as-mask with AND-as-selective-clear. They use the exact same gate (AND) but opposite mask conventions — mask keeps bits where B=1, selective-clear clears bits where B=1 (using B′, the complemented mask). Reading the RTL statement's exact operand (B vs. B′) is what tells them apart.
  • Assuming logic micro-operations can carry information between bit positions. They fundamentally cannot — that's the whole distinction from arithmetic micro-operations. Any circuit that needs carry propagation is, by definition, not a plain logic micro-operation anymore.
  • Forgetting insert is two micro-operations, not one. The mask-then-OR sequence needs the register to hold the intermediate (cleared) result between the two steps — it isn't a single atomic RTL statement.

Applications

  • Status/flag registers are read and written almost entirely with selective operations — setting one interrupt-enable bit without disturbing the others is a textbook selective-set.
  • Instruction field extraction (pulling the opcode or register-number bits out of a wider instruction word) is exactly the Mask operation, isolating one field with an AND.
  • Graphics and bitmap manipulation (setting a pixel's color bits within a packed word, XOR-based sprite drawing) are direct, large-scale descendants of these same bit-level tricks.
