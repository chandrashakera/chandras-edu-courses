Timing and Control

⏱ 18 min read 📝 Quiz inside

Registers hold data; instructions say what to do with it — but something still has to decide when, on which clock pulse, each register actually latches new data. That's the control unit's job. The Basic Computer uses a hardwired control unit: fixed logic gates, not a program, generate every control signal. (Unit 4's Microprogrammed Control topic covers the alternative — a ROM-based control unit — as a direct contrast to this one.)

In simple terms: the sequence counter ticks T0, T1, T2…; the decoded opcode says which instruction it is. Every control signal is 'this instruction AND this tick'.

Generating Timing Signals

SC, the 4-bit Sequence Counter introduced in Computer Registers, feeds a decoder that turns its binary count into one active line per timing state: T0, T1, T2, and onward. Every clock pulse increments SC, so the active timing signal advances by exactly one each cycle — T0, then T1, then T2, and so on — until control logic explicitly clears SC back to 0 to start the next instruction's fetch.

Control unit of basic computer. Adapted from M. Morris Mano, Computer System Architecture, Fig. 5-6.

The figure shows the whole control unit: the 3 × 8 decoder turns the opcode into D0–D7, the 4 × 16 decoder turns the sequence counter into T0–T15, and the control logic gates combine them with I and IR bits 0–11.

Most instructions never reach T6 — a simple register-reference instruction can finish by T3, while a memory-reference instruction with indirect addressing needs a couple states more. SC only counts as far as whatever the current instruction actually requires.

Forming a Control Statement

A timing signal on its own doesn't do anything useful — it only becomes a specific action once it's ANDed with an opcode-decoder output (from a 3-to-8 decoder reading IR bits 14-12, producing D0 through D7) and, when needed, a flip-flop condition. This is the entire "hardwired" idea in one picture:

Example of control timing signals. Adapted from M. Morris Mano, Computer System Architecture, Fig. 5-7.

Each control signal is the AND of a decoder output and a timing signal. LDA (D2), for example, takes two steps: D2T4: DR ← M[AR] and D2T5: AC ← DR, SC ← 0. The timing diagram shows another case: D3 (STA) is active after T2, and at T4 the control function D3T4 also clears SC, so the next instruction starts again at T0 instead of going on to T5.

Common Pitfalls

  • Confusing SC with PC again. SC only ever counts timing states within a single instruction (0 up to about 6); PC counts through the whole program's instructions. They reset on completely different events.
  • Assuming every instruction uses every timing state. T0-T2 are shared fetch/decode states common to all instructions; how many states beyond T2 an instruction needs depends entirely on what it does.
  • Forgetting the explicit SC ← 0. Without control logic clearing SC at the end of an instruction, the counter would just keep incrementing forever instead of restarting the fetch cycle.

Applications

  • This counter-plus-decoder-plus-AND-gate pattern is literally what "hardwired control" means in every textbook — a fixed circuit, not stored instructions, generates every control signal.
  • The next topic, Instruction Cycle, uses exactly this timing mechanism to walk through fetch, decode, and execute state by state for the whole instruction set.
  • Unit 4's Microprogrammed Control replaces this entire gate network with a small ROM ("control memory") that's read instead of wired — same job, a fundamentally different implementation strategy.
