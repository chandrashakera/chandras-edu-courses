Computer Instructions

⏱ 20 min read 📝 Quiz inside 📖 Mano, Ch. 5

Instruction Codes introduced the 16-bit format — I | Opcode(3) | Address(12) — and left one detail open: opcode 111 is reserved. This topic fills in every instruction the Basic Computer actually understands: 25 in total, split across three families.

How Opcode 111 Splits in Two

Opcodes 000–110 are ordinary memory-reference instructions — the address field points at an operand. Opcode 111 means "this instruction needs no memory address," so the address field is repurposed: instead of one 12-bit number, its 12 bits are each treated as an individual one-hot flag. The I bit (bit 15) picks which of two decoders reads them.

One bit position, one instruction — the control unit just needs to test opcode=111 AND I' AND bit-N to know exactly which register-reference instruction is executing, no arithmetic decoding required.

Common Pitfalls

  • Treating opcode 111's address field as a number. It isn't — those 12 bits are individually one-hot. A word like 7014 would be malformed (two bits set) rather than "instruction number 0x14."
  • Mixing up the four skip instructions. SPA/SNA/SZA all test AC (positive / negative / zero respectively); SZE tests E instead — four different conditions, easy to conflate at a glance.
  • Thinking BUN and BSA are interchangeable. BUN is a plain jump; BSA additionally stores the return address before jumping, making it the machine's only built-in subroutine-call mechanism (Instruction Cycle's memory-reference topic works through its RTL in full).

Applications

  • This table is a machine-code reference card — exactly the kind of opcode listing every real ISA manual (x86, ARM, RISC-V) publishes, just at a scale small enough to memorize in full.
  • The one-hot decode trick for register-reference/I/O instructions is a genuine hardware cost-saving: testing one AND gate per instruction is cheaper to build than a full binary decoder, at the price of "wasting" opcode space (only 1 of 4096 possible address patterns is ever legal per instruction).
  • BSA's save-then-jump behavior is the direct conceptual ancestor of a modern CALL instruction — the next unit-worth of ideas (stacks, return addresses, nested calls) all start from this one primitive.
