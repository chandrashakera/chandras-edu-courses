Memory Reference Instructions

⏱ 22 min read 📝 Quiz inside

Instruction Cycle's flowchart compressed all seven memory-reference instructions into one box: "Execute, T3 onward." This topic expands that box — the exact RTL, state by state, for AND, ADD, LDA, STA, BUN, BSA, and ISZ.

In simple terms: each memory instruction is a few register transfers, one per clock tick, starting at T4; most read the memory word into DR first and then use it.

Where Execution Starts

Every memory-reference instruction's execution begins at T4, never T3 — T3 is reserved exclusively for resolving an indirect address:

D7′ I T3:   AR ← M[AR]        (only when I = 1; skipped entirely when I = 0)

By T4, AR is guaranteed to hold the operand's real address either way, so every instruction's execute RTL can simply assume "AR already points at the right place."

The Full RTL

AND (D0):
  D0T4:  DR ← M[AR]
  D0T5:  AC ← AC ∧ DR,  SC ← 0

ADD (D1):
  D1T4:  DR ← M[AR]
  D1T5:  AC ← AC + DR,  E ← Cout,  SC ← 0

LDA (D2):
  D2T4:  DR ← M[AR]
  D2T5:  AC ← DR,  SC ← 0

STA (D3):
  D3T4:  M[AR] ← AC,  SC ← 0

BUN (D4):
  D4T4:  PC ← AR,  SC ← 0

BSA (D5):
  D5T4:  M[AR] ← PC,  AR ← AR + 1
  D5T5:  PC ← AR,  SC ← 0

ISZ (D6):
  D6T4:  DR ← M[AR]
  D6T5:  DR ← DR + 1
  D6T6:  M[AR] ← DR,  if (DR = 0) then (PC ← PC + 1),  SC ← 0

Flowchart for memory-reference instructions. Adapted from M. Morris Mano, Computer System Architecture, Fig. 5-11.

Why DR Shows Up So Often

AND, ADD, LDA, and ISZ all read memory into DR first instead of operating on M[AR] directly. This isn't extra caution — it's a hard constraint from Bus & Memory Transfers: the common bus carries one value per clock pulse, so a memory word has to land in a register before it can be combined with AC on the next pulse. DR exists specifically to be that landing spot.

Two Instructions Worth Slowing Down On

InstructionWhat's actually happening
BSAStores the return address (PC, already pointing past this instruction) at the target location, then bumps AR by one and jumps there — so the subroutine's code starts right after its own stored return address, and a final indirect BUN through that same location gets you back.
ISZIncrements the memory word first, then tests whether that new, incremented value is zero — not whether the original value was zero. It's a built-in decrement-and-test loop-counter pattern (counting up to zero rather than down).

In the example, BSA at address 20 stores the return address 21 in location 135 and jumps to 136; the subroutine returns with an indirect BUN 135.

Common Pitfalls

  • Assuming execution starts at T3. T3 only ever does the indirect fetch (or nothing, if direct) — every instruction's real work begins at T4.
  • Trying to skip DR and write AC ← AC + M[AR] directly. The hardware has no path for that — memory data must land in DR before it can combine with AC.
  • Reading BSA's AR ← AR + 1 as "increment the return address." It's incrementing AR so the following jump lands one word past the just-stored return address — not modifying the return address itself.

Applications

  • DR's staging role is the same underlying idea behind "load-use" constraints in modern pipelined CPUs — a value read from memory generally can't be used in the very next cycle without first landing somewhere.
  • BSA is a direct, minimal ancestor of CALL in every modern ISA — save a return address, then jump; real machines just use a stack instead of a single fixed memory slot.
  • ISZ's increment-and-skip pattern is the classic loop-counter primitive — count toward zero, and let the hardware itself decide when to fall through, no separate compare instruction required.
