Register Transfer

⏱ 16 min read 📝 Quiz inside 📖 Mano, Ch. 4

The last topic wrote T: R2 ← R1 as a piece of notation. This topic builds the actual hardware that statement describes — and along the way, a real design hazard worth knowing before it costs you a working circuit.

What the Hardware Needs

Two things make a controlled transfer happen only when intended: R1's output lines wired straight into R2's input lines (always present, always available), and a load-enable input on R2 that only lets those lines actually get written on a clock edge when the control condition T is true.

Both registers share the same clock — that's what keeps every transfer in the system synchronized to the same instants. Only R2 has its load driven by T: R1 keeps its own content regardless of T, exactly matching the RTL statement's promise that the source is left unchanged.

Why Not Just Gate the Clock?

A tempting shortcut: skip the load-enable pin entirely, and just AND the control signal T with the clock before it reaches R2 — "if T is 0, R2 simply doesn't see a clock edge at all." This is a genuine, well-known hazard called clock gating: T is an arbitrary signal from other logic, not synchronized to the clock's own transitions, so the ANDed clock can develop a glitch — a runt pulse, or an edge at the wrong moment — any time T changes close to a real clock edge. The load-enable approach avoids this entirely: the clock signal itself stays completely untouched and glitch-free everywhere in the circuit; T only ever affects whether the flip-flop's internal logic acts on the clock edge, never the edge itself.

Timing

T must already be stable before the triggering clock edge arrives (this is exactly the flip-flop setup time from Unit 2) — assert T, wait for the next clock edge, and the transfer happens at that single instant:

T rises well before the clock edge and is still high when it arrives — so this edge is a valid load. Notice R2's new content is only visible after that edge, and stays stable through the next clock period whether or not T is still high — exactly the stable, once-per-cycle update behavior a flip-flop-based register guarantees.

Common Pitfalls

  • Gating the clock line with a control signal instead of using a load-enable input. As covered above, this risks glitches and unpredictable edges — always drive a register's dedicated enable/load pin, never the raw clock net.
  • Forgetting both registers still need the same clock even when only one is being loaded. R1's flip-flops are still clocked every cycle — they just aren't told to change their D input, so they simply re-latch their own existing value. The clock net is universal; the load/enable signal is what's selective.
  • Assuming T only needs to be high exactly at the clock edge. Just like any flip-flop input, T must satisfy setup time — stable for some minimum window before the edge — or the transfer's outcome is undefined, same as feeding an unstable D input.

Applications

  • Every register load in a CPU's datapath — writing back to a general-purpose register, latching a memory read into a data register — uses exactly this load-enable pattern, driven by a control signal from the control unit (Unit 3's later topics).
  • Pipeline stage registers in a pipelined CPU are controlled transfers gated by a "stall" or "valid" signal, so a stalled pipeline stage simply doesn't load new data that cycle.
  • Clock gating for power savings is still used in real chips, but only with dedicated, carefully-timed clock-gating cells (integrated clock gates, ICGs) specifically engineered to avoid the glitch hazard described above — not a plain AND gate wired ad hoc.
