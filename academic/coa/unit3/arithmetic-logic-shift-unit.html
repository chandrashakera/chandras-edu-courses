Arithmetic Logic Shift Unit

⏱ 20 min read 📝 Quiz inside 📖 Mano, Ch. 4

This unit built three separate families of micro-operation — arithmetic, logic, and shift — each with its own dedicated circuit. A real CPU doesn't wire three separate circuits into the datapath and pick which one's wires to trust; it builds one combined block, the Arithmetic Logic Shift Unit (ALU), that can perform any of them, chosen by a function-select code.

The Structure

At the block level, an ALU is exactly what its name says: an arithmetic circuit, a logic circuit, and a shifter, all fed the same operand(s), with a final selector choosing which one's result actually reaches the output:

All three circuits are always computing something, every cycle, in parallel — the select code S₂S₁S₀ simply decides which of the candidate results is actually allowed through to F. This is the same core idea behind every MUX-based selection this course has used, applied one level up: instead of selecting a bit, this selects an entire n-bit computed result.

Function Table

With a 3-bit select code, one ALU can offer up to 8 operations — a representative set covering everything from the last three topics:

S₂S₁S₀OperationF
000AddF = A + B
001SubtractF = A + B′ + 1
010ANDF = A ∧ B
011ORF = A ∨ B
100XORF = A ⊕ B
101ComplementF = A′
110Shift rightF = shr A
111Shift leftF = shl A

Every row here is a micro-operation from one of the last three topics — the ALU hasn't introduced any new operation, it's only added the selection logic that makes all of them available from one shared piece of hardware.

🚀 Beyond the textbook: real ALU implementations go further than three fully-separate parallel circuits — a classic design trick shares the arithmetic circuit's adder cells with the logic circuit, by feeding a small MUX-selected combination of B and B′ into the adder's B input instead of B directly, and disabling carry propagation for the "logic" select codes. The visible behavior (the function table above) is identical either way; only the internal gate count changes. The block-level view here is exactly what to reason about first — the shared-adder trick is an optimization on top of it, not a different design.

Common Pitfalls

  • Thinking the ALU "chooses" which circuit computes, saving power by only running one. In the simplest (and most common introductory) design, every candidate circuit computes its result every cycle regardless of the select code — only the final MUX is selective. This costs some power but keeps the design simple and fast (no need to wait for a circuit to "start up" after being selected).
  • Forgetting the select code needs enough bits for every operation you want available. 3 bits cover 8 operations; adding a 9th operation (e.g., a second shift variant) needs a 4th select bit, not a workaround within the existing 3.
  • Treating the ALU as fundamentally different from the micro-operations already covered. It isn't a new kind of circuit — it's a MUX wrapped around exactly the arithmetic, logic, and shift circuits already built in this unit.

Applications

  • Every general-purpose CPU's execute stage centers on an ALU built this way — the specific opcode of an ADD, SUB, AND, OR, or shift instruction is decoded (later units) directly into this select code.
  • The 74181 is a classic, historically significant 4-bit ALU IC built exactly on this arithmetic/logic/select structure, used in real minicomputers before ALUs were integrated onto the same chip as the rest of the CPU.
