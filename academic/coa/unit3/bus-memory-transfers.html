Bus & Memory Transfers

⏱ 20 min read 📝 Quiz inside 📖 Mano, Ch. 4

The Wiring Problem

Connect every register in a system directly to every other register, and the wiring grows as roughly n² for n registers — for even a modest register file, that's an unmanageable number of dedicated point-to-point lines. The standard fix: give every register access to one shared set of lines, the common bus, and let only one register drive it at a time.

A Common Bus via Multiplexers

One clean way to build the bus: for each bit position, put a multiplexer whose inputs are that bit from every register, and whose select lines choose which register's bit reaches the bus. With 4 registers, that's a 4-to-1 MUX per bit, all sharing the same 2-bit select code:

One MUX handles one bit; an n-bit bus needs n identical MUXes, all driven by the same S₁S₀ select code — so a single 2-bit code chooses one of the four registers for the entire word at once. To move C into R1 over this bus: set S₁S₀ to select C (routing C's content onto BUS — purely combinational, no clock involved), then load R1 from the bus:

S₁S₀ = 10 (select C):   BUS ← C,   R1 ← BUS

Both halves happen in the same clock period — the MUX routing is instantaneous (just wires and gates), and only R1's load is what actually needs a clock edge.

The Three-State Alternative

Real bus systems more often use three-state buffers instead of a MUX per bit: each register's output feeds the bus through a buffer that's either driving (0 or 1) or electrically disconnected (high-impedance, "Z") — enable exactly one register's buffers at a time, and the others simply don't interfere, no MUX gate tree required. This is why so many real datasheets describe a bus pin's output as "TRI-STATE" — it's the same idea.

Memory Transfers

A memory unit needs an address register (AR) to select a word, a data register (DR) to hold the value being read or written, and Read/Write control lines:

Two RTL statements cover everything a memory unit does:

Read:   DR ← M[AR]
Write:   M[AR] ← DR

M[AR] means "the memory word addressed by whatever value is currently in AR" — the brackets are doing the same job here that a register name does everywhere else in RTL, just naming a location that depends on AR's content instead of a fixed physical register.

Common Pitfalls

  • Forgetting the bus is purely combinational. Selecting a register onto the bus doesn't need — and doesn't get — a clock edge; only the destination register's load is clocked. The bus itself has no memory of its own.
  • Trying to drive two registers onto the same bus at once. Whether using a MUX (which only has one select code active at a time by construction) or three-state buffers (where enabling two simultaneously creates a genuine electrical bus contention), only one source may drive the bus in a given cycle.
  • Confusing M[AR] with AR itself. AR holds an address; M[AR] refers to the (much larger) memory word stored at that address — two entirely different pieces of data with entirely different sizes.

Applications

  • A CPU's internal register bus — moving values between the register file, ALU, and memory interface — is built from exactly this MUX-or-tristate shared-bus pattern.
  • External system buses (memory bus, PCIe, the classic ISA/PCI buses) are three-state-buffer-based for the same reason: many devices need to share one physical set of wires without every device needing a dedicated point-to-point connection to every other device.
  • The Read/Write/Address/Data structure here is the direct ancestor of every memory interface signal a datasheet or CPU pinout will ever show — the names change, the four-signal shape doesn't.
