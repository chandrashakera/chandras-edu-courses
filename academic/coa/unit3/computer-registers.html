Computer Registers

⏱ 18 min read 📝 Quiz inside

Every idea from the first half of this unit — registers, a shared bus, memory read/write — comes together here as one concrete machine. The Basic Computer has eight named registers plus a handful of single-bit control flip-flops, all connected through one 16-bit common bus (Unit 3's Bus & Memory Transfers topic, applied directly).

In simple terms: the Basic Computer has a handful of registers and one memory, all sharing a single 16-bit bus. Three select lines choose who talks on the bus; a load signal chooses who listens.

The Register Set

RegisterBitsFunction
DR16Data Register — holds the memory operand currently being worked with
AR12Address Register — holds the memory address for the current access
AC16Accumulator — the general-purpose register almost every operation reads or writes
IR16Instruction Register — holds the instruction currently being executed
PC12Program Counter — holds the address of the next instruction to fetch
TR16Temporary Register — holds intermediate values during multi-step execution
INPR8Input Register — buffers one character from an input device
OUTR8Output Register — buffers one character bound for an output device
SC4Sequence Counter — not programmer-visible; sequences the control unit through each instruction's timing states

Control Flip-Flops

Flip-FlopMeaning
IHolds the current instruction's indirect-addressing bit
SStart/stop control — clears to halt the machine's clock
EExtended AC bit — captures carry-out during addition and the extra bit during a circular shift
RInterrupt flip-flop — set when an interrupt is pending and about to be serviced
IENInterrupt Enable — master switch for whether interrupts are allowed at all
FGIInput flag — set when an input device has a new character ready in INPR
FGOOutput flag — set when the output device is ready to accept a new character in OUTR

Connected by One Common Bus

Basic computer registers connected to a common bus. Adapted from M. Morris Mano, Computer System Architecture, Fig. 5-4.

The bus is selected by S2S1S0: the number at each register output (1 = AR, 2 = PC, 3 = DR, 4 = AC, 5 = IR, 6 = TR, 7 = memory) is the select code that places it on the bus. AR alone supplies the memory address, so every memory access goes through AR. AC is not loaded from the bus: it receives the output of the adder and logic circuit, whose inputs come from AC, DR and INPR, with the carry going to E. Registers with LD, INR and CLR inputs can be loaded, incremented and cleared; IR and OUTR can only be loaded. INPR and OUTR hold 8 bits and use the eight least significant bit positions: INPR feeds the adder and logic circuit, and OUTR is loaded from the bus.

Common Pitfalls

  • Confusing AR with PC. Both are 12-bit address-sized registers, but PC always holds the address of the next instruction, while AR holds whatever address the current micro-operation needs — they usually hold different values at any given moment.
  • Treating SC as programmer-visible. No instruction ever reads or writes SC directly — it's purely internal control-unit bookkeeping, covered in the next topic, Timing and Control.
  • Mixing up E with a general status/overflow flag register. E is a single specific flip-flop with two very specific jobs in this design (capturing add's carry-out, and acting as the 17th bit during a circular shift) — it isn't a general-purpose condition-code register the way a modern CPU's flags register is.

Applications

  • Every register named here reappears by name throughout the rest of this unit's RTL statements — Instruction Cycle, Memory Reference Instructions, and Input-Output & Interrupt all assume exactly this register set.
  • Real CPUs scale this same idea up — a modern register file has dozens of general-purpose registers instead of one AC, but still keeps dedicated special-purpose registers (an instruction pointer/PC, a memory address/data interface) playing the same roles as AR, PC, IR, and DR here.
  • The E (extend) bit's role is the direct conceptual ancestor of a modern carry flag — both exist specifically to let one arithmetic circuit's 1-bit overflow become usable data for the next operation.
