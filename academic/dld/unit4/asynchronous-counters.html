Asynchronous (Ripple) Counters

⏱ 18 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 5

What Makes a Counter "Asynchronous"?

A counter is just a sequential circuit that cycles through a fixed sequence of binary states on every clock pulse. In an asynchronous (or ripple) counter, only the first flip-flop receives the external clock directly — every later stage is clocked by the output of the stage before it. The new count doesn't appear all at once; it "ripples" through the chain one stage at a time, each stage only updating after the one before it has already toggled.

3-Bit Asynchronous Up-Counter

FF0 is the LSB and toggles on every external clock pulse; FF1 toggles only when Q₀ falls, and FF2 only when Q₁ falls — each stage runs at half the frequency of the one before it, which is exactly binary counting.

000 → 001 → 010 → 011 → 100 → 101 → 110 → 111 → 000 …

Up vs. Down Counter Rules

Whether a ripple counter counts up or down depends on two independent choices: which clock edge each flip-flop triggers on, and whether the next stage is driven by Q or by Q′:

Clock TriggeringNext Stage Driven ByCounter Mode
Negative edge (↓)QUP
Negative edge (↓)Q′DOWN
Positive edge (↑)QDOWN
Positive edge (↑)Q′UP

The pattern: negative-edge-triggered + Q, or positive-edge-triggered + Q′, both count up; the other two combinations count down. Intuitively, Q′ falls exactly when Q rises, so driving the next stage from Q′ instead of Q effectively flips which transition of the original bit ripples the carry forward.

Designing a Modulo-10 (BCD) Counter

A plain 4-bit ripple counter naturally counts mod-16 (0000 through 1111). To make it a mod-10 (BCD) counter — counting only 0 through 9 — the count needs to reset back to 0000 the instant it would otherwise reach 10 (1010₂):

Required FFs: 2ⁿ ≥ 10 ⟹ n = 4 flip-flops (Q₃Q₂Q₁Q₀) Reset state: Q₃Q₂Q₁Q₀ = 1010 (Q₃=1 and Q₁=1 — the only bits that are 1 at count 10) Clear logic: CLR′ = (Q₃ · Q₁)′

As soon as the counter momentarily reaches 1010, Q₃ and Q₁ are both 1, so the NAND gate's output CLR′ drops to 0 and asynchronously clears every flip-flop back to 0000 — the count never actually settles at 1010 for a full clock cycle, it just flashes through it as a brief reset trigger:

Common Pitfalls

  • Assuming all bits change simultaneously. In a ripple counter they don't — each stage's toggle physically waits for the previous stage's output to settle, so the count briefly passes through invalid-looking intermediate states (e.g., 011→100 can transiently show 010 or 000 as the ripple propagates). This accumulated delay is the main reason synchronous counters (next topic) exist.
  • Forgetting the reset condition must use the exact bit pattern of the target count, not the count number itself. For mod-10, the reset trigger is Q₃=1,Q₁=1 (the pattern for decimal 10), not some direct encoding of "10."
  • Using the wrong Q/edge combination and getting an up-counter when a down-counter was wanted (or vice versa). Always check both the trigger edge and whether Q or Q′ feeds the next stage.

Applications

  • Frequency dividers — each successive Q in a ripple counter is exactly half the frequency of the one before it, making a ripple counter a simple divide-by-2ⁿ circuit, widely used for clock generation.
  • The 7490 is a classic decade (mod-10) ripple counter IC, built with exactly this Q₃·Q₁ reset-gate structure internally.
  • Digital clocks and frequency counters historically used cascaded mod-10 and mod-6 ripple counter stages to directly display seconds, minutes, and hours in BCD.
