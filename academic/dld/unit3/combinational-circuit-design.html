Combinational Circuit Analysis & Design Procedure

⏱ 18 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 4

A combinational circuit is any circuit whose outputs depend only on its present inputs — never on any history of past inputs, and never on a clock. n binary input signals go in, m binary output signals come out, and every output is some Boolean function of the inputs, built purely from logic gates with no feedback loop back to an earlier point in the circuit. Every circuit in this unit — adders, comparators, decoders, multiplexers — is combinational in exactly this sense; Unit 4 is where memory (and therefore output depending on the past) enters the picture.

There are two matched skills for working with any combinational circuit, and they run in opposite directions: analysis starts from a circuit diagram and recovers the Boolean function(s) it computes; design starts from a written specification and produces a minimal circuit that implements it. Every remaining topic in this unit is really just repeated application of the design procedure to a specific, standard building block.

Analysis Procedure

Given a gate-level circuit diagram, recovering its Boolean function is mechanical:

  1. Label every wire. Give a name to the output of every gate, working from the inputs toward the outputs — not just the final output(s).
  2. Write each gate's output as a Boolean expression in terms of the wires feeding it, substituting as you go until every output is expressed purely in terms of the original circuit inputs.
  3. Build a truth table (optional but recommended) by evaluating the final expression(s) for every input combination — this catches transcription errors and makes the circuit's behavior immediately checkable.

Worked Example — Analyzing a 2-Gate Circuit

Analyze the circuit below, which has three inputs A, B, C and one output F:

Step 1 — label the AND gate's output:  w1 = AB
Step 2 — the OR gate combines w1 and C directly:  F = w1 + C
Step 3 — substitute:                              F = AB + C

Evaluating F = AB + C for all 8 input combinations gives the full truth table — F is 1 whenever C is 1 (regardless of A, B), or whenever both A and B are 1.

Design Procedure

Going the other direction — from a word specification to a circuit — follows a fixed sequence:

  1. State the problem precisely and identify the number of inputs and outputs.
  2. Assign letter symbols to each input and output variable.
  3. Derive the truth table that defines the required relationship between inputs and outputs.
  4. Obtain the minimal Boolean function(s) for each output — a K-map (Unit 2) is the usual tool.
  5. Draw the logic diagram from the minimal SOP or POS expression, and verify it against the original specification.

Worked Example — 3-Input Majority Function

Design a circuit with three inputs A, B, C and one output F, where F = 1 whenever a majority (2 or more) of the inputs are 1.

Truth table → minterms: F is 1 for input combinations with two or three 1s: m3 (011), m5 (101), m6 (110), m7 (111). So F(A,B,C) = Σm(3,5,6,7).

A\BC00011110
0 0m0 0m1 1m3 0m2
1 0m4 1m5 1m7 1m6
Pair {m6,m7} → AB Pair {m5,m7} → AC Pair {m3,m7} → BC

Three valid pairs exist, and each one shares cell m7 with the other two — a normal and expected overlap (recall from Unit 2: a group only needs to cover a 1, nothing forbids the same 1 from being covered more than once):

Pair {m6, m7} (A=1, B=1, C varies): term = AB
Pair {m5, m7} (A=1, C=1, B varies): term = AC
Pair {m3, m7} (B=1, C=1, A varies): term = BC

F = AB + AC + BC

The minimal circuit needs 3 two-input AND gates (one per product term) feeding a 3-input OR gate — or equivalently, two cascaded 2-input OR gates. Either is a direct, mechanical translation of the SOP expression above: five gates total, and no further simplification is possible since every group is already a maximal pair (2-cell groups can't merge into a 4-cell group here — check any pair of pairs and they differ in more than one variable outside their shared cell).

Common Pitfalls

  • Skipping the "label every wire" step during analysis. Trying to write the final output's expression directly from a multi-gate diagram, without naming intermediate signals, is where transcription errors creep in — label first, substitute second.
  • Forgetting that a K-map group can overlap another group. As the majority-function example shows, using the same 1-cell in multiple groups is completely normal and often unavoidable for functions like this one.
  • Jumping straight to a circuit from the truth table, skipping minimization. An unminimized SOP (one AND gate per row that's a 1) always works, but a K-map-minimized version is smaller, cheaper, and usually faster — minimization is a required step of the procedure, not an optional polish.

Applications

  • Reverse-engineering an unlabeled schematic (from a datasheet, a legacy design, or a lab exercise) always starts with the analysis procedure — there's no other systematic way to recover what a circuit does.
  • Every building block in the rest of this unit — adders, comparators, decoders, encoders, multiplexers — was itself originally derived using exactly this design procedure, starting from a truth table that defines the desired behavior.
  • Majority-vote circuits specifically are used in triple-modular-redundancy (TMR) fault-tolerant systems — three identical subsystems compute the same result, and a majority circuit like this one picks the answer that at least two of them agree on.
