Multiplexers & Demultiplexers

⏱ 18 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 4

This closes out the unit with the last standard building block pair: a multiplexer (MUX) selects one of several data inputs to route to a single output, and a demultiplexer (DEMUX) does the reverse — routing one input to a chosen one of several outputs.

Multiplexer (Data Selector)

A 4-to-1 MUX has four data inputs (I₀–I₃), two select lines (S₁, S₀), and one output Y — the select code picks which single data input is copied through to Y:

S₁S₀Y
00I₀
01I₁
10I₂
11I₃
 
Y = S₁′S₀′I₀ + S₁′S₀I₁ + S₁S₀′I₂ + S₁S₀I₃

Each term should look familiar: S₁′S₀′, S₁′S₀, S₁S₀′, and S₁S₀ are exactly the four outputs of a 2-to-4 decoder (previous topic) — a MUX is essentially a decoder where every output gate's third input is a data line instead of a shared enable. Here's the I₁ term, S₁′S₀I₁, built out explicitly:

A MUX as a Universal Function Generator

Because each select-line combination routes through a chosen data input unchanged, a 2ⁿ-to-1 MUX can implement any function of n+1 variables: use n of the variables as select lines, and wire the data inputs to 0, 1, the last variable, or its complement — decided per-input by checking what the function reduces to once the select variables are fixed.

Worked Example — F(A,B,C) = Σm(1,3,5,6) on a 4-to-1 MUX

Use A,B as the select lines (S₁=A, S₀=B) and check what F reduces to for each AB combination as C varies:

AB=00 (m0,m1): F(0,0,0)=0, F(0,0,1)=1  → F = C        → I₀ = C
AB=01 (m2,m3): F(0,1,0)=0, F(0,1,1)=1  → F = C        → I₁ = C
AB=10 (m4,m5): F(1,0,0)=0, F(1,0,1)=1  → F = C        → I₂ = C
AB=11 (m6,m7): F(1,1,0)=1, F(1,1,1)=0  → F = C′       → I₃ = C′

Wire I₀=I₁=I₂=C and I₃=C′ into the 4-to-1 MUX from the diagram above, with A,B driving S₁,S₀ — no K-map, no separate AND/OR array, and no minimization needed at all. This is a genuinely different implementation strategy from every other circuit in this unit: instead of building the function from minimized gates, a MUX-based design just routes an already-known signal (0, 1, C, or C′) to the right place.

Demultiplexer (Data Distributor)

A 1-to-4 DEMUX takes one data input D and two select lines S₁, S₀, and routes D to exactly one of four outputs (Y₀–Y₃) — all other outputs stay 0:

Y₀ = S₁′S₀′D    Y₁ = S₁′S₀D    Y₂ = S₁S₀′D    Y₃ = S₁S₀D

Compare this directly against last topic's decoder: a demultiplexer is a decoder, with the single data line D taking the place of the shared enable input. Any decoder with an enable pin can be used as a demultiplexer for free, and vice versa — they're the same circuit wearing two different names depending on how the extra input is used.

Common Pitfalls

  • Confusing which device has multiple data inputs and which has multiple data outputs. A MUX takes many inputs, one output; a DEMUX takes one input, many outputs — exactly opposite, easy to swap by mistake.
  • Forgetting that unselected data inputs are simply ignored, not required to be 0. A MUX only ever looks at the one data input its select code chooses — the other data inputs can be anything without affecting Y.
  • Picking the wrong variable to leave off the select lines when using a MUX as a function generator. Any variable can be the "leftover" one wired into the data inputs, but choosing poorly (e.g., one where the reduced expressions per data input come out messier) makes the resulting data-input assignments harder to derive — the choice doesn't affect correctness, only how easy the derivation is.

Applications

  • Data buses inside a CPU — selecting which register or memory source drives a shared bus at any given moment — are built from multiplexers, one per bus-width bit.
  • Time-division multiplexing in communication systems uses the exact same MUX/DEMUX pair at the system level: multiple signal sources share one transmission line (MUX), then get separated back out at the receiving end (DEMUX).
  • FPGA lookup tables (LUTs) — the fundamental configurable building block inside an FPGA chip — are literally large multiplexers with the data inputs pre-programmed to implement whatever function the designer needs, a direct hardware descendant of the function-generator technique shown above.
