FSM Case Studies: Traffic Light and Vending Machine

⏱ 24 min read 📝 Quiz inside

Both designs follow the procedure of the sequence detector: state diagram → state table → state assignment → flip-flop input equations → output equations. Both are Moore machines (outputs belong to states) and use D flip-flops, so each D input simply equals the next-state bit.

In simple terms: a traffic light and a vending machine are both just a few states and a rule for moving between them — the same design steps as the sequence detector turn each into flip-flops and gates.

Case Study 1 — Traffic-Light Controller

A junction of a north–south (NS) and an east–west (EW) road. A timer input T becomes 1 when the current light has been on long enough. The lights go NS green → NS yellow → EW green → EW yellow → back to NS green; the other road is red throughout.

Traffic-light controller: four states, each held while T = 0 and left when T = 1.

State assignment (Gray code, so only one flip-flop changes per step): S0 = 00, S1 = 01, S2 = 11, S3 = 10 (Q1Q0).

Present Q1Q0Next, T = 0Next, T = 1NS lightEW light
00 (S0)0001GreenRed
01 (S1)0111YellowRed
11 (S2)1110RedGreen
10 (S3)1000RedYellow

Flip-flop input equations — with T = 0 each bit holds; with T = 1 the next code is read from the table (Q1 takes the old Q0, Q0 takes the old Q1′):

D1 = T′Q1 + TQ0
D0 = T′Q0 + TQ1′

Output equations (one per lamp):

NS green = Q1′Q0′    NS yellow = Q1′Q0    NS red = Q1
EW green = Q1Q0      EW yellow = Q1Q0′    EW red = Q1′

Check: in S2 (11), NS red = Q1 = 1 and EW green = Q1Q0 = 1; every other lamp is 0. ✓

Case Study 2 — Vending Machine

An item costs ₹15. The machine accepts ₹5 coins (input N) and ₹10 coins (input D), one coin per clock at most (N and D are never both 1). When ₹15 or more has been paid it opens (output Open = 1) for one clock and returns to the start. (This simple version gives no change; adding a change output is a common extension.)

Vending machine: the state is the amount paid so far; S15 dispenses and returns to S0.

State assignment: S0 = 00, S5 = 01, S10 = 10, S15 = 11 (Q1Q0).

PresentNo coinN (₹5)D (₹10)Open
S0 (00)S0S5S100
S5 (01)S5S10S150
S10 (10)S10S15S150
S15 (11)S0S0S01

Flip-flop input equations — from K-maps of Q1, Q0, N, D, with ND = 11 as don’t-cares:

D1 = Q1′D + Q1Q0′ + Q1′Q0N
D0 = Q0′N + Q1Q0′D + Q1′Q0N′
Open = Q1Q0

Check S5 + ₹10 (01, D = 1): D1 = Q1′D = 1, D0 = Q1′Q0N′ = 1 → 11 = S15 ✓. Check S15 (11): every term of D1 and D0 has Q1′ or Q0′, so both are 0 → S0 ✓.

Common Pitfalls

  • Forgetting the “hold” arrows. Without the T′ self-loops (traffic light) or “no coin” self-loops (vending machine), the machine would race through states on every clock.
  • Binary instead of Gray assignment for the traffic light. Counting 00 → 01 → 10 → 11 changes two flip-flops between S1 and S2, which can briefly light the wrong lamp; the Gray order 00 → 01 → 11 → 10 changes one bit per step.
  • Leaving ND = 11 as 0 in the vending K-maps. That combination cannot occur, so using it as a don’t-care gives the smaller equations above.

Applications

  • Real traffic controllers add pedestrian buttons, vehicle sensors and a night “flashing” mode — each is just more states and inputs in the same diagram.
  • Vending, ticket and parking machines extend the same amount-paid states with change-giving outputs and more coin values.
  • Any controller described as “wait for an event, then move on” — washing machines, lifts, elevators — is designed this way.
