Programmable Logic Devices

⏱ 18 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 3

Unit 1 showed that any Boolean function can be written as a canonical sum of minterms — an AND-OR structure: a layer of AND gates producing product terms, feeding a layer of OR gates that sums the ones the function needs. A programmable logic device (PLD) is exactly that AND-OR structure built as reconfigurable hardware — instead of wiring discrete gates for one fixed function, you "program" (or the manufacturer pre-wires) which connections exist. The three classic PLD families — ROM, PLA, and PAL — differ in exactly one thing: which of the two arrays, if either, is fixed versus programmable.

ROM — Fixed AND, Programmable OR

A ROM used as combinational logic treats its n address inputs as a full decoder: the AND array is fixed and always generates all 2n possible minterms, no matter which ones a given function actually needs. Only the OR array is programmable — each output is free to sum any subset of those 2n minterms. This is precisely a truth table in hardware: address in, corresponding row's data out.

The cost: since the AND array must generate every minterm regardless of use, ROM size grows as 2n — practical for a modest number of inputs, but exponentially wasteful once n gets large and most functions only need a handful of the possible product terms.

PLA — Programmable AND, Programmable OR

A Programmable Logic Array makes both layers programmable. The AND array only needs to generate the product terms some output actually uses — not all 2n — and a product term computed once can feed multiple OR gates, so two outputs that happen to share a term don't pay for it twice.

This is the most flexible of the three — but a programmable OR array is more complex (and historically more expensive) to manufacture reliably than a fixed one, which is exactly the tradeoff PAL is built around.

PAL — Programmable AND, Fixed OR

A Programmable Array Logic device programs only the AND array; the OR array is fixed at manufacture time, with each output wired to its own dedicated, fixed-size bank of AND-array lines. That one simplification — no programmable OR crosspoints — makes PAL cheaper and faster than an equivalent PLA.

The tradeoff: because each output's OR gate only ever sees its own dedicated AND lines, a product term needed by two different outputs has to be generated twice — once in each output's bank — since a PAL's fixed OR wiring gives it no way to share.

Worked Example — Efficiency Comparison

Implement F1(A,B,C) = Σm(1,3,5) and F2(A,B,C) = Σm(1,2,3) together. Minterms 1 and 3 are needed by both functions:

ROM: fixed decoder always builds all 8 minterms → 8 AND lines used, regardless of need. PLA: only the 4 distinct minterms actually required {1,2,3,5} need to exist at all, and m1, m3 each feed both OR gates → 4 AND lines total. PAL: each output needs its own dedicated bank — F1's bank builds {1,3,5} (3 lines), F2's bank separately builds {1,2,3} (3 lines) — m1 and m3 each built twice → 6 AND lines total.

PLA (4) beats PAL (6) beats ROM (8) here specifically because this example has shared minterms and doesn't need every possible one — exactly the two conditions under which a fixed, complete AND array (ROM) or a fixed, non-sharing OR array (PAL) pays a real cost.

Common Pitfalls

  • Assuming PLA is strictly better than PAL because it's more flexible. Flexibility isn't free — a programmable OR array historically costs more silicon and speed than a fixed one, which is exactly why PAL became the dominant, cheaper choice for many real designs despite its sharing limitation.
  • Forgetting a PAL output's product-term bank has a fixed maximum size. A function needing more product terms than a given PAL output supports simply cannot be implemented on that device without restructuring — this is a real hardware constraint, not just a theoretical inefficiency.
  • Thinking ROM can only store data. Any combinational truth table — including one used purely as logic, with no "data" interpretation at all — can be implemented in a ROM; it's a completely general combinational device, just an inefficient one for sparse functions.

Applications

  • Early lookup-table-based logic and microcode (control unit sequencing in classic CPU designs) were classic ROM applications, directly exploiting the "address in, exact row out" structure.
  • PALs (and their successors, GALs) were the dominant "glue logic" chips of the 1980s–90s, replacing dozens of discrete SSI gates with one programmable device per board.
  • Modern FPGAs are the direct descendants of this entire family — vastly larger, with many small programmable lookup tables (LUTs, essentially tiny ROMs) wired together instead of one monolithic AND-OR array, but built on exactly the same "program the interconnect" idea introduced here.
