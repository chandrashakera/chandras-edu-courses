Moore vs. Mealy Finite State Machines

⏱ 18 min read 📝 Quiz inside

From Sequential Circuit to Finite State Machine

Every synchronous sequential circuit in Unit 4 — every counter, every shift register — is really a specific case of something more general: a finite state machine (FSM). An FSM is fully described by five things: a finite set of states, a set of inputs, a set of outputs, a next-state function (present state + input → next state), and an output function. That last piece — exactly what the output function is allowed to depend on — is the one design choice that splits every FSM into one of two standard models.

In simple terms: a Moore machine's output depends only on which state it is in; a Mealy machine's output also depends on the input arriving now.

The Moore Model

In a Moore machine, the output depends only on the present state — never directly on the input:

Moore machine: the output logic sees only the present state.

The flip-flops forming the state register are exactly what Unit 4 called the "state" — an n-bit code identifying which of the machine's states it's currently in. Because output logic here only ever reads that state, the output is guaranteed stable for the entire clock period; it can only change right after a clock edge, in sync with the state itself.

The Mealy Model

A Mealy machine adds one wire: the output logic also reads the current input directly, not just the state:

Mealy machine: the output logic also sees the input.

Because output logic is purely combinational, a Mealy output can change the instant the input changes — even between clock edges — which is exactly why Mealy outputs are not guaranteed stable for a full clock cycle the way Moore outputs are.

Worked Comparison — Detecting Two Consecutive 1s

Build a circuit whose output goes to 1 whenever the last two bits received on a serial input were both 1. The two models solve this with a different number of states.

Moore Version — 3 States

Moore detector for two consecutive 1s: three states, output z shown in each state.

S0 = "no 1 seen yet," S1 = "last bit was 1," S2 = "last two bits were 11" — and S2 is the only state whose output z is 1. Notice the machine has to stay in S2 (via its self-loop on input 1) for the output to keep reading 1 across consecutive 11 pairs in a longer run of 1s.

Mealy Version — 2 States

Mealy detector for two consecutive 1s: two states, arrows labelled input/output.

Each arrow is now labeled input/output. S0 = "last bit wasn't 1" (or no history yet), S1 = "last bit was 1." The output only reads 1 on the specific transition S1→S1 driven by input 1 — the second 1 of a "11" pair — and reverts to 0 the instant the input changes, without needing a dedicated third state to "remember" that the output should currently be high.

Common Pitfalls

  • Assuming Mealy is simply "better" because it uses fewer states. Fewer states is a real advantage, but Moore's output stability is often the deciding factor in practice — a Mealy output driving asynchronous downstream logic can produce a brief incorrect pulse if the input changes right as the state does.
  • Forgetting that a Mealy output is a function of the arrow (transition), not the circle (state). In the diagram, the output label belongs to the edge you're traversing, not to either state it connects.
  • Mixing the two notations on one diagram. Moore output labels belong inside/below the state circle; Mealy output labels belong on the transition arrow, alongside the input. Putting an output label in both places (or in the wrong place) makes the diagram ambiguous.

Applications

  • Vending machines and traffic light controllers are classic Moore-style designs — the current state (e.g., "red light on") directly determines the output with no ambiguity about timing.
  • Protocol/handshake logic and serial receivers (UART framing, bus protocols) often use Mealy machines specifically because reacting to an input within the same cycle — rather than waiting a full clock cycle for the state to update first — reduces latency.
  • Any FSM can be converted between the two models — a Mealy machine can always be turned into an equivalent Moore machine (usually needing more states) and vice versa, which is why the choice is a design tradeoff, not a fundamental limitation of either model.
