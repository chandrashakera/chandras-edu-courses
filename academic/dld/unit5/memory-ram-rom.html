Memory: RAM and ROM

⏱ 20 min read 📝 Quiz inside
In simple terms: a memory is a large set of numbered boxes, each holding one word. Give it an address and it either stores the word you supply (write) or hands back the word already there (read).

What a Memory Unit Is

A memory unit is a collection of binary storage cells together with the circuits that move information in and out of them. It stores information in groups of bits called words; each word has an address from 0 to 2k − 1, where k is the number of address lines. A memory of 2k words of n bits has k address lines, n data input lines, n data output lines, and control inputs that say whether to read or write.

Block diagram of a memory unit. Adapted from M. Morris Mano and Michael D. Ciletti, Digital Design, Fig. 7.2.

Memories are named by size: 1K = 210 = 1,024 words, 1M = 220, 1G = 230. A “1K × 16” memory has 1,024 words of 16 bits: it needs 10 address lines (210 = 1,024) and 16 data lines in each direction.

Worked Example — Counting Lines

Memory        Words      Address lines (k)   Data lines (n)   Capacity
1K × 16       1,024      10                  16               2,048 bytes
4K × 8        4,096      12                   8               4,096 bytes
64K × 16      65,536     16                  16               131,072 bytes
Rule: 2^k = number of words   →   k = log2(words)

Write and Read Operations

Write: (1) put the binary address on the address lines; (2) put the data bits on the data input lines; (3) activate the write control. The word is stored at that address, replacing what was there.

Read: (1) put the address on the address lines; (2) activate the read control. The stored word appears on the data output lines; reading does not change it.

Memory chips usually have a memory enable (chip select) input and one Read/Write line:

Memory enableRead/WriteOperation
0XNone (chip not selected)
10Write to the selected word
11Read from the selected word

Inside a RAM

Each bit is held in a binary cell (BC) — in effect a latch with gating. When its select line is 1, Read/Write = 0 stores the input bit and Read/Write = 1 places the stored bit on the output.

A binary storage cell as a block.

A RAM of m words × n bits is an m × n array of cells. A k-to-2k decoder turns the address into one word-select line; every cell in that row is selected; the data inputs go to every column, and an OR gate per column collects the selected row’s bits for output.

A 4 × 4 RAM: the 2 × 4 decoder selects one word of four cells. Adapted from M. Morris Mano and Michael D. Ciletti, Digital Design, Fig. 7.6.

Coincident (Two-Dimensional) Decoding

A single decoder for a 1K memory needs 1,024 outputs (1,024 AND gates). Arranging the words as a 32 × 32 grid instead lets two 5 × 32 decoders do the job: one picks the row (X), the other the column (Y), and the word where they cross is selected — only 64 decoder outputs.

Two-dimensional decoding of a 1K memory: address 404 = 01100 10100 selects row 12 and column 20. Adapted from M. Morris Mano and Michael D. Ciletti, Digital Design, Fig. 7.7.

1-D decoding: one 10 × 1024 decoder  → 1,024 outputs
2-D decoding: two 5 × 32 decoders     →    64 outputs (32 + 32)

Access time is the time to select a word and read it; cycle time is the time to complete one read or write before the next can start.

Common Pitfalls

  • Mixing up words and bits. “4K × 8” means 4,096 words of 8 bits — 12 address lines (from the 4K) and 8 data lines (from the 8), not 32 lines.
  • Thinking reading erases the data. A read is non-destructive in RAM and ROM; only a write changes a word.
  • Calling ROM “random-access only for reading” and RAM “not random-access”. Both are random-access — any word takes the same time to reach. The real difference is that RAM is written in normal operation and is volatile; ROM is not.

Applications

  • Cache and registers use SRAM for speed; main memory uses DRAM for capacity.
  • Firmware and boot code live in flash/EEPROM so they survive power-off.
  • Look-up tables (e.g. code converters, seven-segment patterns) are stored in ROM — the ROM-as-logic idea of the previous topic.
