Error Detection & Correction: Parity, Hamming Code

⏱ 25 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 1

Every bit stored or transmitted by a digital system can, in principle, get corrupted — a stray voltage glitch, electromagnetic interference, a scratched disk sector. This page covers two techniques for dealing with that reality: parity checking, which can tell you a bit got flipped but not which one, and Hamming code, which can pinpoint the flipped bit exactly and correct it automatically.

Parity Check

A parity bit is one extra bit appended to a group of data bits, chosen so that the total number of 1-bits in the whole group (data + parity) matches an agreed convention:

  • Even parity: the parity bit is chosen so the total count of 1s is even.
  • Odd parity: the parity bit is chosen so the total count of 1s is odd.

The parity bit itself is just the XOR of all the data bits (for even parity) — XOR naturally produces a 1 exactly when an odd number of its inputs are 1, which is precisely what's needed to force the total count to come out even.

Worked Example — Even Parity

Data: 1011000  (four 1s — already even)
Even parity bit = 0
Transmitted: 1011000 0

Data: 1011001  (five 1s — odd)
Even parity bit = 1
Transmitted: 1011001 1

On the receiving end, the receiver recomputes parity over the received bits (including the received parity bit) and checks whether the result matches the agreed convention. A mismatch means at least one bit was corrupted somewhere in the group — but not which one.

⚠️ A single parity bit can only reliably detect an odd number of bit flips. If exactly two bits flip, the total 1-count changes by an even amount, and parity comes out looking correct even though the data is wrong — a real, well-known blind spot of simple parity, not just a theoretical edge case.

Hamming Code

Parity tells you that an error happened. Hamming code goes further: by using multiple parity bits, each covering a carefully chosen overlapping subset of positions, it can pinpoint exactly which bit is wrong — and since knowing the location of a single-bit error is enough to fix it (just flip that bit), Hamming code can self-correct single-bit errors without needing a retransmission.

Placing the Parity Bits

Number the bit positions of the codeword starting at 1. Parity bits go at every position that's a power of 2 (1, 2, 4, 8, ...); data bits fill every other position. For 4 data bits, that means 3 parity bits (positions 1, 2, 4) and a 7-bit total codeword — this specific case is called Hamming(7,4).

Each parity bit covers the positions whose binary representation has a 1 in the corresponding bit: p1 covers every position with bit 0 set (1,3,5,7), p2 covers every position with bit 1 set (2,3,6,7), p4 covers every position with bit 2 set (4,5,6,7). Each parity bit is the even-parity XOR of the positions it covers.

Worked Example — Encoding Data 1011

Encode data bits d1 d2 d3 d4 = 1, 0, 1, 1 into Hamming(7,4):

Positions:   1   2   3   4   5   6   7
Role:        p1  p2  d1  p4  d2  d3  d4
Data placed: ?   ?   1   ?   0   1   1

p1 (covers 1,3,5,7) = d1⊕d2⊕d4 = 1⊕0⊕1 = 0
p2 (covers 2,3,6,7) = d1⊕d3⊕d4 = 1⊕1⊕1 = 1
p4 (covers 4,5,6,7) = d2⊕d3⊕d4 = 0⊕1⊕1 = 0

Final codeword: 0  1  1  0  0  1  1
Position:       1  2  3  4  5  6  7

Worked Example — Detecting & Correcting a Single-Bit Error

Suppose position 5 gets flipped in transit (0 → 1). The receiver gets 0 1 1 0 1 1 1 instead of the original 0 1 1 0 0 1 1. To locate the error, the receiver recomputes each parity check over the received bits and builds a syndrome:

c1 = XOR of positions 1,3,5,7 = 0⊕1⊕1⊕1 = 1   (mismatch)
c2 = XOR of positions 2,3,6,7 = 1⊕1⊕1⊕1 = 0   (match)
c4 = XOR of positions 4,5,6,7 = 0⊕1⊕1⊕1 = 1   (mismatch)

Syndrome = c4 c2 c1 = 1 0 1 = binary 101 = 5

→ Position 5 is the error. Flip it back: 1 → 0.
→ Corrected codeword: 0 1 1 0 0 1 1  (matches the original exactly)

This is the genuinely elegant part: the syndrome, read as a binary number, directly gives the position number of the flipped bit — no searching required. A syndrome of all-0s means no error was detected at all.

🚀 Beyond the textbook: the version above, Hamming(7,4), corrects any single-bit error but can be silently fooled by a 2-bit error (it will "correct" the wrong bit, making things worse). Adding one more overall parity bit across the whole codeword extends it to Hamming(8,4) / SEC-DED (Single Error Correction, Double Error Detection) — it can still correct any single-bit error, and additionally reliably detects (without attempting to fix) any 2-bit error. This SEC-DED variant is what's actually used in ECC RAM in servers and workstations.

Common Pitfalls

  • Simple parity cannot detect 2-bit (or any even number of bit) errors — this is a fundamental limitation, not a bug in a specific implementation.
  • Mixing up which positions each Hamming parity bit covers. p1, p2, p4 cover positions based on their binary bit-position pattern (1,3,5,7 / 2,3,6,7 / 4,5,6,7 respectively) — writing these out explicitly before computing avoids errors.
  • Forgetting that a Hamming(7,4) syndrome of 0 means no error, not "error at position 0" — position numbering starts at 1, so syndrome value 0 is a special "all clear" case.
  • Assuming basic Hamming code can fix 2-bit errors — it can only reliably correct single-bit errors; a 2-bit error will be miscorrected rather than caught, unless the SEC-DED extension is used.

Applications

  • ECC (Error-Correcting Code) RAM, standard in servers and many workstations, uses a SEC-DED Hamming-based code to silently correct the occasional single-bit memory error caused by cosmic rays or electrical noise, without crashing the system.
  • Simple parity bits are still used in serial communication protocols (like RS-232) and older memory systems, where the cost of full error correction wasn't justified but basic error detection was still valuable.
  • Deep space communication and storage systems use much more powerful descendants of these ideas (Reed-Solomon, LDPC, turbo codes) — but Hamming code is the conceptual starting point every one of them builds on: redundant bits computed from overlapping subsets of data, decoded via a syndrome.
