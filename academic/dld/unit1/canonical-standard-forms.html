Boolean Functions: Canonical & Standard Forms

⏱ 20 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 2

Given a truth table, is there a mechanical, no-judgment-required way to write down the exact Boolean expression it describes? Yes — that's exactly what canonical forms give you. This page covers how to build one directly from a truth table, and the more compact "standard forms" used once you're ready to simplify.

Minterms and Maxterms

For n Boolean variables, a minterm is an AND term that includes every one of the n variables exactly once — uncomplemented if that variable is 1 in a given row, complemented if it's 0. A maxterm is the dual idea: an OR term including every variable, uncomplemented if 0 in that row, complemented if 1.

ABCMintermMaxterm
000m₀ = A′B′C′M₀ = A+B+C
001m₁ = A′B′CM₁ = A+B+C′
010m₂ = A′BC′M₂ = A+B′+C
011m₃ = A′BCM₃ = A+B′+C′
100m₄ = AB′C′M₄ = A′+B+C
101m₅ = AB′CM₅ = A′+B+C′
110m₆ = ABC′M₆ = A′+B′+C
111m₇ = ABCM₇ = A′+B′+C′

Notice the pattern: mᵢ = Mᵢ′ for every row — a minterm and its same-numbered maxterm are complements of each other. This isn't a coincidence; it's exactly what DeMorgan's law produces when you complement an AND-of-literals into an OR-of-complemented-literals.

Canonical Sum-of-Products (SOP)

The canonical SOP form of a function is the OR of the minterms corresponding to every row where the function equals 1. Read directly off a truth table with zero algebraic work.

Worked Example — Canonical SOP

F(A,B,C) is 1 for rows 1, 4, and 7 (using the row numbering above: A′B′C, AB′C′, ABC):

F = A′B′C + AB′C′ + ABC = Σm(1,4,7)

The Σm(...) shorthand — "sum of minterms" — just lists the row numbers where the function is 1, without writing out every term longhand.

Canonical Product-of-Sums (POS)

The canonical POS form is the AND of the maxterms corresponding to every row where the function equals 0 — the mirror image of canonical SOP.

Worked Example — Canonical POS (Same Function)

The same F above is 0 for rows 0, 2, 3, 5, 6:

F = M₀·M₂·M₃·M₅·M₆ = ΠM(0,2,3,5,6)

The ΠM(...) shorthand — "product of maxterms" — lists the row numbers where the function is 0. Notice the two forms are complementary lists: SOP lists where F=1, POS lists where F=0, and together they cover every row exactly once.

🚀 Both canonical forms describe the exact same function — they're not two different functions, just two different (and fully mechanical) ways of writing the same truth table algebraically. Either one can be derived directly from the other just by knowing which rows aren't listed.

Standard Forms

Canonical forms are useful precisely because they're mechanical — but they're rarely the simplest expression, since every single term must include every variable, even when a shorter term would do. A standard SOP is any sum of AND terms where each term doesn't necessarily include all the variables (a mix of minterms and shorter product terms); a standard POS is the equivalent for OR terms. Standard forms are what you actually get after simplification (algebraic or K-map, covered in Unit 2) — canonical forms are the unsimplified starting point.

Worked Example — Canonical vs. Standard SOP

Canonical SOP:  F = A′B′C + AB′C′ + AB′C
Standard SOP:   F = A′B′C + AB′        (AB′C′ + AB′C = AB′(C′+C) = AB′)

Same function, fewer literals — the standard form dropped from 9 literals to 5 by combining two minterms that differ in only one variable, exactly the kind of pattern K-maps are built to spot automatically.

Common Pitfalls

  • Forgetting that a minterm and its same-index maxterm are complements — mᵢ and Mᵢ are related but not interchangeable; mixing them up when converting between canonical SOP and POS produces a wrong expression.
  • Listing the wrong rows for POS. Canonical POS uses the maxterms for rows where F=0, not where F=1 — the easiest way to get this backwards is applying the SOP mental model (list where F=1) to POS by habit.
  • Treating a standard form as if it were unique. Unlike canonical forms (exactly one canonical SOP and one canonical POS per function), there are many valid standard forms for the same function — different, equally-correct simplification paths can land on different (but equivalent) standard expressions.

Applications

  • Canonical SOP is the direct starting point for decoder-based circuit implementation (covered in Unit 3) — each decoder output line IS one minterm, generated in hardware.
  • Truth-table-to-equation conversion tools (in HDL synthesis, spreadsheet logic tools, and digital design software) mechanically generate canonical SOP or POS internally as a first step, before any minimization runs.
  • K-map minimization (Unit 2) takes a canonical form's minterms as its direct input — the Σm(...) shorthand on this page is exactly the notation used to specify which cells of a K-map get marked with a 1.
