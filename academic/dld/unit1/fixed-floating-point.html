Fixed-Point & Floating-Point Representation

⏱ 22 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 1

So far every number on this page has been a whole number. Real digital systems constantly need to represent fractions and very large or very small magnitudes too — everything from a sensor reading of 3.14 to a distance measured in light-years. There are exactly two strategies digital hardware uses for this, and they trade off in opposite directions.

Fixed-Point Representation

A fixed-point number places the binary point at a permanently agreed-upon position within a fixed-width word — some number of bits for the integer part, the rest for the fractional part, decided once at design time and never moved. Bits to the right of the point carry negative powers of 2.

...b₂b₁b₀ . b₋₁b₋₂b₋₃...

Each fractional bit position b₋ᵢ contributes b₋ᵢ × 2⁻ⁱ to the value — the same weighted-sum idea from the previous page, just extended to negative exponents.

Worked Example — Fixed-Point Binary Fraction

1011.101₂
= (1×2² + 0×2¹ + 1×2⁰) + (1×2⁻¹ + 0×2⁻² + 1×2⁻³)
= (4+0+1) + (0.5+0+0.125)
= 5 + 0.625
= 5.625₁₀

Fixed-point's defining trade-off: with a fixed total bit width, giving more bits to the fractional part (for finer precision) means fewer bits for the integer part (smaller maximum magnitude), and vice versa. The range and precision are both locked in at design time and can't flex to the data.

Floating-Point Representation

A floating-point number instead stores a number the way scientific notation does: a sign, a mantissa (also called the significand — the significant digits), and an exponent that says how far, and in which direction, to shift the binary point. The point "floats" to wherever the exponent says it should be, rather than sitting at a fixed bit position.

Value = (−1)sign × 1.mantissa × 2exponent − bias

Normalization

A floating-point number is normalized when the mantissa is adjusted so exactly one nonzero digit sits before the binary point — in binary specifically, that leading digit is always 1, so it doesn't even need to be stored explicitly (this is the "implied leading 1" or "hidden bit" trick, used to squeeze one extra bit of precision out of the mantissa field for free).

IEEE 754 Single Precision (32-bit)

FieldWidthPurpose
Sign1 bit0 = positive, 1 = negative
Exponent8 bitsStored with a bias of 127, so it can represent both positive and negative exponents using only unsigned bits
Mantissa (fraction)23 bitsThe bits after the implied leading 1

Worked Example — Encoding 5.625 in IEEE 754 Single Precision

5.625₁₀ = 101.101₂  (from the fixed-point example above)

Normalize: 101.101₂ = 1.01101 × 2²

Sign     = 0                (positive)
Exponent = 2 + 127 = 129 = 10000001₂
Mantissa = 01101000000000000000000  (23 bits, padded with 0s)

Final layout:
0  10000001  01101000000000000000000
sign  exponent(8)      mantissa(23)
🚀 Beyond the textbook: the bias exists specifically so exponent comparison can use ordinary unsigned integer comparison — a genuinely clever design choice baked into IEEE 754 that makes hardware comparators simpler. Also worth knowing: IEEE 754 reserves the all-0s and all-1s exponent patterns for special values — exponent all-0s (with a zero mantissa) represents ±0, and exponent all-1s represents ±infinity or NaN ("Not a Number") depending on the mantissa. These aren't arbitrary edge cases; they're a deliberate part of the standard.

Fixed-Point vs. Floating-Point

Fixed-PointFloating-Point
RangeFixed, limited by word widthVery wide — exponent lets it represent tiny and huge magnitudes
PrecisionConstant across the whole rangeRelative — more precise near zero, coarser for huge magnitudes
Hardware costCheap — plain integer adders/multipliers work directlyExpensive — needs dedicated floating-point units (FPUs) for normalization and exponent alignment
Typical useEmbedded/DSP systems with known, bounded value rangesGeneral-purpose computing, scientific calculation

Common Pitfalls

  • Forgetting the implied leading 1 when decoding a normalized floating-point number — the stored mantissa is only the bits after that implicit 1, not the whole significand.
  • Adding the bias in the wrong direction. The stored exponent field is (true exponent + bias); recovering the true exponent means subtracting the bias back out, not adding it again.
  • Assuming fixed-point precision is uniform in floating-point too. Floating-point precision is relative to magnitude — the gap between representable values near 1,000,000 is far larger than the gap near 1.0, even though both use the same number of mantissa bits.

Applications

  • Digital signal processors (DSPs) in audio and embedded systems often use fixed-point specifically for its cheap, fast, predictable-latency arithmetic, when the value range is known in advance.
  • Every general-purpose CPU and GPU includes hardware floating-point units implementing IEEE 754, since scientific and graphics computation needs the huge dynamic range floating-point provides.
  • Financial software deliberately avoids floating-point for currency values (using fixed-point or decimal types instead), precisely because floating-point's relative-precision rounding is unacceptable when cents must be exact.
