Number Systems: Binary, Octal, Decimal, Hexadecimal

⏱ 20 min read 📝 Quiz inside 📖 Mano & Ciletti Ch. 1

Every digital circuit you'll design in this course ultimately works with just two voltage levels — but the numbers those circuits represent don't have to be written in binary to be understood. This page covers the four number systems you'll meet constantly in digital design, and — more importantly — how to convert cleanly between them.

Positional Number Systems

All four systems on this page are positional (radix) number systems: the value of a digit depends on both the digit itself and its position in the number. A number system with radix (base) r uses r distinct digit symbols (0 through r−1), and a number is evaluated as a weighted sum of powers of r:

N = Σ dᵢ × ri

where dᵢ is the digit at position i, counting from 0 at the radix point going left. This single formula is all four number systems on this page — only r changes.

SystemRadixDigit set
Decimal100–9
Binary20, 1
Octal80–7
Hexadecimal160–9, A–F (A=10 ... F=15)
Octal and hexadecimal exist purely for human convenience — no circuit computes in base 8 or base 16 internally. They're used because 3 binary digits map exactly onto 1 octal digit, and 4 binary digits map exactly onto 1 hex digit, making long bit strings far easier for a person to read and write without losing the underlying binary structure.

Converting Any Base to Decimal

Directly apply the weighted-sum formula above, evaluating in decimal.

Worked Example — Binary and Hex to Decimal

1011₂ = 1×2³ + 0×2² + 1×2¹ + 1×2⁰
      = 8 + 0 + 2 + 1  =  11₁₀

2AF₁₆ = 2×16² + A×16¹ + F×16⁰
      = 2×256 + 10×16 + 15×1
      = 512 + 160 + 15  =  687₁₀

Converting Decimal to Any Base

Use repeated division by the target radix, reading the remainders from bottom to top (last remainder computed is the most significant digit).

Worked Example — Decimal 45 to Binary and Octal

45 ÷ 2 = 22 remainder 1   (LSB)
22 ÷ 2 = 11 remainder 0
11 ÷ 2 =  5 remainder 1
 5 ÷ 2 =  2 remainder 1
 2 ÷ 2 =  1 remainder 0
 1 ÷ 2 =  0 remainder 1   (MSB)

Reading remainders bottom-to-top: 45₁₀ = 101101₂

45 ÷ 8 = 5 remainder 5   (LSB)
 5 ÷ 8 = 0 remainder 5   (MSB)
45₁₀ = 55₈

Check: 101101₂ = 32+8+4+1 = 45. ✓ And 55₈ = 5×8+5 = 45. ✓

Binary ↔ Octal and Binary ↔ Hexadecimal — Direct Grouping

Because 8 = 2³ and 16 = 2⁴, converting between binary and octal, or binary and hex, never needs decimal as a middle step — group the binary digits directly.

  • Binary → Octal: group bits in 3s from the radix point outward, pad with leading/trailing zeros if needed, convert each group independently.
  • Binary → Hexadecimal: group bits in 4s from the radix point outward, same padding rule, convert each group independently.
  • Octal/Hex → Binary: reverse the process — expand each digit back into its fixed-width bit group and concatenate.

Worked Example — Binary to Octal and Hex by Grouping

10 110 101₂  (grouped in 3s from the right)
 2   6   5
= 265₈

1011 0101₂  (grouped in 4s from the right)
  B    5
= B5₁₆
⚠️ Grouping always starts from the radix point, not necessarily the left edge of the number as written. For an integer, that just means starting from the rightmost bit — but if there's a fractional part, group outward in both directions from the point, padding each end separately.

Common Pitfalls

  • Padding on the wrong side. When grouping bits for octal/hex conversion, zero-padding must happen at the end farthest from the radix point (the leading end for an integer's leftmost group), never in the middle of the bit string.
  • Confusing hex letters with decimal digits. A=10, B=11, C=12, D=13, E=14, F=15 — a common slip is miscounting partway through the alphabet-to-number mapping.
  • Reading division remainders top-to-bottom instead of bottom-to-top when converting decimal to another base — the first remainder computed is the least significant digit, not the most significant.

Applications

  • Memory addresses and machine code are almost universally displayed in hexadecimal — compact enough to read, while still trivially convertible to the binary the hardware actually uses.
  • Octal permission notation in Unix/Linux file systems (e.g., chmod 755) is a direct real-world use of octal-as-compact-binary, since each octal digit represents exactly 3 permission bits (read/write/execute).
  • Every register, bus, and memory cell in the digital circuits covered later in this course operates natively in binary — decimal is purely for human specification and verification.
